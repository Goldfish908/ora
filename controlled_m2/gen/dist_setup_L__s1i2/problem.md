# dist_setup_L__s1i2:3 仓 5 店配送计划(运输时滞 + 仓库启用费)

3 个仓库(W1、W2、W3)向 5 家门店(S1、S2、S3、S4、S5)配送同一种商品,计划未来 6 期。仓库发货后**次期才到店**(运输时滞 1 期:第 t 期发出的货在第 t+1 期到达并可销售;第 6 期发出的货到不了,等于白付运费和启用费)。每家门店每期需求已知,门店可持有库存;需求必须当期满足,不允许缺货。每个仓库每期的发货总量有上限;**只要某仓库某期有发货(总量大于 0),该仓该期就必须记为"启用"并支付启用费 `depot_cost[w]`(启用是 0/1 决策;不允许有发货却不启用,也不允许未发货却启用)**。目标是最小化总成本。

## 业务规则

1. **门店库存平衡**:门店 s 第 t 期期末库存 = 上期期末库存 + 本期到货量 − 本期需求。**本期到货量 = 所有仓库上一期发往该店的发货量之和**(第 1 期无到货)。第 1 期的"上期期末库存"为给定的期初库存。
2. **仓库发货能力**:每个仓库每期发往各门店的发货量**合计**不超过该仓的能力上限 `cap[w]`。
3. **启用激活**:仓库 w 第 t 期发货总量 > 0 当且仅当该仓该期启用标志为 1。
4. **目标**:总成本 = 运输成本(发货量 × `cost[w][s]`)+ 启用费(启用标志 × `depot_cost[w]`)+ 门店库存持有成本(门店期末库存 × `hold_cost[s]`),最小化。

## 数据

`data/params.json`:

- `demand[s][t]`:门店 s 第 t 期需求(t=1..6)
- `init_inv[s]`:门店期初库存
- `cap[w]`、`depot_cost[w]`、`cost[w][s]`、`hold_cost[s]`

**JSON 形态**(务必按此读取,不要当下标数组):`demand` 是以门店名为键、值为数组的对象——`demand["S1"][0]` 是 S1 第 1 期需求(数组 0 起始);`init_inv`、`hold_cost` 以门店名为键;`cap`、`depot_cost` 以仓库名为键;`cost` 是嵌套对象,`cost["W1"]["S1"]` 是 W1→S1 的单位运费。

## 输出要求

把结果写入本程序所在目录的 `solution.json`:

```json
{
  "objective": <总成本>,
  "ship": {"<仓库>|<门店>": [第1期, ..., 第6期], ...},
  "inventory": {"<门店>": [第1期, ..., 第6期], ...},
  "depot": {"<仓库>": [0或1, ..., 共6个], ...}
}
```

同时在标准输出打印一行 `OBJECTIVE <总成本>`。
