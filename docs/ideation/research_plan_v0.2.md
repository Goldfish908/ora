## 0. 一页结论

1. **只投一篇 CCF-A，首选 NeurIPS 2027 主会**（往年 5 月中截稿，待官方确认）。ICML 2027 只剩约 10 周，来不及做新机制和多数据集评测；ACL Industry Track 在多数单位不算 CCF-A 长文；EMNLP 是 CCF-B。
2. **核心问题**：OR 建模里"成功"信号本身不可信。目标值匹配会把语义错误的解（幻影）当成正确，修复压力还会把崩溃洗白成静默错误。所有已有的验证方法和经验库都默认这个信号可信。
3. **核心方法**：把 memory 做成**验证知识的进化**。每条经验是一个可执行检查，带适用范围和出处类型（题面依据、数学结构、领域惯例），验证通过后才晋升；按 L0 可执行、L1 数学结构、L2 业务语义分层；低层修复不得破坏高层检查；没有依据的检查不能否决。这把你说的"memory 和 witness 有重合"和"可执行经验与业务语义经验分层管理"统一成一个机制。
4. **竞品格局**：
   - "能执行不等于正确"已被 ICML 2026 至少四篇工作当作动机，不能再作为贡献。
   - "OR 建模的经验库"已被 AlphaOPT（KDD 2026）占用。
   - 仍然空白的是：**经验是验证器而不是提示**、**正确性超出目标值**、**按出处决定否决权**、**层间不回退**。
5. **成败取决于一个 go/no-go 判断**：按出处设门槛后，自动产生的检查误报率能不能从 49% 降到可用水平（比如 15% 以下），同时召回不崩。这必须第一个做。
6. **工程与论文分开**：现有 IndustryOR 管线（structured、DAG、hybrid）作为工程系统继续用，并作为论文里的强基线；论文的贡献集中在验证知识的进化。

## 1. 现有证据（含已更正的判断）

| 证据 | 数字 | 说明 |
|---|---|---|
| RetailOpt 零样本：真正确 vs 目标值匹配 | 6.8% vs 32%（约 4.7 倍） | 幻影的核心证据 |
| 幻影的构成 | 约 54% 只违反期初库存惯例（C-INIT） | **削弱了 4.7 倍的说服力**：相当一部分属于题面没写清楚，必须把 C 类单独研究 |
| witness 反馈 vs SAC-Opt 自评 | 54.2% vs 28.4% | witness 作为反馈信号有效 |
| 三条链 witness 过滤仲裁 | 80.5% | 工程上可用 |
| ReLoop 同模型复现 | 可执行 93.2%，正确 28.4% | "只保可执行"的典型 |
| 洗白（F12） | 关掉验证时幻影从 43 增加到 115 | 可执行压力把崩溃变成静默错误 |
| 共识投票（consensus trap） | AUC 0.57 | **更正**：共识只是没有信息量，不是有害的"陷阱"；之前"37 个幻影多数"主要是并列打破造成的假象 |
| D1 自动写检查 | 误报率约 49% | 自动验证知识的精度是核心难点 |
| JEV 蒸馏 | 效果不佳 | 蒸馏的是 witness 的判定结果，应该学的是写检查的能力 |
| IndustryOR：DAG 修复 | +10，p≈0.002 | 显著 |
| IndustryOR：hybrid 选择 | +4，p=0.125 | 不显著 |
| IndustryOR：memory | 约 0 | 文本记忆不产生验证信号 |
| IndustryOR 总体 | 数值上达到 SOTA（对比 CoOpa，口径不完全一致） | 没有 held-out，存在对开发集过拟合的风险；只审计了 8 题 |

**诊断**：确定性 witness 规则无法跨族迁移；memory 和 DAG 消耗验证信号，但自己不产生；自动写的检查误报高，因为写检查的模型和生成模型面对的是同一份有歧义的题面。

## 2. 竞品格局（详见配套文档）

### 2.1 OR 建模的验证（ICML 2026）

| 工作 | 验证方式 | 共同盲区 |
|---|---|---|
| VeriSimpl | 求解器构造简化的诊断问题，LLM 判断 | 正确性只看目标值；不积累知识；处理不了题面没写的惯例；不单独报可执行率；不统计修复把对的改错 |
| Opt-Verifier | LLM 回译结构，并解释求解结果 | 同上；按论文数字反推，验证器误报率很高 |
| DA-RL | RL 训练"先写草稿、再审查" | 同上；"静默错误 32.6%→0%"主要是静默错误变成了崩溃；奖励等于奖励幻影 |
| ORLoopBench | 求解器的不可行子系统（IIS）驱动修复 | 范围止于可解；semantic drift 只用目标值检测 |

### 2.2 经验库与记忆

| 工作 | 存什么 | 怎么入库 | 共同盲区 |
|---|---|---|---|
| **AlphaOPT（KDD 2026）** | OR 建模提示（标签、条件、解释、示例） | 目标值和标签一致 | 都把成功信号当作真值；都不存"对解运行的检查" |
| ProcMEM（ICML 2026） | 技能（自然语言程序） | PPO Gate（基于环境奖励） | 同上 |
| XSkill（ICML 2026） | 技能流加经验流 | 不检验，由 LLM 整理 | 同上；出现负迁移 |
| UMEM（ICML 2026） | 文本记忆，由 RL 训练的模型写入 | 无门槛，每次提交最好的候选 | 同上 |
| MemEvolve（ICML 2026） | 演化记忆系统的架构 | Pareto 选择 | 同上 |

### 2.3 差异化表述

> AlphaOPT 类经验库存的是靠目标值一致验收的文本指导，分不清语义正确的模型和目标值碰巧一致的幻影。我们演化的是带出处类型、验证后才晋升、在推理时用于否决或修复的可执行检查，并且证明靠目标值验收的记忆会收进并放大幻影。

**不能再说的**：首次发现能执行不等于正确；首次提出 OR 建模的验证；首次提出 OR 建模的经验库。

## 3. 研究问题

**主问题**：当任务的成功信号（目标值匹配）本身不可靠时，agent 怎样积累**可信的**验证知识，使可执行率和正确率同时提高，而不是用一个去换另一个？

**子问题**：
- **RQ1（现象）**：幻影和洗白在 RetailOpt 之外是否普遍存在？在已有方法（VeriSimpl、Opt-Verifier、DA-RL、AlphaOPT）里是否也存在？
- **RQ2（门槛）**：按出处设晋升门槛，能否把自动产生的检查的误报率压到可用水平？
- **RQ3（分层）**：低层修复不得破坏高层检查的规则，能否消除洗白，同时保住可执行率？
- **RQ4（迁移）**：验证知识能否跨族迁移？哪一层迁移得好，哪一层只能在本领域内使用？
- **RQ5（可选，学习）**：能否用 RL 训练写检查的模型，以精度为主的奖励是否比 SFT 或蒸馏更好？

**结合工业业务带来的变化**：工业背景主要作用在 L2，即不同领域、不同企业的惯例。这正好解释了为什么需要可进化、可限定范围的经验，而不是一套通用的人写规则。RetailOpt 是工业零售场景的代表，不需要把整篇论文写成运筹学论文。

## 4. 机制设计

### 4.1 经验单元

```text
Check {
  id, layer: L0 | L1 | L2,
  trigger / scope: 适用的题型、约束族或领域
  program: 对 (题面, 模型, 解) 运行的可执行检查
  provenance: text-grounded（附题面原文片段）| math-structural | convention（附适用领域）
  repair_hint: 失败时给生成端的修复提示
  evidence: 命中数、在验证集上的精度和召回、误否决数、来源任务
  status: candidate | promoted | advisory | retired
}
```

### 4.2 分层与权限

| 层 | 内容 | 能否跨族 | 晋升门槛 | 权限 |
|---|---|---|---|---|
| L0 可执行 | 求解器/API 用法（I 类） | 能 | 低：代码跑通即可 | 只能修复 |
| L1 数学结构 | 守恒、界、量纲、变量类型 | 大多能 | 中 | 可否决 |
| L2 业务语义 | 题面明文（E 类）和惯例（C 类） | 只在本领域内 | 高：需要题面依据或经验证的惯例 | 有依据才能否决，否则只作提示 |

### 4.3 两条规则

1. **层间不回退**：任何修复都必须保持已晋升的高层检查结果不变。这条直接针对洗白。
2. **出处决定否决权**：没有依据的检查只能作为提示，不能否决。这条直接针对 49% 的误报。

### 4.4 生命周期

借鉴 ProcMEM 的生命周期，并利用"检查是确定性的、可以精确重放"这一优势：

1. **提出**：从失败轨迹中由 LLM 生成候选检查。
2. **验证**：在历史解库上精确重放，计算精度（用 Wilson 下界）、召回和误否决率，同时核对出处（题面原文片段是否真的存在）。
3. **晋升或降级**：达到门槛才晋升；没有依据的降为提示；上线后表现变差的退役。

**真值从哪里来**：RetailOpt 上由 witness 提供，对系统隐藏，只用来评估；其他数据集上用人工审计的子集，加上注入惯例违反构造的样本。

### 4.5 可选：RL 训练写检查的模型

- 用 GRPO 对 Qwen3-4B 做全参训练，或对 8B 用 LoRA；2×A800 跑 72 小时，大约 250–300 步。
- 奖励参考 UMEM 改造：在按约束结构构造的邻域上，以精度的 Wilson 下界为主项，加召回，对误否决施加大于 1 的惩罚系数，惩罚破坏高层检查的修复，去掉效率项。
- 这一部分是加分项，不放在关键路径上。

## 5. 评测设计

### 5.1 数据集

| 角色 | 数据集 | 说明 |
|---|---|---|
| 机制开发 | RetailOpt 开发部分 | witness 作为隐藏真值 |
| 机制评估（领域内） | RetailOpt held-out（90 题） | 已有划分 |
| 跨族、跨数据集 held-out | OptMATH-Bench、LogiOR、ComplexOR、ReSocratic、NL4OPT、MIPLIB-NL（选做） | 使用 OptArena/LLM4OR 的清洗版；方法冻结后只跑一次 |
| 已接触过，单独列出 | IndustryOR、MAMO、NLP4LP | 不算 held-out |
| 语义审计子集 | 每个 held-out 数据集抽 30–50 题人工审计 | 用来估计目标值匹配之外的静默错误率 |

### 5.2 指标

可执行率、目标值匹配率、真正确率（witness 或审计）、静默错误率、幻影率、验证器误报率和误否决率、修复前后对错翻转的数量、每题成本。

### 5.3 基线

- **OR 验证类**：VeriSimpl（加一个计算量对等的 best-of-K 基线）、Opt-Verifier、DA-RL（推理端）、ReLoop、SAC-Opt。
- **经验库类**：AlphaOPT（代码公开）、ExpeL、ReasoningBank，可以借用 EvolveLab 平台。
- **模型**：内网 Qwen3.8-27B 为主；关键实验用闭源前沿模型（Claude Opus、GPT 系列）复跑一遍，回答"换更强的模型，问题是不是就消失了"。

### 5.4 关键实验（按优先级）

| 编号 | 实验 | 是否需要 API | 回答的问题 |
|---|---|---|---|
| E0 | D1 误报是否集中在没有依据的规则上；RetailOpt 幻影的 E/C 拆分 | 否 | go/no-go 的第一步 |
| E1 | 小规模按出处设门槛的实验 | 是（内网） | RQ2 的 go/no-go |
| E2 | 用 witness 重新评判 VeriSimpl、Opt-Verifier、DA-RL 的输出 | 是 | RQ1：竞品的指标高估了正确性 |
| E3 | AlphaOPT 幻影收录审计：它靠目标值收进库的经验中，有多少重放后产生幻影 | 是 | 和 AlphaOPT 的差异化核心证据 |
| E4 | 按族依次输入的流式评测：经验能否迁移到没见过的族 | 是 | RQ4 |
| E5 | 层间不回退规则的消融：可执行率、正确率、幻影数 | 是 | RQ3 |
| E6 | held-out 数据集主表 | 是 | 泛化 |
| E7 | 前沿模型复跑 | 是（闭源） | 强模型是否让问题消失 |
| E8 | RL 训练写检查的模型（可选） | 训练资源 | RQ5 |

## 8. 工程和论文的边界

| 内容 | 工程系统 | 论文 |
|---|---|---|
| RetailOpt witness | 领域验证器，生产可用 | 隐藏真值，只用于评估；部分规则作为 L2 种子 |
| IndustryOR 管线（structured、DAG、hybrid） | 主管线，可集成到 mini-swe-agent | 强基线；DAG 修复可以作为生成端组件 |
| 文本 memory | 保留 | 作为基线（约等于 0 增益正好是动机） |
| 三条链仲裁 | 保留 | 不作为贡献 |
| 共识投票分析 | 不用 | 一句话结论（没有信息量） |
| JEV 蒸馏 | 不用 | 作为负结果，引出"学写检查而不是学判定" |
| 检查库、晋升、分层规则 | 后续回灌到工程系统 | **核心贡献** |

## 9. 风险

1. **幻影只在 RetailOpt 上大量出现**：需要在 IndustryOR、OptMATH 等数据集上人工审计，确认同类现象存在。
2. **C 类占比高**：约 54% 只违反期初库存惯例。必须把"题面没写的惯例"作为研究对象，并区分"模型错"和"题面没写清楚"。
3. **门槛实验失败**：如果误报降不下来，机制主线不成立。按第 7 节的退路处理。
4. **AlphaOPT 后续版本**：作者可能补上更强的验证；需要持续关注 arXiv 更新。
5. **复现成本**：VeriSimpl、Opt-Verifier、AlphaOPT 都依赖 Gurobi 或 GPT-4o，移植到 PySCIPOpt 和 Qwen 需要说明改动。
6. **记忆类工作还没查全**：ASI、SkillWeaver、Voyager、Memp、Memory-R1、EvolveR、Darwin Gödel Machine 需要补查。
