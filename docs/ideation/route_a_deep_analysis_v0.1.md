# 路线 A 深度评估 v0.1

日期：2026-11-18  
配套：`research_plan_v0.2.md`、`related_work_or_verification_v0.1.md`  
目的：在 GEPA 类比、系统路线对照，以及 Blind Curator / Echo Gap / FGSE / AutoPyVerifier 补读之后，把路线 A 收紧成可投稿的问题定义。

---

## 0. 一句话判断

**路线 A 可行，但不能用“自进化在代理指标下会放大错误”当主贡献——这句话到 2026 年末已被多篇工作占住。**  
可投 CCF-A 的位置是更窄、更硬的三点：

1. **内生洗白**：优化过程本身会把错误推进代理指标的盲区（崩溃 → 目标值碰巧对的幻影），假通过率不是固定常数，而是被优化推高。  
2. **有金标准的代理仍会系统性漏检**：原因是题面/规格欠定（E/C/I，尤其是 C 类惯例），不是 LLM judge 偏松。  
3. **修正不是换更强 judge，而是让验证知识本身进化**：可执行检查 + 出处决定否决权 + 层间不回退；并证明按错误代理验收的记忆会收进并放大幻影。

GEPA 式“小机制、高新颖性”仍然是对的形态；ORAgent 系统是载体，不是贡献。

---

## 1. 为什么 GEPA 类比成立，又不能照抄

| GEPA 要素 | 我们的对应 | 风险 |
|---|---|---|
| 一句话说清 | “代理成功信号下的自进化会把错误洗进盲区；修正是让验证知识进化，且只有有依据的检查才能否决” | 句子一长就变系统论文 |
| 挑战主流范式 | 挑战 GEPA / AlphaOPT / UMEM / RLVR 共同默认的“代理指标可信” | 不能挑战“自进化”本身（已被它们做得更好） |
| 跨任务 | OR 主领域 + 代码第二领域（弱测试 vs EvalPlus） | 只做 OR 会被看成小众 |
| 醒目曲线 | 进化轮数 ↑ → 代理准确率 ↑、真正确率持平/掉、幻影占比 ↑ | **曲线不出现则论点塌** |
| 可插拔 | 两条规则作为插件，套在 GEPA / AlphaOPT / 自修循环上 | 机制若绑死整条 OR 管线，就失去 GEPA 味 |

GEPA 的前提是评价指标可信。OR 上目标值匹配 32% vs 真正确 6.8%，正好打在这个前提上。所以我们是站在它肩膀上问它没问的问题，不是另起一个“更好的 prompt 进化器”。

## 2. 2026 年这块地已经被占了多少

### 2.1 已被占用（不能再当主贡献）

| 主张 | 谁占了 | 我们怎么处理 |
|---|---|---|
| 能执行 ≠ 正确 | VeriSimpl / Opt-Verifier / DA-RL / ORLoopBench | 背景 |
| OR 经验库 | AlphaOPT | 必须当基线；差异化写在“检查 vs 提示” |
| 记忆入库前要验证 | FGSE（假说门控）、ProcMEM（PPO Gate） | 引用为“行为更新的门控”；我们门控的是**验证器** |
| 代理假通过伤害自进化 | Blind Curator（假通过关掉技能退役）、Echo Gap（自评分通胀经记忆复利） | 引用为最近邻；改写为我们的更窄主张 |
| 从标注数据学可执行验证器 | AutoPyVerifier（DAG 搜索 Python 检查集） | 引用为“离线归纳验证器”；我们强调自进化闭环 + 代理标签本身错 |

### 2.2 仍然空着的缝（按强度排序）

**缝 1：内生洗白（最强）**  
Blind Curator 显式把“技能内容导致 judge 变瞎”标成 out-of-scope；Echo Gap / LUCID 的检测器抓的是崩溃、空结果、字面量泄漏——正是你们 F12 里会被修复循环洗掉的那一类。  
你们已有：幻影 43→115。还缺：在 **GEPA / AlphaOPT / 自修** 上，按轮次画出假通过率与幻影占比上升的曲线。

**缝 2：有金标准的结构化代理漏检（强）**  
Echo Gap 讲的是无标签、LLM 自评分；Blind Curator 讲的是注入噪声。你们讲的是：**对照了参考目标值之后仍有约 79% 的“匹配”是幻影**，且大量来自未写明惯例（C-INIT 约占幻影 54%）。这是规格欠定问题，不是 judge 松的问题。E/C/I 分类是独有资产。

**缝 3：验证知识作为记忆内容 + 出处否决 + 层间不回退（中强，机制）**  
FGSE 存的是行为补丁，环境验证器被当成真值。AutoPyVerifier 用开发集标签归纳检查，但标签若是目标值匹配，它会学会预测幻影为正确。  
我们的差异：记忆里存的是检查；晋升要审计集上精确重放的精度下界；无出处不能否决；L0 修复不得翻 L1/L2。

**缝 4：结构化相关假通过可 falsify Blind Curator 的 i.i.d. 悬崖（加分）**  
RetailOpt 粗算假通过率 ≈ (32−6.8)/(100−6.8) ≈ 0.27，低于他们 τ=0.10 时的 0.45 悬崖；若仍观察到退役失效或幻影放大，就能说明“假通过独立于内容”的通道模型不够。

## 3. 收紧后的论文主张

### 3.1 主张（可写进摘要）

> 当自进化系统优化一个**看起来有金标准、实则欠定**的代理成功信号时，优化会把错误从可检测失败推进到代理盲区（内生洗白），使假通过率随进化上升。我们在自然语言→优化建模上用隐藏的语义见证器量化这一现象，并给出修正：让可执行验证知识按出处与精度门槛进化；只有晋升后的检查可否决；修复按层接受，禁止破坏已晋升高层语义。

### 3.2 明确不主张

- 不说“首次发现能执行≠正确”  
- 不说“首次提出自进化会放大错误”  
- 不说“首次做 OR 经验库”  
- 不说“首次学可执行验证器”  
- 不用目标值准确率当唯一主指标  

### 3.3 差异化一句（对熟悉 FGSE / Echo Gap / AlphaOPT / AutoPyVerifier 的审稿人）

> 已有工作要么假设环境验证器可信再门控行为记忆（FGSE），要么诊断 LLM 自评分通胀并用固定检测器降分（Echo Gap），要么从标签归纳检查来逼近该标签（AutoPyVerifier），要么用目标值一致验收文本建模经验（AlphaOPT）。我们证明在欠定 OR 设定下，**连带金标准的目标值匹配也会系统性通过语义错误解**，且修复/进化会把错误洗进该盲区；因此记忆应进化的是验证器本身，且否决权必须由出处与审计精度授予。

## 4. 机制：小到像 GEPA，硬到能挡竞品

### 4.1 两条规则（核心插件）

**R1 出处决定否决权**  
候选检查在小审计集上精确重放 → 精度 Wilson 下界达标，且出处 ∈ {题面可引用片段, 数学结构, 已验证惯例} → `promoted`（可否决）；否则 `advisory`（只能提示）。

**R2 层间不回退**  
修复按字典序接受：不得改变任何已晋升的更高层检查结果。L0（可执行）修复若翻了 L1/L2，则拒绝该修复。直接打洗白。

### 4.2 经验单元（仍要，但不膨胀成系统）

```text
Check {
  layer: L0 | L1 | L2
  scope / trigger
  program: executable on (problem, model, solution)
  provenance: text-span | math-structural | convention(+domain)
  status: candidate | promoted | advisory | retired
  evidence: precision_lb, recall, false_veto, source_tasks
}
```

实现上可以很薄：一个检查库 + 晋升脚本 + 接到现有生成/修复循环的两处钩子（否决、接受修复前重放）。**不要**把 DAG、hybrid、structured IR 写进贡献。

### 4.3 和 AutoPyVerifier / FGSE 的接口

- AutoPyVerifier：可作“离线从审计标签学初始检查集”的组件；我们的增量是**在线进化 + 标签不可信时的出处门槛 + 与修复闭环耦合**。  
- FGSE：其门控可套在“是否写入一条行为经验”；我们额外问“环境分数本身是否假通过”，并让写入物变成检查。

## 5. 实验设计（按 go/no-go 排序）

### 5.1 必须先做的：放大曲线（决定路线 A 生死）

**设置**  
在 RetailOpt 开发集上，分别跑：

1. GEPA（开源，代理指标 = 目标值匹配）  
2. AlphaOPT（开源，若可跑）或简化版“失败→重试到目标值匹配→写经验”  
3. 现有报错驱动自修循环（你们已有洗白证据）

**每轮报告**  
可执行率、目标值匹配、witness 真正确、幻影数、假通过率（在不可执行/错误解中被代理判对的比例）、检查库大小（若有）。

**通过标准**  
至少一种方法上，幻影占比或假通过率随轮次显著上升，且目标值匹配上升。  
**失败标准**  
代理准了、真正确也同步升，幻影不升 → 论点从“放大”退化为“静态高估”，冲击力不够撑 NeurIPS 主贡献，需改投现象/基准或并入更弱的机制论文。

### 5.2 E0（无 API，立刻可做）

- D1 自动检查误报是否集中在无出处规则  
- RetailOpt 幻影按 E / C / I 拆分（尤其 C-INIT-only）  

用于写清：幻影不全是模型错，惯例欠定必须单独建模。

### 5.3 竞品在幻影指标下重评

VeriSimpl、Opt-Verifier、Draft→Audit、AlphaOPT 经验重放：报告目标值匹配 vs witness 真正确、修复翻转。预期：代理升、真正确少升、幻影不降或升。

### 5.4 机制消融

| 条件 | 预期 |
|---|---|
| 仅代理自进化 | 幻影↑ |
| +R1 出处否决 | 误否决↓、真正确↑ |
| +R1+R2 不回退 | 洗白↓、可执行不崩 |
| 无出处也可否决 | 误报≈高，重演 D1 49% |
| AutoPyVerifier 以目标值标签训练 | 学会放行幻影 |

### 5.5 第二领域（强烈建议）

**首选代码**：HumanEval/MBPP 自带测试 = 代理；EvalPlus = 更强真值。  
Echo Gap 已占 BIRD；第二领域用 SQL 容易撞车，除非把“执行正确”本身当假通过代理来反转他们的设定。

### 5.6 held-out 与闭源

OptArena 可用且未调过的集作表；闭源模型复跑回答“换强模型是否消失”。

## 6. 和路线 B（ORAgent 系统）的边界

| | 路线 A | 路线 B |
|---|---|---|
| 贡献 | 现象（内生洗白）+ 两条规则 | 整条管线 SOTA |
| 新颖性 | 中高（若曲线成立） | 中低（组件已占） |
| 现有消融 | 用得上（memory≈0 成动机） | 伤害（hybrid 不显著） |
| 会议 | NeurIPS / ICLR | KDD ADS（需部署）/ Industry / D&B |
| 形态 | GEPA 式小机制 | 系统论文 |

**建议**：论文走 A；工程继续叫 ORAgent / 现有管线；若有真实部署，ADS 另开一篇，结果不重叠。

## 7. 风险登记（按概率 × 杀伤力）

1. **放大曲线不出现**（高杀伤）→ 先做，3 周内 go/no-go。  
2. **C-INIT 占比过高**（中高）→ 正面写成欠定/惯例问题，不要全算成模型错。  
3. **审稿人：“FGSE/Echo Gap/AutoPyVerifier 已做过”**（高）→ 摘要与相关工作必须用第 3.3 节那句对齐。  
4. **第二领域做不动 / 现象复现弱**（中）→ 至少完成代码弱测试 vs EvalPlus 的静态幻影率；动态放大可只在 OR。  
5. **检查晋升门槛失败**（中）→ 退路：以现象 + 竞品重评 + 审计协议为主的短文/基准向。  
6. **AlphaOPT / AutoPyVerifier 后续补强**（低中）→ 盯 arXiv。

## 9. 结论

路线 A 值得做，且比系统路线更接近 NeurIPS/ICLR 口味，**但必须把贡献从“代理指标有害”收窄到“有金标准的欠定代理 + 内生洗白 + 验证知识进化与出处否决”**。  
GEPA 提供的是形态模板（小、硬、可插拔、跨任务曲线），不是问题本身。  
下一步唯一关键的是：**先画出放大曲线**；曲线不成立就不要硬写机制论文。
