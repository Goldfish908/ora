# BWOR 已保存响应的语法归一化重放协议 v0.2

状态：在 v0.1 失败归因之后、运行 v0.2 之前登记。v0.1 及其结果已暴露，因此本轮是历史开发，不是 frozen 或新自然候选评估。

## 已观察到的输入问题

- BWOR-010/012 的 `path` 直接写数据键，解释器要求 `data.` 前缀；旧静态检查没有覆盖这种写法。
- BWOR-002 将列表索引写成 `lookup:{path,index}`，当前表达式语法要求 `index:{value,at}`。
- BWOR-005 截断，不能形成完整模型，不尝试补全。

## 固定变换与拒绝规则

在共享初始处理中，变量列表归一化之后、模型验证之前增加 `normalize_candidate_paths`：

1. 对表达式中的直接数据路径，只有加上 `data.` 后能在候选自己的 `data` 对象中解析，才改为带前缀路径。
2. 对 `lookup:{path,index}`，只有路径指向候选自己的列表、index 是非布尔整数字面量且在列表范围内，才改为 `index:{value,at}`。
3. 不添加或修改任何数据常数，不猜缺失路径，不改变量名、约束、目标或问题语义，不读取公开答案进行转换。
4. 非 data 命名空间、缺失路径、非法 lookup/index 形式在求解前 fail-closed。原始响应和输入对象保持不变，记录所有转换。

三臂、独立参考评分、预算和安全规则与 v0.1 相同，不重试生成、不改 prompt、不挑选案例。输出到新的 `work/bwor_saved_contract_replay_v0.2/`，保留 v0.1。

## 归因

- 路径/索引变换带来的有效求解称为**确定性契约归一化后的执行恢复**，不是 LLM 新语义修复。
- 只有独立参考模型与解确认的正确性改善才单列；不因“可以求解”就称业务正确。
- 这批输入已用于设计归一化，后续自然候选评估必须单独登记并冻结同一版本，不能把本轮数字当 heldout 增益。
