### 5.1 部分数据的方法学警示（2026-11-02 中期检查，~66% 记录）

在中期快照（B' ~212/322 条记录）上直接跑主分析会产生**系统性低估
B'** 的假象：B' 正在进行的细胞只写入了部分轮次记录，分析脚本按最新
已完成轮次计终局，使在途细胞（多为打满 3 轮的难细胞）被记为失败；
而对照 B 臂早已全量完成。表现为配对翻转 B-only 19 / B'-only 8、
crash 47 vs 37——与 §5 完全配对快照方向相反。结论：**配对比较只对
两臂均已收官的细胞有效，部分数据快照不可用于决策**；最终结论以全量
完成后重跑的 `psv_online_analysis.py` 主表为准。

## 6. 结论

**假说成立。** B 臂 crash 残余膨胀（18→37）确由闸门反馈重写引入的新
API 错误所致：B' 臂（guard v0.1）将 crash 残余从 37 压回 **19**，与无
闸门 A 臂的 18 基本持平，即 guard 几乎完全抵消了闸门重写带来的 crash
副作用。

定量结论：

1. **crash 残余 37→19(−49%)**，同时真成功率 87→90(45.8%→47.4%),
   配对净翻转 +3。guard 不仅防崩，还把省下的轮次转化为真实成功。
2. **失败层级整体上移**:crash 减少的 18 例几乎全部转化为
   witness_infeasible(+20)——代码从"跑不起来"变成"跑得起来但语义不
   满足出题人意图"。崩溃层问题已被 guard 显著压缩，**主要矛盾转移到语
   义层**（witness_infeasible 70 例，占残余的 70%)，这正是蒸馏/语义
   层约定的用武之地。
3. **错误级联真实存在但有限**:guard v0.1 单层预算下仍有 19 例 crash,
   中期分析显示其中 18/22 可被 v0.3(G2/G6/G7/G8）离线捕获。
4. **成本**:LLM 时间 +7%,solve +27.7%（可运行代码增多所致，属预期）。

后续臂决策（B''):**值得跑**。guard v0.3 离线检出率 97.0%、误报 0%,
且能覆盖 B' 残余 crash 的 82%(18/22);B''(v0.3 + 闸门，guard 预算可
考虑 2 次/轮以覆盖级联）预期将 crash 残余压到个位数，进一步把失败推向
语义层，为语义约定先验（蒸馏 v0.2）提供更干净的信号。
