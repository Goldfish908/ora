# D1: Checker-Authoring 冷启动实验设计 v0.1

日期:2026-11-04。状态:设计定稿,实施中。

## 1. 问题

witness 语义规则目前是手工按数据集/题族定制的,换数据集清零(阶段 C 实测:
IndustryOR 上 21–30% 出解细胞是幻影,无任何在线机制能发现)。已有工作
(ReLoop 扰动测试、Li & Hai 的 falsification 电池、ORSMT)都不能覆盖
"幻影组件/错误取值"类错误,也没有自动生产过程。

**D1 回答:LLM 能否只读题面(不看真值、不看失败代码)自动起草出可执行的
语义检查规则,在没见过的数据集上冷启动检出幻影?**

## 2. 诚实性协议(防泄题)

- authoring agent 的输入**只有** `en_question`;**绝不**给 `en_answer`、
  不给被 judge 的代码、不给任何题目的对错信息;
- 规则产出后才在带标签细胞上评估(标签来自 en_answer,oracle 口径
  |obj−ref|/|ref| ≤ 1e-3);
- 这与部署场景同构:新数据集到来,先有题面,规则必须先于任何求解结果存在。

## 3. 规则形式(v0)

每条规则 = 一个 Python 函数,签名:

```python
def check(code: str, objective: float | None, params: dict) -> str | None
    # 返回违例描述(str)或 None(通过)
```

- `code`:被审细胞的 gen.py 全文;
- `objective`:打印的目标值;
- `params`:authoring agent 同时产出的**题面参数抽取**(JSON dict,
  例如需求量、成本、容量、起订量……),规则可以引用它做数值一致性检查。

规则类型不设限(静态代码检查、数值边界、量纲/守恒、目标值合理区间……),
由 agent 自由发挥,每题 ≤5 条。规则在沙箱中执行,超时 5s,异常=规则自身
作废(记为 rule_error,不计误报也不计检出)。

## 4. 对照臂(D1 矩阵)

| 臂 | 机制 | 资产 |
|---|---|---|
| A0 | 无校验(所有出解即接受) | 无 —— 现状地板 |
| A1 | 自一致性:同题 3 次独立采样,目标值两两相对差 >5% 则报警 | 零资产 |
| A2 | **checker-authoring**:题面 → ≤5 条 Python 检查规则 | 自动生产,题面级 |

(A1 直接用已跑完的 Z0 单发 + 补采 2 个同配置样本,共 3 样本;
扰动探针臂因实现成本高且 falsification 论文已给出理论上限与检测率,
D1 暂不实现,作为相关工作数字对照引用。)

## 5. 评估集与指标

- 评估集:阶段 C 三臂台账每题最后一轮出解细胞,240 个
  (61 幻影 / 179 正确,Z0/Z1/Z2 混合——这正好模拟真实部署中
  不同质量来源混合的输入流);
- **检出率** = 被至少一条规则判违例的幻影数 / 61(越高越好);
- **误报率** = 被判违例的正确细胞数 / 179(越硬性的指标,目标 <5%);
- 规则级统计:每题规则数、rule_error 率、单规则命中率;
- 与既有数字的对照:Open-Jev AUC 0.662 / 误放行 98.4%@t=0.5(同数据集);
  falsification 电池检测率 56.1%(其论文,不同错误分布,仅作量级参考)。

## 6. 通过线(预注册)

- **检出率 ≥50% 且误报率 <5%** → 冷启动可行,进 D2(闭环接入修复环);
- 检出率 20–50% → 部分可行,分析规则失败类型后迭代一轮提示词;
- 检出率 <20% 或误报 ≥20% → 否,转"failure-informed authoring"
  (给 agent 看失败案例的变体,测其泛化),并重估方向。

## 7. 实施

- `scripts/d1_author.py`:逐题 authoring(--limit 冒烟);
- `scripts/d1_apply.py`:规则在 240 细胞上沙箱执行+汇总矩阵;
- 输出:`runs/d1_authoring/rules_<id>.json`、`runs/d1_authoring/matrix.json`;
- LLM:内网 Qwen3.8-27B,thinking on,T=0.6(与主线一致)。
