# D2: 反例驱动的规约进化(模板槽位化 + 自我标定)v0.1

日期:2026-11-04。状态:设计定稿,待实施。
前置:D1(检出 52.5%/误报 49.2%,未过线)、D1.5(oracle 上界 42.6%@FP=0,
19/499 条规则;贪心选择 test 34.8%/7.2%)。

## 1. 从 D1/D1.5 学到的设计约束

D1.5 的决定性数字:**即使完美选择,现有规则库在 FP=0 下检出上限只有
42.6%** → 瓶颈在规则生成端,不在选择端。因此 D2 改生成,选择器只做补充。

D1 的分层诊断给出生成端的两个硬约束:

1. **禁止自由文本代码 grep 规则**(Youden J=−8pp,净效应为负);
2. **数值规则必须带证据**(D1 数值规则误报 11.7%,抽查看主要是
   幻觉边界——author 编造了题面里并不存在的数值约束)。

## 2. 规则形态 v2:参数化模板 + 槽位 + 证据

规则不再是自由函数,而是**模板实例**:

```json
{
  "template": "objective_range",
  "slots": {"lower": 15000, "upper": 56850000},
  "evidence": {"lower": "题面原文 span: 150 tables at $100 each...",
               "upper": "题面原文 span: total demand ... max price ..."},
  "legit_exceptions": "题面明确允许的情形(如允许初始库存),无则 null"
}
```

执行语义与 D1 相同(沙箱 check(code, objective, params) → str|None),
但生成被约束在模板库内。v0 模板库(覆盖 D1 真阳性的全部机制):

| 模板 | 机制 | 槽位 | 所需输入 |
|---|---|---|---|
| objective_range | 目标值越出物理可能区间 | lower/upper 推导式 | objective, params |
| phantom_resource | 凭空资源(初始库存/免费容量) | resource 名, 题面授予量 | code, params |
| sense_direction | max/min 方向错 | 期望方向 | code |
| constant_fidelity | 关键常数与题面不符 | 常数名→题面值 | code, params |
| conditional_moq | 条件化业务关系 q=0 ∨ q≥m | 门槛 m 的题面绑定 | code(结构), params |

每个模板的 code 骨架由人写死一次(可审、可单测),author agent 只填
槽位+给证据。这把"LLM 写代码"降级为"LLM 做阅读理解和数值推导",
错误面大幅收缩。

## 3. 自我标定协议(零真值)

每个规则实例入库前必须通过自测,author 需同时产出:

- **must-fire 用例**:一个该规则必须报警的最小输入(对 objective_range
  就是一个越界数值;对 phantom_resource 就是一段含幻影变量的代码片段);
- **must-pass 用例**:一个该规则不得报警的合法输入(如题面明确允许
  初始库存时的对应代码片段;或界内目标值)。

沙箱执行两个用例,fail 则规则打回(最多修订 2 次,仍 fail 则弃)。
这是 CEGIS 的最小化形态:反例由 author 自己构造,不需要真值。

## 4. 旗舰判别实验:初始库存对照对

区分"学到业务关系"与"记住补丁"的预注册实验:

- **幻影组**:RetailOpt 幻影注入(题面无初始库存,代码捏造)——
  phantom_resource 规则应报警;
- **合法组**:构造/选取题面明确写有非零初始库存的对照题(同族、同
  参数尺度)——同一条规则必须放行;
- 通过线:幻影组检出 ≥80% 且合法组误报 ≤10%(比全局线严,
  因为这是单机制对照实验);
- 迁移检验:在 IndustryOR 细胞集上看 phantom_resource 模板实例的
  检出/误报(与 D1 同机制规则对比)。

## 5. 评估协议(与 D1 可比)

- 同一 240 细胞集,同一 dev/test 题内分半(seed 0);
- 对照臂:A1 自一致性、D1 全规则、D1 贪心选择(34.8%/7.2%)、
  D2 模板规则、D2+选择器;
- 通过线沿用预注册:检出 ≥50% 且误报 <5%(test 半);
- 报告 dev→test 泛化间隙。

## 6. 与参数线的接口(JEV 的位置)

- D2 的全部产物(模板实例、自标定用例、触发记录、细胞标签)落盘,
  作为**判官训练语料**;
- 参数线数据工厂(合成注入)产出 ≥1k 条带标签轨迹后,用 Open-Jev
  配方在 27B 基座上训练判官头(即插即用已否决:AUC 0.534/0.662,
  价值在训练配方不在 checkpoint);
- 最终消融三方对照:**纯规则门 / 纯学习判官 / 联合**,回答
  "符号检查与学习型判官是否互补"。

## 7. 诚实性协议

- authoring 仍然只看题面,真值只做事后评估;
- 模板库设计使用了 RetailOpt 失败知识(训练侧设计先验),在
  IndustryOR 上评估时声明这一点(与 D1 协议一致);
- must-pass 用例若引用题面文本,需摘录 span 存档,供人工抽检。

   再填槽位),自标定循环;
3. IndustryOR 100 题全量 → 240 细胞矩阵 → 与 D1 各臂对照;
4. 旗舰判别实验(RetailOpt 库存对照对);
