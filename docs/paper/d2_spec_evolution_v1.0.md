# D2: 反例驱动的规约进化(模板槽位化 + 自我标定)v1.0(含全量结果)

日期:2026-11-04。状态:**v1 全量完成——误报达标(5.6%)、检出严重不足
(9.8%),诊断清晰,D2.1 方向确定**。

## 1. 从 D1/D1.5 学到的设计约束

D1.5 的决定性数字:**即使完美选择,现有规则库在 FP=0 下检出上限只有
42.6%** → 瓶颈在规则生成端,不在选择端。因此 D2 改生成,选择器只做补充。

D1 的分层诊断给出生成端的两个硬约束:

1. **禁止自由文本代码 grep 规则**(Youden J=−8pp,净效应为负);
2. **数值规则必须带证据**(D1 数值规则误报 11.7%,抽查看主要是
   幻觉边界——author 编造了题面里并不存在的数值约束)。

## 2. 规则形态 v2:参数化模板 + 槽位 + 证据

规则不再是自由函数,而是**模板实例**:

```json
{
  "template": "objective_range",
  "slots": {"lower": 15000, "upper": 56850000},
  "evidence": {"lower": "题面原文 span: 150 tables at $100 each...",
               "upper": "题面原文 span: total demand ... max price ..."},
  "legit_exceptions": "题面明确允许的情形(如允许初始库存),无则 null"
}
```

执行语义与 D1 相同(沙箱 check(code, objective, params) → str|None),
但生成被约束在模板库内。v0 模板库(覆盖 D1 真阳性的全部机制):

| 模板 | 机制 | 槽位 | 所需输入 |
|---|---|---|---|
| objective_range | 目标值越出物理可能区间 | lower/upper 推导式 | objective, params |
| phantom_resource | 凭空资源(初始库存/免费容量) | resource 名, 题面授予量 | code, params |
| sense_direction | max/min 方向错 | 期望方向 | code |
| constant_fidelity | 关键常数与题面不符 | 常数名→题面值 | code, params |
| conditional_moq | 条件化业务关系 q=0 ∨ q≥m | 门槛 m 的题面绑定 | code(结构), params |

每个模板的 code 骨架由人写死一次(可审、可单测),author agent 只填
槽位+给证据。这把"LLM 写代码"降级为"LLM 做阅读理解和数值推导",
错误面大幅收缩。

## 3. 自我标定协议(零真值)

每个规则实例入库前必须通过自测,author 需同时产出:

- **must-fire 用例**:一个该规则必须报警的最小输入(对 objective_range
  就是一个越界数值;对 phantom_resource 就是一段含幻影变量的代码片段);
- **must-pass 用例**:一个该规则不得报警的合法输入(如题面明确允许
  初始库存时的对应代码片段;或界内目标值)。

沙箱执行两个用例,fail 则规则打回(最多修订 2 次,仍 fail 则弃)。
这是 CEGIS 的最小化形态:反例由 author 自己构造,不需要真值。

## 4. 旗舰判别实验:初始库存对照对

区分"学到业务关系"与"记住补丁"的预注册实验:

- **幻影组**:RetailOpt 幻影注入(题面无初始库存,代码捏造)——
  phantom_resource 规则应报警;
- **合法组**:构造/选取题面明确写有非零初始库存的对照题(同族、同
  参数尺度)——同一条规则必须放行;
- **切片约束**:对照对一律从 gapcheck60 / F5–F8 出,禁止用 dev40
  训练侧的题(见 p_track_repair_training_v0.1.md §2);
- 通过线:幻影组检出 ≥80% 且合法组误报 ≤10%(比全局线严,
  因为这是单机制对照实验);
- 迁移检验:在 IndustryOR 细胞集上看 phantom_resource 模板实例的
  检出/误报(与 D1 同机制规则对比)。

## 9. D2 v1 全量结果(2026-11-04)

**Authoring**:99/100 题成功,共产出 337 条通过自标定的规则
(constant_fidelity 211 / sense_direction 84 / objective_range 34 /
phantom_resource 8 / conditional_moq 0;14 条被自标定打回淘汰);
单测 22/22;沙箱执行 808 次零 rule_error。

**240 细胞矩阵与各臂对照**(D1-greedy 为 test 半口径,其余全量):

| 门 | 检出(61 幻影) | 误报(177 正确) | 备注 |
|---|---|---|---|
| D1 自由规则全量 | 52.5% | 49.2% | 检出高,误报爆炸 |
| D1 贪心选择 | 34.8% | 7.2% | dev 选择,test 评估 |
| A1 自一致性 | 16.4% | 5.0% | 55% 题无法投票 |
| **D2 模板+自标定** | **9.8%** | **5.6%** | 误报达标,检出塌缩 |
| D2 ∨ A1 | 23.0% | 9.5% | 当前最干净组合 |

**模板级触发**:objective_range 3 TP/2 FP;constant_fidelity 3 TP/
11 FP(主要误报源);sense_direction 0/0(84 条零触发——安全但无效);
phantom_resource 0/0(仅 8 条)。

**诊断(为什么检出塌缩)**:

1. **实例化覆盖率不足**:35 个幻影题里只有 12 题实例化了
   objective_range、3 题 phantom_resource——多数幻影题根本没有
   对应的检测器存在;
2. **界太松、方向单一**:幻影目标值落在物理区间内部则不触发
   (例:id=2 界 [0,125],幻影 50,真值 125)。D1 真阳性靠的是
   *紧锚点界*(如"全部新购成本 350"这种平凡策略参照),v1 模板
   的"物理区间"做不到这么紧;
3. **紧锚点界确实有效**:id=19 由 MOQ 推出的下界"至少订 100 把
   椅子 → 最低花费 4000"直接抓住幻影目标 365(真值 4000);
   id=2 上界 125 恰好等于最优值——贴着真值的界才是好界;
4. **幻觉边界基本绝迹**(D1 数值规则 FP 11.7% → D2 全库 5.6%),
   证据 span + 自标定对误报的压制按设计生效。

**结论**:v1 在精度-召回权衡上过度偏向保守。预注册线(≥50% &
<5%)未过,但两个子结论成立:(a) 自标定+证据协议能压误报;
(b) 检出瓶颈在**模板表达力与实例化召回**,不在执行。

## 10. D2.1 方向

1. **锚点界模板**替换物理区间模板:从约束语句推导紧界——
   MOQ/至少/至多子句 → 最小/最大花费;平凡策略参照(全部新购、
   全部外包、不做任何优化)作为上下界;author 必须给出"界为什么
   紧"的推导;
2. **强制实例化**:凡出现资源/库存/容量名词必须实例化
   phantom_resource;凡有目标函数必须尝试 objective_range,
   推不出紧界要说明理由;
3. **级联部署配置**:D2(高精度)报警 = 高置信拦截;D1-greedy
   或 A1 报警 = 二级复核——整体 FP 可控且召回叠加;
4. constant_fidelity 误报治理:字面量匹配升级为"数值参与约束"
   检查(常数出现在目标/约束系数中才算),或降为提示级信号。
