## 4. 失败层级

### 4.1 参考覆盖与共享 schema

13/41 参考不合格，完整保留在全 41 覆盖报告中。参考本身由 Qwen 构造，虽与候选和 binding 隔离，但不是独立人工金标；共同语义偏差仍可能存在。共享变量声明是强先验，初始正确率较高，不能外推到无 schema 的完整 agent。

### 4.2 binding 语义覆盖与误报

- 仅 16/28 达到完整行为覆盖，平均覆盖约 83.4%。
- **BWOR-024**：复杂排程 binding 行为覆盖 45.2%，并在干净解上有 9 条误报，说明复杂依赖/位置绑定仍未解决。
- **BWOR-041**：题面要求“每种玩具在每个门店各 1500”，binding 错为“所有玩具在该门店合计≤1500”，是真实的约束粒度错误。
- **BWOR-047**：binding 多加期末备船储存费 `constant=40`，但第三年末尚未发生延迟，参考模型正确地未计该项。它先造成真实误报，再触发修复，最终因输出契约失败而修坏 win。

这些案例说明：**最危险的不是 DSL 不能执行，而是 LLM 生成的业务绑定看似合理却错误。** 模板可执行性不能替代独立语义验证。

### 4.3 修复输出契约与复杂度

28 个 `invalid_repair` 的分布：

| 原因 | 数量 |
|---|---:|
| `problem_id mismatch` | 26 |
| 无完整 JSON | 1 |
| 约束数超过 2000 | 1 |

按臂分布为 A0 6、A1 8、A2 6、A3 8。多数与修复 prompt 未明确要求 `problem_id` 一致，另有无输出和复杂模型约束爆炸。发现这些问题后没有修改 prompt、替换 ID、归一化或重跑，因为它们属于 frozen 后的配置变更。不能把它们全部误写成 DVSA 的语义失败，也不能忽略其对配置级 win-safe 的影响。

### 4.4 覆盖不足与 satisfied 误接受

A2 的 22 次 `no_call` 避免了不必要的自评，但 satisfied 并不等于整个模型正确。BWOR-034 中，文本和 no-memory 修复成功，A2 未触发并保持错误；BWOR-025 的 binding 行为覆盖只有 39.3%，A2 也没有触发。保守 gate 同时带来调用节省与漏修风险。

## 7. 机制边界与可用结论

可以保留的结论是：

- 可执行语义规格能发现很多受控错误（272/304），并能提供可审计的数值证据。
- 保守 gate 可显著减少修复调用（6 vs 28），且 22 次 `no_call` 避免了一部分不必要的自评。
- RetailOpt dev 的 10 个语义触发案例和 BWOR validation 的 BWOR-058 提供了局部成功先例，但不能抵消 frozen 的泛化失败。
- 失败可以被精确定位到参考覆盖、binding 粒度、常数项、复杂依赖、输出契约和执行失败，而不是笼统归因于“LLM 不可靠”。

不能支持的结论是：

- DVSA 相对文本 memory 有稳定质量优势、普遍零误报、跨域通用自进化或 SOTA；
- 只看调用少就宣称等质量成本最优；
- 把 typed interface、SMT、CEGIS 或普通经验蒸馏包装成本文首创；
- 把共享 schema 的结果写成自主 agent 的端到端能力。

后续研究首先应解决**独立语义标签和 binding 验证**，而不是先扩大模型或数据规模。修复输出契约也是必要的工程前提，但在本 frozen 协议下不追加补救实验。
