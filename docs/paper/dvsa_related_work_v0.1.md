# DVSA 相关工作矩阵与独立贡献审查 v0.1

日期：2026-11-11。状态：设计前审查；本文不把尚未实现的 DVSA 写成已验证贡献。

## 1. 研究对象与术语

**DVSA（domain-validated semantic assets，领域验证语义资产）**暂定义为：面向一组明确适用域的优化问题，把业务要求写成带来源、作用域、输入绑定和版本的实例级语义检查；候选资产只在开发域的独立正反例上验证，冻结后才可复用。其输出是带数值证据的 `violated / satisfied / unknown`，而不是仅凭目标值或 LLM 自评作判定。

这里有两个必须分开的对象：

1. **单题规格**：这一题要求什么，如何根据题面、数据和返回解重算。
2. **可复用资产**：哪些要求属于一个明确的问题域，如何绑定新实例的数据与解，在什么独立证据下允许复用。

`m1_witness/retailopt.py` 已覆盖前者的一部分；它不能直接证明后者。DVSA 的研究增量只能是第二项及其端到端效果，而不是给第一段 Python 检查改名为“资产”。

## 2. 机制矩阵

以下“泛化”指论文实际验证的范围，不替作者扩大主张。

| 工作 | 输入假设 | 验证粒度与证据 | 反馈来源 | 更新对象 | 泛化协议 | 与 DVSA 的真实边界 |
|---|---|---|---|---|---|---|
| **ORSMT** ([v1](https://arxiv.org/html/2610.29145v1)) | 可获得的 source requirements、书面数学、实例化 solver code、report；进入精确核的部分须为有理系数仿射模型，变量可为实数、整数、布尔 | 模型/代码/报告的精确关系；source contract 也含来源文本、量化作用域和适用条件；SMT 给出不可满足证明或局部化反例 | 精确 SMT 查询，不是 LLM 自评 | 修复当前数学、代码或报告；采用的候选必须重新过关系检查 | 3,034 个问题、6 个生成器，按可用输入与精确关系分层；不是跨任务资产晋升实验 | **最近邻，不能忽略。** 它已经覆盖 typed interface、source contracts、固定实例反例和认证修复。DVSA 只能研究显式适用域内的跨实例资产生命周期、无完整形式模型时的解级业务重算，及其相对文本 memory 的增量 |
| **SOVER** ([论文](https://arxiv.org/abs/2609.00728), [代码](https://github.com/baranwa2/SOVER)) | 两个数学优化形式及变量/参数映射；线性/混合整数用 Z3，非线性连续问题用 dReal；有界展开等限制须随结果披露 | 两个重构的可行域与目标顺序是否等价，不是某个返回解是否满足业务要求 | 映射由 LLM 辅助提出，Z3/dReal 负责验证；数值采样只是诊断，不是形式证明 | 当前变量/参数映射和重构验证 | EquivaFormulation 派生对及 NLEQUIV-150；100 个等价、50 个困难非等价非线性对；报告一个已知正例映射提取失败 | 可借鉴“LLM 提议、独立工具裁决”的分离。不能把 DVSA 的实例解通过检查称为模型等价证明，也不能把 SOVER 写成只比较最优值 |
| **ReLoop** ([v6](https://arxiv.org/html/2602.15983v6), [代码](https://github.com/junbolian/ReLoop)) | 自然语言优化问题、可执行模型及可扰动参数；不要求逐题标准答案来做行为检查 | 结构化生成；执行恢复；对约束/目标相关参数做 solver 行为扰动；带回归保护 | 求解器行为差异，而非纯文本自评 | 当前题的模型/代码及求解器诊断 | RetailOpt-190、MAMO-ComplexLP 等，多种基座；分别报告可执行性、可行性、形式正确性 | 它不是“只修执行、不修语义”。DVSA 的差异是用外部业务不变量直接重算返回解，并检验其跨实例复用，而非声称首次发现语义错误 |
| **CEGIS** ([Solar-Lezama 等](https://arxiv.org/pdf/1710.07740v1.pdf)) | 可执行的候选生成器与能证明或给出反例的验证器 | 对候选成立或返回具体反例；反例加入后续合成 | 验证器反例 | 候选程序/规格 | 取决于归纳合成任务；反例覆盖不自动等于对未见任务的统计泛化 | DVSA 可复用这一候选—反例循环。**CEGIS 不是我们的发明**；新实验必须检验反例验证后的资产是否迁移，而不只修已见反例 |
| **CFOE** ([论文](https://arxiv.org/html/2610.22984v1)) | 冷启动、failure-only 的经验流；不同实验再放宽 verifier/成功轨迹条件 | 最终环境结果与轨迹分析；它研究经验更新，不提供 OR 业务语义证明 | 失败交互；对照中另有 verifier feedback 与成功轨迹 | 非参数经验、技能或 agent 外部状态，视具体范式 | 三种自进化范式、多个 LLM、四种交互环境；重点为 repair–generalization gap | 它直接削弱“修过失败就形成通用能力”的叙事。DVSA 的硬检查可解决错误反馈，但不能据此假定解决迁移；冻结测试仍是必要条件 |
| **COOPA** ([论文](https://arxiv.org/html/2606.27611v1), [代码](https://github.com/xxxxxa-hub/COOPA)) | NL 问题；多候选结构化 formulation，带元素级文本溯源和置信度；路由到专用 optimizer | 建模置信度选择与人工可审计溯源；最终公开分数仍以 gold objective 的指定误差判定，不是独立业务语义标签 | LLM 多维置信度、max-min 选择与迭代建模；solver 执行 | 当前题的 formulation、候选选择和 solver 路由；不是跨题验证资产库 | ComplexLP、IndustryOR、BWOR，8 个基座、4 个基线；同模型同条件比较 | 它是质量/成本对照，不是 witness 方法基线。其来源引用与人工审计值得借鉴，但置信度不能替代独立语义检查；比较须使用同一容差和分母 |
| **OptiMUS** ([论文](https://arxiv.org/html/2310.06116v2)) | NL 问题、结构化模型、数据和代码；可生成测试与检查代码 | 模型连接、执行、解和最优性测试；单点数据正确不保证其他数据点正确 | solver 执行及自动测试，部分步骤由 LLM 生成 | 当前题建模和代码 | 多类 NL 优化题及案例，不是版本化领域资产研究 | 生成测试代码和参数扰动均已有先例。DVSA 若仅“让 LLM 写 checker”没有足够新颖性 |
| **LLM4MIP** ([项目](https://llm4mip.github.io/)) | OR 问题、历史实例经验和求解反馈 | 求解结果验证与实例经验检索/蒸馏 | 执行反馈与历史轨迹 | 非参数经验及当前解 | 跨实例/数据集效果依其具体实验设置；引用前逐表核口径 | “经验积累”本身不新。DVSA 必须比较同一文本经验与其可执行、经验证版本，避免只重复成功轨迹迁移 |

## 4. 独立贡献声明（限定版）

在完成后续实现和对照之前，只能提出以下**待检验贡献**：

> 在已有形式化验证、行为验证和实例经验学习之上，研究具有显式适用域、来源绑定和版本记录的实例级业务语义资产。资产由候选检查经独立正反例验证后冻结，跨实例复用时记录绑定、激活和 UNKNOWN；研究其作为修复反馈，是否比同内容的文本经验更可靠，并区分域内复用、冷启动构造与旧域规则直接迁移。

可主张的差异若被实验支持，是以下组合及其证据链，而不是任一单点：

1. **复用单元**：不是整段 prompt，也不是某题答案，而是单一业务机制、明确适用条件和数据/解绑定的检查规格。
2. **信任来源**：不是作者自测或 LLM 置信度，而是开发集上独立干净解和受控错误；UNKNOWN 不计为成功检出，脚本错误不当作业务违规。
3. **生命周期**：候选、验证、冻结、激活、失效均有版本和来源记录；测试集不能反向写资产。
4. **验证层级**：输出仅说明当前解对已编码业务不变量的满足情况；模型语义等价、最优性和业务规约正确性分别处理。
5. **迁移协议**：域内冻结资产与新域冷启动分开；直接迁移 RetailOpt witness 只是否定性对照，不预设它应有效。

## 5. 明确不重复、不越界的声明

- 不声称首创确定性检查、typed semantic interface、source traceability、反例驱动修复、求解器扰动、经验蒸馏或成功轨迹迁移。
- 不声称“当前解通过业务检查”蕴含模型语义等价、所有实例正确或最优性。
- 不把由同一 witness 构造的错误再交给该 witness 检出，作为独立真值；这类实验只能做机制 sanity check。
- 不把 NLP4LP 的专家 `problem_info` 当作自然语言自动理解的结果。若用其导出规格，实验名称必须是 **specification-assisted audit**，并单列从 NL 自动构造规格的覆盖率。
- 不把旧 RetailOpt/IndustryOR 的聚合提升当作新协议下 DVSA 的证据；旧 MAMO/NLP4LP sealed 结果也不能重命名为新实验。
- 不把单条资产、单题修复或统计不显著的多轮更新称为“通用自进化”。论文题目暂不使用 Self-Evolving。
- 不通过购买更强闭源模型来证明资产有效。闭源模型只能运行已冻结的 harness 对照，帮助分离基座能力和机制贡献。

## 6. 与 ORSMT 的最小区分实验

若后续资源允许，优先做同题互补对照，而非再写一个弱文本 judge：

1. 对一个同时具有数学模型、代码和返回解的实例，运行 ORSMT 的可支持关系查询；记录无法输入、无法决定和已证明的范围。
2. 对同一返回解运行 DVSA，检查已编码业务不变量，给出数值违规证据。
3. 构造两种分离案例：(a) 模型关系不一致但当前解未触发某项业务约束；(b) 模型/代码彼此一致、却共同违反一个已承认的业务要求。
4. 分别报告模型关系、当前解满足性、参考规约冲突，不压成一个“正确率”。

该实验用于界定互补性，不预设 DVSA 比精确 SMT 更强。对能形式化且能决定的关系，精确证明优先；DVSA 不应用数值容差检查冒充形式证明。

## 7. 目前的风险判断

- **最大风险不是 detector 检不出，而是新颖性和规格来源。** ORSMT 的 source contracts 已非常接近“业务要求可执行化”；只用 RetailOpt 手写规则不能支撑独立贡献。
- **第二风险是 oracle 泄漏。** 从专家公式或参考解提取的规则必须与待检查生成器分离，并披露人工/专家规格假设。
- **第三风险是资产复用被数据绑定吞掉。** 若每题仍需 LLM 重写全部检查，实验证的是 checker authoring，不是可复用资产；必须记录零 LLM 的 frozen-asset replay 和真正的跨题激活。
- **第四风险是评估没有剩余 frozen test。** IndustryOR、MAMO sealed、NLP4LP sealed 已广泛使用，均不能改名叫本轮 frozen test。新域须从未做逐题实验的公开数据中选择，并先登记暴露情况。

因此，下一步不是直接跑更多 memory，而是定义最小规格、独立审计标签与未暴露新域，随后用小规模开发实验判断这条路线是否值得继续。
