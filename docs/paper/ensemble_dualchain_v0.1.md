# 双链集成仲裁 v0.1:两条独立管线 + witness 仲裁,无额外 LLM 成本拿到 68.4%

日期:2026-11-03
脚本:`scripts/ensemble_arb.py`(纯离线重放,确定性,零 LLM 调用)
输入:B'' 臂结果(`runs/m1_presolve/m1_presolve_online_v{0..4}.jsonl` 等,guard v0.3)
与 combo 臂结果(`runs/m1_presolve/m1_presolve_combo_v{0..4}.jsonl`,P2 先验 + guard v0.4)
输出:`runs/m1_presolve/ensemble_dualchain.md`
图:`docs/paper/figs/ensemble_dualchain_v0.1.png`

## 1. 动机

`docs/paper/combo_arm_v0.1.md` §3 已经发现:两条管线虽然架构同源(都是
"生成 → guard 检查 → 预求解闸门 → witness 环"),但失败谱**互补**:

- B''(无先验 round-1)胜出的细胞,combo(P2 先验生成)反而失败,反之亦然;
- 翻转细胞 29/36,远高于随机波动,说明多样性来自"有无先验注入"这一
  生成路径差异,而不是采样噪声。

失败互补 ⇒ best-of-N 集成自然成立:两条链都跑完,用 witness 的**可行性裁决**
在候选解里挑一个。整个过程是确定性的离线裁决,不增加任何 LLM 调用,
只增加约 2× 的单链求解/执行成本(solver 秒级)。

## 2. 方法

对 190 个细胞(on 模式),每题取两条链各自的最终候选(若有):

- **E1 并集(witness 可行 + grade)**:任一链通过 witness 可行性且目标值
  match/better 参照值即算成功。这是成功率上界,但判定需要参照值。
- **E2 并集(仅 witness 可行)**:任一链候选通过 witness 可行性即算成功。
  完全不需要真值,但会把"可行但次优"的解也算进成功(口径偏松)。
- **E3 仲裁(本文主推)**:收集两条链中所有 witness 判定可行的候选,
  取**目标值最小**者(min 问题即最优),再对该解判 grade。
  仲裁决策本身只需要 witness(无需真值);最后的 grade 评分才用参照值。
  即:**决策 GT-free,可部署;评分阶段用真值仅为报告数字**。

仲裁规则"可行中取最小目标值"的依据:witness 已经挡掉不可行解,
剩余候选里目标值更优者更可能是真最优(与 MIP 求解的最优性语义一致)。

## 3. 结果

| 规则 | 成功 | 率 | 决策时是否需真值 |
|---|---|---|---|
| 单链 B'' | 103/190 | 54.2% | — |
| 单链 combo | 96/190 | 50.5% | — |
| E1 并集(witness可行+grade) | 132/190 | 69.5% | 需要(评分用) |
| E2 并集(仅 witness 可行) | 136/190 | 71.6% | 不需要 |
| **E3 仲裁(可行中取 min,再判 grade)** | **130/190** | **68.4%** | **决策不需要** |

E3 仲裁选中来源分布:B'' 92 / combo 44 —— 两条链都有实质贡献,
不是一条链的简单支配。

- 相对最佳单链(B'' 54.2%):**+14.2pp**;
- 相对基线(pass@1 6.8%):+61.6pp;
- 相对 ReLoop 同模型最好配置(R2+thinking, 28.4%):+40.0pp。

全景图(含各臂历史数字)见 `figs/ensemble_dualchain_v0.1.png`。

## 4. 讨论

1. **多样性的来源是可解释的设计差异,不是运气。** 两链唯一的系统性差异是
   生成端是否注入 P2 先验(代码惯例 + 建模脚手架)。先验压住了 crash 类失败
   (64%→5%),但偶尔把模型带离本可成功的路径(幻影 84% 持平);无先验链
   则保留了这部分"歪打正着"。两条链在失败谱上正交,这正是集成有效的条件。

2. **witness 是集成的关键基础设施。** 没有 witness 的可行性裁决,best-of-N
   只能退化为"目标值最小"或多数投票——前者会被幻影解(不可行但目标值
   虚低)欺骗,后者在系统性错误下失效(见 motivation 研究:幻影是多数错,
   不是随机错)。witness 把集成从"猜"变成"裁决"。

3. **E2(71.6%)与 E3(68.4%)的 3.2pp 差值** = "可行但次优"的细胞。
   部署场景若接受次优可行解(很多运营场景如此),E2 是可用上界;
   追求最优则用 E3。两者的决策都不需要真值。

4. **成本**:2× 单链的执行成本(LLM 生成是主要耗时,两链可并行,
   墙钟时间不翻倍;CPU/配额翻倍)。68.4% vs 54.2% 的 14.2pp 收益
   对 2× 成本是划算的,且还有空间:N=3(加入第三条生成路径,如
   不同温度/不同 prompt 风格)值得后续验证。

## 5. 局限

- E3 的最终评分(报告 68.4% 这个数字)仍用了参照值;无参照值场景下
  只能报告 E2 口径(71.6% 可行率)。
- 仲裁假设"witness 可行的候选里,min 目标值者最优"。若 witness 漏放
  幻影(当前 witness 残余幻影约 15 例/190),min 规则会优先选中幻影
  (幻影目标值往往虚低)。残余幻影是 E3 的主要风险敞口,
  对应下一步"语义层第 2 代 memory"(族留出协议)要攻的问题。
- 两链架构同源,多样性有限;引入异构生成(如 ReLoop 式 repair loop、
  或不同 base 模型)可能进一步抬升。
