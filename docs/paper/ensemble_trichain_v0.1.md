# 三链集成仲裁 v0.1:80.5%,多样性仍在变现

日期:2026-11-03
脚本:`scripts/ensemble_arb.py`(三链版;纯离线重放,零 LLM 成本)
输出:`runs/m1_presolve/ensemble_dualchain.md`
图:`docs/paper/figs/ensemble_trichain_v0.1.png`
前置:`ensemble_dualchain_v0.1.md`(双链 68.4%)

## 1. 设置

三条链(均已跑完,on 模式,190 题):

- 链 A:无先验生成 + 守卫 v0.3 + 闸门 + witness 环 → 单链 54.2%
- 链 B:代码惯例 v0.2 生成 + 守卫 v0.4 + 闸门 + witness 环 → 单链 50.5%
- 链 C:语义惯例 v0.3 生成 + 守卫 v0.4 + 闸门 + witness 环 → 单链 57.9%

仲裁规则不变:收集三链所有轮次中 witness 判可行的候选,取目标值
最小者,再与参照值判分。**决策不需要真值,可部署**;参照值仅用于报告。
每题只取首次完整轨迹(断连重复记录去重)。

## 2. 结果

| 规则 | 成功 | 率 | 决策需真值 |
|---|---|---|---|
| 最佳单链(链 C) | 110 | 57.9% | — |
| 双链仲裁(A+B,旧) | 130 | 68.4% | 否 |
| **三链仲裁(A+B+C)** | **153** | **80.5%** | **否** |
| 三链并集上界(E1,需真值评分) | 155 | 81.6% | 是 |
| 三链并集(仅 witness 可行,口径偏松) | 161 | 84.7% | 否 |

- 相对最佳单链 **+22.6pp**;相对双链 **+12.1pp**(多样性收益未饱和);
- 仲裁选中来源:链 A 81 次 / 链 B 39 次 / 链 C 41 次 —— 三条链都有
  实质贡献,连单链分数最低的链 B 也贡献了 39 题;
- E3(80.5%)与并集上界 E1(81.6%)只差 1.1pp:min-目标值仲裁规则
  已接近"知道答案再挑"的 Oracle;
- 残余 37 题:三链全部 witness 不可行或无可行候选,其中 witness
  infeasible 硬幻影仍是主体。

## 3. 讨论

1. **多样性变现曲线未饱和**:2→3 链仍 +12.1pp。链间差异全部来自
   生成端注入的记忆不同(无/代码/语义),佐证"记忆多样性 → 失败谱
   正交 → 仲裁变现"这条链路的因果性。
2. **仲裁规则几乎贴住上界**:min-目标值在 witness 过滤后极少选错,
   说明残余风险主要在"三链全都不可行"的题,而非仲裁决策。
3. **成本**:3× 单链执行成本,LLM 生成可并行,墙钟≈单链;
   对部署场景,80.5% vs 57.9% 的差值通常远大于 3× 求解成本。
4. 与自进化的接口:进化产出的新基因组若与现有三链失败谱不同,
   可直接作为第四条链入仲裁;集成是进化成果的零成本放大器。

## 4. 局限

- E2(仅可行)与 E3 的差(4.2pp)是"可行但次优"细胞,追求最优须用 E3;
- witness 残余幻影仍是 min-规则的风险敞口(幻影目标值虚低会被优先选中);
- 三链架构同源,引入异构生成(不同 base 模型/不同修复策略)
  是下一步多样性来源。
