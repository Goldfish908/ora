# IndustryOR 全量管线与旧 z2 对照协议 v0.1

## 分母与基线

- 全部 `data/industryor/IndustryOR.json` 的 **100 题**，不按结果筛题。
- 统一目标匹配：`|objective - en_answer| <= 0.1`，与 COOPA 的绝对误差口径一致。该指标不是完整业务语义正确性证明。
- 旧日志复算：z0=35、z1=60、z2=74；exec_ok 分别 50、93、100，optimal 分别 49、92、99，LLM 调用分别 100、179、115。相对误差 1% 的旧数字 39/67/79 不用于本比较。
- COOPA 公开 IndustryOR 为 76，模型与生成配置不同，不称同条件超越。

## 新运行

使用内网 `Qwen3_8-27B`、z2 工程惯例与 `SCIP_CONTRACT`。每题只生成一次初始候选，不读 `en_answer`、独立参考模型或参考解。

- `temperature=0.6`、`reasoning_effort=medium`、`max_tokens=32768`；
- 每题最多三轮，沿用 z2 的 crash/timeout/infeasible 修复路径；
- 当前 `ProgressController` 处理重复动作、已知 API 错误和证据预算；
- 当前证据 DAG 保存候选快照、动作、父哈希、执行与独立评分；
- 对支持的 19/20/21 使用独立目标＋指示＋整数域资产和确定性窄修复；
- ID 20 的既有 `R/C/B/D` 分别对应四种产品，`y/z` 对应前两种产品。已注册映射只把这些名称适配到审计的 `x1..x4/y1..y4`，补充缺失的后两个二元指示变量和双向链接，不全局整数化、不改写其他业务约束。映射只覆盖已核对的变量形态，其他形态保留为失败或交给 LLM 修复；
- 对 4/8/9/19/20/21/25/48 做当前变量级业务审计，其中 48 的审计边界保持 blocked；
- 无完整业务 auditor 的题标记 `business_unverified`，不把 objective match 当作业务接受；其 crash、timeout、infeasible、无输出或导出失败仍走执行修复，而不是因不可审计直接放弃；
- 无已注册窄修复时，控制器可退回 LLM 重生成。无完整业务 checker 时不声称 Witness 接受；原本业务正确的解通过真实根快照回滚保留。

## 验证与比较

分别报告：全集执行率、optimal 数、目标匹配数（abs≤0.1）、独立业务审计子集结果、错误接受、 harmed-win、回滚、LLM 调用、tokens、延迟与 SCIP 次数。

与旧 z2 使用同一目标误差规则，不混用相对误差、不同分母或论文的相对指标。差分始终限于本次实际运行的相同 ID；只有全集结果与 z2 的 74/100 直接相减。基座模型名称相同，但旧离线 revision 与新内网服务 revision 未形成严格同一性证明，因此不把差值全部归因于 Witness/DAG。

所有初始 prompt、原始响应、代码、执行 stdout/stderr、动作、每轮评分与成本均落盘。每次 LLM 调用的 messages、返回内容、usage、模型名、真实延迟与每次网络重试都保存；缓存恢复不冒充新调用。执行缓存按原始代码和插桩代码双重哈希核对，分别报告候选评估次数和实际 SCIP 调用次数。

失败、UNKNOWN、不可审计和负结果不删除。服务或环境故障不得被标为业务正确。保存全集 manifest、逐题 z2 目标差分及失败分类。最终运行完整 pytest 与 `m2gen` 回归。四题冒烟只用于工程验证，不是性能或跨族结论；其中早期缓存缺少重试元数据时应明确标记，不能混入全量重试率。
