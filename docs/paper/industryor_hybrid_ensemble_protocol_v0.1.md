# IndustryOR 三次混合选择来源多数表决协议 v0.1

## 冻结规则与验证边界

输入仍是冻结的 structured full-memory 与 raw k=3 selected 候选。每个输入先遵循 `industryor_hybrid_protocol_v0.1.md`：独立业务接受优先、同目标保留 full、执行完整性确定性裁决，其余使用 LLM max-min。对每道题获得三次独立选择后，按来源进行多数表决：至少两票 `raw_selected` 才选择 raw，否则选择 full。三票不存在平局；聚合不读取目标值，不使用参考答案或候选池 oracle。

开发阶段使用既有三次选择（77、76、78）形成多数表决。最终复验必须在协议写定后，另外执行三次全新选择采样，再按同一规则聚合；不得挑选最好的一次或用开发轮次替代复验轮次。

## 预算与成本

每次选择沿用 temperature=0.2、reasoning_effort=medium、max_tokens=16384。当前冻结输入中，每轮最多 18 次 LLM 调用，因此一个三票集成最多 54 次新增选择调用；确定性同目标、独立业务接受和执行恢复不额外调用。聚合本身不调用 LLM。分别报告每一轮结果和集成结果，以及三轮总成本。

## 结论限制

复验只覆盖选择阶段，冻结 formulation、初始代码和 repair 输出，不等于完整生成管线的新采样复现。所有数据均为 IndustryOR 开发采样，不是 held-out。报告公开目标匹配、相对 full 的增益/损失、8 题独立业务审计、误接受、来源、逐题投票和成本；不把 COOPA-inspired 实现称为官方实现，不宣称未经进一步验证的 SOTA。
