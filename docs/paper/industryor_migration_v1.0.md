# IndustryOR 零适配迁移实验 v1.0(阶段 C)

日期:2026-11-04(跑批完成,结果回填)。

## 1. 动机

RetailOpt 上的全部语义资产(witness 18 条族规则、P3 语义 memory)都是
**数据集内蒸馏**的——换数据集即清零。本实验回答一个工程与科研双重问题:

> **witness 空白期,系统还剩什么?**

工程侧:验证 harness 的"机械层"(崩溃修复环)与"工程先验"(PySCIPOpt
API 知识)有多少是数据集无关、开箱即迁移的。
科研侧:无语义审计时,系统的错误谱长什么样——为"checker 冷启动"
(Open-Jev 判官 / checker-authoring)提供需求实测。

## 2. 数据

- IndustryOR-100(HF `CardinalOperations/IndustryOR`,CC-BY-NC-4.0
  非商用研究许可;本仓 `data/industryor/IndustryOR.json`,gitignore 不入仓,
  获取与完整性:`scripts/fetch_industryor.sh`,sha256
  `5b889e49…5f36`);
- 字段:`id`(1–100)、`en_question`(纯自然语言,**无内嵌数据契约、
  无 data.json**——数据在题面文本里)、`en_answer`(全部可解析为数值
  最优值)、`difficulty`(Easy 39 / Medium 41 / Hard 20);
- 已发表基线(IndustryOR 列):GPT-4 标准 28.0%、ORLM-LLaMA-3-8B 38.0%。
- 官方执行口径:COPT,600s/题;我们:PySCIPOpt,求解限时 570s、
  执行超时 620s(与 RetailOpt 全线一致)。

## 3. 三臂设计(零适配的精确定义)

| 臂 | 生成端 | 环(≤3 轮) | witness | 含义 |
|---|---|---|---|---|
| **Z0** | 裸 NL+SCIP 契约,单发 | 无 | 无 | 地板 |
| **Z1** | 同 Z0 | crash/timeout/infeasible 反馈修复 | 无 | "day-1 系统":只有机械层 |
| **Z2** | Z1 + 工程先验 | 同 Z1 | 无 | +数据集无关的工程知识迁移 |

- 三臂均 thinking on、温度 0.6、max_tokens 32768(与 RetailOpt 主线同配置)。
- **不迁移**:witness 18 规则(RetailOpt 族定制)、P3 语义 memory(7 条
  RetailOpt 语义惯例)、预求解闸门(F13/F14 为 RetailOpt 模式)。
- Z2 先验 = `evo/genomes/g0_seed/code.txt`(G1–G9 PySCIPOpt 工程陷阱 +
  建模程序),**唯一改写**:第 1 条中 data.json 相关两句中性替换为
  "All data appears in the problem text below; transcribe it into Python
  literals at the top of your script."(IndustryOR 无 data.json 基建,
  原句会注入假契约;改写只删环境引用,不引入任何 RetailOpt 语义)。
- 修复环诚实性:环内反馈**只用**执行/求解器信号(crash、timeout、
  declared_infeasible、无目标值),**绝不**用 en_answer——真值只出现在
  事后评分。环在"出解打印目标值"即停,正确性环内不可知。

## 4. 评分口径

- **可执行率**:returncode 0 且打印 objective;
- **Acc@1e-4 / 1e-3 / 1e-2**:|obj − ref| / |ref| ≤ 容差(与 ReLoop 对照
  口径对齐;RetailOpt 主表用 1e-3);
- 难度分层(Easy/Medium/Hard);
- **冷启动幻影代理**:出解且打印目标值、但目标值与 en_answer 不匹配的
  细胞——无语义审计时这就是"看不见的火",只能靠真值事后点亮。
  (注:目标值匹配但语义错误的幻影在此口径下**不可见**,是已知的
  测量下限;RetailOpt 上此类占幻影的 ~4%,见 reloop_qwen27b §4。)

## 5. 预注册式预测(跑批前写死)

1. Z2 相对 Z1 的 crash 率显著下降(RetailOpt 上工程先验把 crash
   64%→7%;若 IndustryOR 上无此效应,说明先验过拟合了 RetailOpt 的
   崩溃台账而非通用工程知识);
2. Z1/Z2 的"出解但目标值不匹配"占比将显著高于 RetailOpt 有 witness
   臂的同类残余(语义防线空白的直接度量);
3. 总 Acc@1e-2 若接近或超过 GPT-4 的 28.0% 已发表基线,说明
   harness 机械层 + Qwen3.8-27B 在新数据集上即战力可观;准确率天花板
   则受限于无语义审计。

## 6. 运行与产物

- 脚本:`scripts/m3_industryor.py`(--arm z0/z1/z2 --shard k/K,
  断点续跑按 (id, arm) 去重);
- 输出:`runs/industryor/m3_<arm>_s<k>.jsonl` + sandbox;
- 分析:`scripts/m3_industryor_analyze.py`(三臂 × 难度 × 口径表,
  幻影代理统计);
- 结果回填本文档 §7。

## 7. 结果

三臂全量各 100 题跑批完成(内网 Qwen3.8-27B,总耗时约 26 分钟)。
分析器:`scripts/m3_industryor_analyze.py`;原始台账 `runs/industryor/m3_*.jsonl`。

### 7.1 主表(最后一轮口径)

| 臂 | n | 可执行 | Acc@1e-4 | Acc@1e-3 | Acc@1e-2 | 冷启动幻影代理(占出解) |
|---|---|---|---|---|---|---|
| Z0 裸模型 | 100 | 49.0% | 36.0% | 37.0% | 39.0% | 12/49 = 24.5% |
| Z1 +机械修复环 | 100 | 92.0% | 62.0% | 64.0% | 67.0% | 28/92 = 30.4% |
| Z2 +工程先验 | 100 | **99.0%** | 75.0% | **78.0%** | **79.0%** | 21/99 = 21.2% |

参照:已发表基线(同数据集,官方 COPT 口径)GPT-4 标准提示 28.0%、
ORLM-LLaMA-3-8B 38.0%。我们的裸臂 Z0(37.0%@1e-3)已与微调 8B 模型
持平,Z2(78.0%)则远超——**注意口径差异**:基线用 COPT+600s,我们用
PySCIPOpt+570s;数值容差对齐(1e-3),但不排除题目级实现差异,此对照
只宜作量级参考,不作严格排名。

### 7.2 难度分层(Acc@1e-3)

| 臂 | Easy (39) | Medium (41) | Hard (20) |
|---|---|---|---|
| Z0 | 38.5% | 34.1% | 40.0% |
| Z1 | 64.1% | 56.1% | 80.0% |
| Z2 | 82.1% | 63.4% | **100.0%** |

Hard(20/20)反超 Easy 是意外发现:IndustryOR 的 Hard 多为结构复杂但
表述规范的 LP/MIP(多阶段、多资源),恰是工程先验帮得上的类型;而部分
Easy 题题面口语化、有歧义陷阱。Hard 样本仅 20 题,此分层结论待更大样本
确认,但"难度标签 ≠ 对 LLM 的难度"这一现象本身值得记录。

### 7.3 崩溃分类与工程先验的迁移性

Z0 全部 50 个崩溃的归因(终值):

| 类别 | 次数 |
|---|---|
| `setObjective` 的 sense 字符串不被识别 | 19 |
| `addVar()` 关键字误用(如 `v=`) | 9 |
| 把 pyscipopt 变量/表达式对象当数值用 | 9 |
| `quicksum` 误当作 Model 方法 | 5 |
| 其它目标函数 API 误用 | 5 |
| SyntaxError / SCIP 状态异常等 | 3 |

**全部是求解器 API 知识错误,与题面语义无关**——这正是 G0 工程先验
覆盖的内容。直接度量:**首轮崩溃率 Z1 = 56/100 vs Z2 = 9/100**
(RetailOpt 上同一对照是 64%→7%,效应量几乎一致)。轮次分布:
Z1 有 58 题需要 ≥2 轮修复,Z2 仅 13 题。

### 7.4 冷启动幻影(witness 空白期的语义防线实测)

- 三臂幻影代理占出解的比例:Z0 24.5%、Z1 30.4%、Z2 21.2%——
  **没有任何一臂有机制能在线发现它们**,只能靠真值事后点亮;
- 注意 Z1 的绝对幻影数(28)高于 Z0(12):修复环把"崩掉"救成"出解",
  其中一部分救出来的是错模型——**机械层提升可执行率的同时,
  按绝对数量增加了幻影**。这是"出解即停"环路的固有性质:
  环内正确性不可知;
- 对照 RetailOpt 有 witness 臂:真错误检出 3/4(on),幻影存活率被压到
  ~0。IndustryOR 的 21–30% 幻影占比 = 语义防线空白的直接度量;
- 此口径是**下界**:目标值碰巧匹配的语义错误(RetailOpt 上约占幻影
  4%)在此不可见。

**定性案例(id=15,Medium,工具维修规划)**:参考解 168,模型解 431
(虚高 156%)。模型给每个阶段都强加 `s[j]+f[j]==r[j]`(用后必修),
包括最后一次使用之后——末期工具的维修费纯浪费,正确模型应允许弃置。
代码机械完好(一次跑通、目标值正常打印),错误在建模语义;现行修复环
与 Z2 工程先验都无权也无力发现它。这正是"checker 冷启动"要解决
的问题形态。

### 7.5 预注册预测裁决

1. **"Z2 相对 Z1 crash 率显著下降"——成立。** 首轮崩溃 56%→9%,
   与 RetailOpt 的 64%→7% 效应量几乎一致 → 工程先验是**数据集无关的
   通用工程知识**,非 RetailOpt 崩溃台账的过拟合;
2. **"Z1/Z2 幻影占比显著高于有 witness 臂"——成立。** 21–30% 的
   出解是幻影代理(下界),无任何在线机制可发现;RetailOpt 有 witness
   臂幻影存活 ~0 → witness 空白期的语义防线**确实不存在**,checker
   冷启动(Open-Jev 判官 / checker-authoring)有实测需求支撑;
3. **"Acc@1e-2 接近或超过 GPT-4 基线 28.0%"——成立且远超预期。**
   裸臂 Z0 已 39%,Z2 达 79% → harness 机械层 + Qwen3.8-27B 在新
   数据集即战力很强;但注意 Z2 仍有 21% 题"出解但错"——准确率天花板
   确实受限于无语义审计,与预测方向一致。

### 7.6 与 RetailOpt 结论的对照

| 维度 | RetailOpt-190 | IndustryOR-100(本文) |
|---|---|---|
| 裸模型正确率 | 6.8%(witness 重判口径) | 37.0%(Acc@1e-3) |
| 首轮崩溃率 | 64% | 56%(Z1)/ 9%(Z2) |
| 工程先验效应 | 64%→7% | 56%→9% |
| witness 空白幻影 | (未测,直接上了 witness) | 21–30% 出解为幻影代理 |
| 数据契约 | 题面+data.json 双层 | 纯题面文本 |

差异解读:RetailOpt 裸正确率低得多,主因是其隐藏数据契约(data.json)
与语义陷阱设计;IndustryOR 题面自包含、数值直白,瓶颈转移到 API 工程
与建模语义。两个数据集的共性结论:**崩溃层可被数据集无关的工程先验
解决,语义层不能**——后者必须靠 witness 类资产(蒸馏/判官/作者化)
补齐,而这类资产目前是数据集内定制的,跨数据集需要冷启动方案。

### 7.7 局限

- 数值容差口径:目标值匹配 ≠ 语义正确(下界,见 §7.4);
- Hard 分层 n=20,分层结论不稳定;
- 与已发表基线的对照存在求解器/模型代差,只作量级参考;
- Z2 的 21 个幻影代理尚未逐题归因(计划归入 checker 冷启动实验的
  评估集——它们正是判官需要学会抓的错误类型)。
