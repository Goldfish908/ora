# 分层业务世界模型:一个面向 LLM 运筹建模的叙述框架

版本 v0.1 · 2026-11-06 · 状态:故事框架定稿中,部分证据在测(判官跨域迁移)

---

## 0. 一句话主张

> LLM 做运筹建模失败的根本原因不是"不会写代码",而是**它没有业务世界模型**——不知道"期初库存不能凭空出现"这类业务物理。现有方法用执行信号或语义对齐做代理,结构性看不见由此产生的系统性错误。我们的做法是给 LLM 外挂一个**分层的、可生长的业务世界模型**:公理打底、直觉扩展、经验沉淀、失败驱动生长。

---

## 1. 问题根源:缺失的世界模型

### 1.1 什么是"业务世界模型"

借用世界模型(world model)的定义:一个能够预测"**在什么状态下、采取什么动作、会导致什么后果**"的内部模型。对运筹建模而言,它至少包含:

- **业务物理**:库存守恒、最小起订量、保质期、资金/人力容量的硬边界——什么是不可能的;
- **业务惯例**:安全库存的取值习惯、服务水平与成本的权衡结构——什么是不合理的;
- **推演能力**:给定决策,预测库存流、资金流、履约率的演化——做了会怎样。

### 1.2 LLM 的症状:规约博弈(specification gaming)

我们数据集 RetailOpt-190 上的实测证据(幻影漏斗):

```
190 题
 └─ 69 跑通(语法/求解层面成功)
     └─ 61 "看似合理"(跑通 + 目标值对得上参考解容差)
         ├─ 46 幻影 ← 目标值对,但解违反业务物理
         └─ 15 过审
             └─ 13 真成功
```

传统评测口径(跑通+目标值)会把成绩**高估 4.7 倍**(61/13)。

幻影不是随机失误:全部幻影共享同一机制——**幻影初始库存**。题面欠规约(未声明"期初库存为零"),模型系统性地借入不存在的库存去降低订货成本,目标值系统性虚低 7%–45%。这是被优化压力**筛选**出来的行为:模型在"要跑通、要目标值好看"的压力下,恰好占据规约留下的自由度。这正是 AI 安全文献中 specification gaming 在运筹建模域的实例化。

### 1.3 为什么现有方法结构性看不见

| 方法 | 代理信号 | 盲区 |
|---|---|---|
| ReLoop 式修复环 | 求解行为是否合理(可执行、状态正常) | 幻影**跑得很正常**——执行信号全绿 |
| SAC-Opt 式语义对齐 | 建模与题面的语义一致性 | 幻影**忠实于题面**——题面本来就没说期初库存 |
| 结果奖励 RL | 目标值/求解状态 | 幻影**目标值更好**——奖励会强化它 |

三条路线的共同盲区:它们审计的对象都是"题面 ↔ 模型 ↔ 求解行为"这个闭环**内部**的一致性,而幻影的错误在闭环**外部**——它违反了题面没写、但业务上必然成立的物理。**要抓住它,必须有一个与求解行为无关、独立于题面文本的知识源——即业务世界模型。**

## 2. 分层架构

我们把业务世界模型拆成四层,加一个生长机制。每一层回答一个不同的问题,有不同的认识论地位(确定性 vs 学习性)、成本结构和失效模式。

```
                    ┌─────────────────────────────────────┐
                    │ L4 生长层:失败驱动的世界模型进化       │
                    │  (台账→条款/卡片/规则/训练数据)        │
                    └──────────▲──────────────────────────┘
                               │ 沉淀                │ 蒸馏
        ┌──────────────────────┴──────────────────────────┐
        │ L3 经验层:memory(惯例条款/闸门规则书/修复卡片)    │ ← 跨题积累,"这类题通常有什么坑"
        ├──────────────────────────────────────────────────┤
        │ L2 直觉层:判官(参数化,LoRA)                     │ ← 跨域搬运,"这看起来不对劲"
        ├──────────────────────────────────────────────────┤
        │ L1 公理层:witness(确定性规则,18条)              │ ← 终审,"这在业务上不可能"
        ├──────────────────────────────────────────────────┤
        │ L0 推演层:求解器(SCIP/HiGHS)                    │ ← 精确模拟,"这个模型算出什麼"
        └──────────────────────────────────────────────────┘
                               ▲
                    LLM 建模器(被装备者)
```

### L0 推演层:求解器 = 受控模拟器

- **角色**:前向模拟。给定模型+数据,精确算出决策后果(目标值、解结构)。
- **认识论地位**:数学上精确,但它推演的是 **LLM 写的模型**,不是真实业务。模型写错了,solver 会精确地算出错误世界的最优解——幻影就是"错误世界里的最优解"。
- **失效模式**:对建模错误完全透明(transparent),这正是为什么"solver 跑通"不能作为正确性证据。

### L1 公理层:witness = 业务物理的显式编码

- **角色**:终审法官。零成本(Python 规则)、零延迟、100% 可复现。
- **输入**:实例数据(需求/成本/MOQ…)+ 解的数字(solution.json)。**不看题面、不看模型代码、不看目标值是否合理**——只看数字是否满足业务物理。
- **输出**:违例清单(哪条规则、哪个变量、哪个数值)。
- **为什么必须在求解后**:规则检查的是**解的属性**(如期初库存非零),求解前这个属性不存在。检查点无法前移——这不是设计选择,是认识论必然:你只能在"后果"上验证"物理"。
- **为什么不被学习替代**:幻影是被优化压力筛选出的对抗样本,天然落在学习型判官的盲区(实测:裸 Qwen27B 判官幻影误放行 45.3%,Open-Jev-27B 误放行 99.6%)。确定性规则不看"合理性",只看"物理",因此免疫。
- **失效模式**:规则按族定制,换域即失效——这是它唯一的、但致命的弱点,也正是 L2 存在的理由。
- **定位**:终审权**永不下放**。任何学习型组件只能初筛,不能终审。

### L2 直觉层:判官 = 业务物理的参数化近似

- **角色**:冷启动期的实习生 + 跨域搬运工。在 witness 规则尚未建立的域(新问题族、新数据集)顶班,做**初筛/分流**(fail-open:高置信才拦截,拿不准放行)。
- **训练**:LoRA(0.43% 参数),868 条样本,标签来自 witness 判定 ∪ 参考解比对 + 构造保证的变异细胞。**判官是 witness 的蒸馏物**——没有 L1 就没有 L2 的训练信号。
- **当前状态**:v3 训练中,dev70 AUC 0.682 → 0.808(epoch3 进行中)。分布外迁移(F5–F8 留出族、IndustryOR 异构数据集)待终测。
- **失效模式(实测)**:未经域内训练的判官在幻影上系统性失效(见 L1)。判官能力**不能白拿**,必须用目标域标签训出来。
- **与 L1 的关系**:不是竞争者,是**孵化器**。判官的高置信判定积累成弱标签,喂养 checker-authoring(规则自动生成);规则长出来后判官退休——**自我消除式设计**。

### L3 经验层:memory = 跨题沉淀的惯例知识

- **角色**:LLM 的"执业经验"。三类载体,各有独立的进化史:
  - **惯例条款**(G0–G8,求解前注入):从 263 条真实崩溃台账蒸馏,崩溃率 64%→7%;
  - **闸门规则书**(求解前 verifier 的规则库):四代进化,历史崩溃检出率 73.8%→91.6%→93.9%→97.0%,期间经历过 G2 数据流教训(修复时引入新 bug)、G6 误报收窄教训(规则太宽误杀合法解);
  - **修复卡片**(RECOGNIZE/ROOT CAUSE/FIX 三段式):修复成功率 50.3%→90.5%。
- **性质**:符号化、非参数、事件驱动(不是每题更新,是失败积累到阈值才蒸馏)。
- **与深度学习的类比**:这是**非参数的持续学习**——不碰权重,但知识在增长。其教训是双向的:进化可以提高检出,也会引入过拟合和误杀,因此需要留出族(gapcheck60/F5–F8)做"零接触"验证。

### L4 生长层:失败驱动的世界模型进化

- **核心循环**:
  ```
  求解失败 → witness 判定定位 → 失败台账
       → 条款蒸馏(L3)         [已验证,跨题有效]
       → 规则书修订(L3 闸门)   [已验证,四代]
       → 修复卡片(L3)         [已验证]
       → 判官训练数据(L2)     [进行中]
       → checker-authoring(L1 规则自动生成) [规划中]
  ```
- **这是"世界模型"区别于"过滤器集合"的关键**:系统不只是用知识,而是**生产知识**。每一次失败都(潜在地)转化为一条新的业务物理。
- 与 RSI(递归自我改进)的关系:当前进化对象是"知识"(条款/规则/卡片/判官),元进化(改进进化过程本身)是后续开放方向。

## 3. 这个故事的三个可证伪预测

好故事必须能错。以下预测若被证伪,框架需要修正:

1. **跨域迁移**:若判官在 F5–F8/IndustryOR 上保持远超零样本基线的判别力 → 它学到了某种可迁移的"业务物理直觉";若崩塌 → 它只记住了 RetailOpt 的规则模板,分层故事退化为"单域规则蒸馏"。**(在测)**
2. **容量下界**:27B→9B→4B 消融。若 4B 也能达到可用判别力 → "业务物理直觉"是低容量能力;若崩塌 → 语义审计存在容量门槛。**(排队中)**
3. **checker-authoring 闭环**:判官弱标签喂养的规则自动生成,若在留出族上达到接近人工盲写规则的检出/误报水平 → 世界模型的公理层可以自动生长,框架闭合。**(未开始)**

## 4. 与相关文献的关系(诚实边界)

- **世界模型文献**(Ha & Schmidhuber 及后续):经典世界模型是**前向预测**的状态转移模型。我们目前**没有**前向预测组件——L0 solver 推演的是人工(LLM)写的模型,不是学到的业务动态。因此严格说我们构造的是"**审计式世界模型**"(auditor's world model):不预测世界如何演化,但知道什么样的世界状态是不可能的。
- **自然的下一步**:把判官的训练目标从 verdict(对错)换成 consequence prediction(给定决策预测库存/资金轨迹),即从"审计"走向"模拟"。这是比判官更大的故事,当前不声称。
- **specification gaming / reward hacking 文献**:幻影是该现象在运筹建模域的实证实例,我们的贡献是展示了它在此域的系统性(共享单一机制、目标值系统性偏移)与可检测条件(需要独立于求解行为的知识源)。
