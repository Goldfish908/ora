# Memory→Witness sealed 执行协议 v0.1

日期：2026-11-11 · 状态：先于 sealed 内容访问冻结

## 1. 不可变更项

- sealed 仅用于一次性终验，不用于提议、反例、选择、调参、提示词修订或阈值修订。
- MAMO 使用已冻结的 101 个 sealed ID；NLP4LP 使用已冻结的 120 个 sealed ID。不得先运行子集再决定后续策略。
- Qwen3.8-27B、PySCIPOpt、既有最大轮数与求解预算不变。
- dev/validation 的 memory、作者提示词、guard/witness 代码、评分脚本在 sealed 前记录 SHA256。
- 198 这类重放失败候选不得直接部署；sealed 中的失败候选同样记录并拒绝，不事后删除其失败证据。

## 2. MAMO 四臂

1. **A0 无先验**：z1 执行修复，无 memory、无语义 witness。
2. **A1 仅软 memory**：z2 工程经验 + 已冻结的可数单位软规则，无硬 guard。
3. **A2 直接迁移旧 witness**：z2 + RetailOpt witness，真实记录 schema 不兼容和 fail-open。
4. **A4 完整冷启动**：固定基线代码 + dev/validation 冻结 memory 作者 + 确定性 guard 重放。

A4 的作者器可以读取 sealed 题面和生成代码，但**不能读取 sealed 参考答案、独立反例或任何候选评分**。sealed 中不运行整数反例晋升；该机制只在 dev/validation 已验证。每个新候选记录来源、证据、脚本哈希和是否实际激活。

固定代码重放用于区分 guard 的因果贡献；独立在线生成只用于报告端到端表现，不把两次采样差异归因于 guard。

## 3. 参考与评分

- 原始 MAMO 榜分：公开答案绝对误差≤0.1，仅用于复现原榜单口径。
- 独立 TSP 审计分：`mamo_tsp_audit.py` 穷举全部循环，仅用于评分，不用于规则选择或修复。
- 两种分数并列报告，不把审计分用于 COOPA 原始排名。
- 记录改善、退化、未解决、guard 激活、UNKNOWN、LLM 调用、延迟、token 和求解执行成本。
- A4 相对 A1 的逐题正确率使用 McNemar 配对检验；`p<0.05` 且误报/误伤不超过 10% 才允许宣称消融有效并启动 SOTA 对比。

## 4. NLP4LP 后续终验

- sealed 参考一致性审查必须先于候选检查生成，不得按候选结果选择排除项。
- 使用冻结的 dev memory 生成检查，max_repairs=0，不写回 memory。
- 固定制品审计与端到端修复分开；报告错误检出、干净误报、UNKNOWN、成本和配对检验。
- 原始标签与独立裁决后的结果同时报告，主结论不得只选择有利口径。

## 5. 负结果与停止规则

若 A4 未达到有效线，不移动球门、不继续增加数据集、不启动 SOTA 对比。按候选提出、参考标签、规则覆盖、判决纪律、修复反馈和跨域资产迁移分层归因后结题。
