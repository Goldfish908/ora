# Motivation 验证发现 v0.1(27B 先导，2026-10-30;F2 节 v0.2 更新于 2026-10-31)

数据来源：内网 Qwen3_8-27B 单模型。M1 = RetailOpt-190 先导（4 个 F1 实例 × on/off);M2 = 受控集先导（base:4 结构 × 2 实例 × on/off × 4 采样；翻转对 v5:storage_time/hold_time/setup_link 6 实例 × 8 采样、activation_link 2 实例 × 8 采样，witness 程序归因）。翻转对已到每格 48 样本；其余仍为小样本先导，供机制判断。

## F1（发现编号，非数据集族）誊抄错误是大头失败模式 → 测量必须剥离

M1 prompt_full 模式（数据内嵌题面）:on 模式 4/4 全部死于数据誊抄（把内嵌 JSON 抄成 Python 语法，`json.loads` 即炸）。切换到 prompt_schema 模式（数据预加载为变量，物理上不可能誊抄）后 crash 率从 7/8 降到 3/8。
**含义**:M1 主测量必须用 schema 模式，否则测的是抄写不是建模。题面长度本身（13.8k 字符）不是瓶颈，内嵌数据才是。

## F2 假成功普遍且必须程序审计：witness 重判后 F1 实例真实正确率 0/4(v0.2 更新）

schema 模式下能跑通的产出全部 `better_than_reference`（比已证最优解好 1.6%–45%)，即有效产出全部是漏约束的假成功。**只比对目标值会把这些全部误判为正确**。

**v0.2(2026-10-31):f1 族 witness 检查器建成并完成首测**。`m1_witness/f1.py` 重算 11 条硬规则（初始库存/新鲜流入/库龄/损耗/可售/需求平衡/产能/库容/替代边/非负/目标值重算）,C-FIFO 因 r≥2 桶间持有成本相同降级为 warning。自检：4 个参照解阳性对照全过（目标值与数据集参照相对差 ~5e-7),8 个单规则变异体阴性对照全 HIT。pilot 换 `--prompt-mode schema_sol`（模型须 dump solution.json）重跑 4 实例 × on/off:

- **4/4 可执行产出 witness 全部判 infeasible**——目标值通道的"假成功"在 witness 下无一漏网，F2 结论从"目标值可疑"升级为"违规已定位";
- **违规机制高度一致：全部 4 例含 C-INIT（幻影初始库存）**。模型给 t=1 的非新鲜桶凭空填入库存（如 `I[SKU_Basic,DC1,1,9]=892.25`)，免费现货替代采购 → 目标值低 7%–45%。根因是题面欠规约：KEY EQUATIONS (1)(2) 未定义 t=1 时 r<SL 的桶，题面也无"期初库存为零"字样，数据集参照语义（已用参照解交叉验证）假设为零。**模型不是随机犯错，而是系统性地占据规约留下的自由度**——这比"随机漏约束"更难靠 prompt 修补，是 witness 检查器必须独立存在的核心论据（同时印证 F3：欠规约是系统性伪影，但此处伪影在*数据集题面*一侧，属于测量对象的固有难度而非我们装置的缺陷）;
- 附带观察：on 模式 3/4 crash 于 PySCIPOpt `setObjective` API 误用（长推理产出的代码更长更"自创"API);off 1 例 crash 于没按契约读 `data.json`（自己编了 `scenario.json`)。

M1 测量标配 schema_sol 模式 + 按族 witness 检查器（替代纯目标值比对与 §8.2 的 LLM 归因标注器：更便宜、可复现、无自我偏好）。

## F3 题面欠规约是系统性测量伪影

M2 inv_cap 第一轮 16/16 crash，主因不是语义错误：`prod_cost` 对标量/逐期列表双形态，题面未写明，模型默认标量。题面补全数据形态说明后 inv_cap base 变 16/16 全对。**受控集题面必须数据形态完备，否则测到的是"猜数据结构"。**

**v0.2 补充（m2gen v2 新结构首扫）**：同一伪影的第二形态——`demand`/`cost` 等以名称为键的 JSON 对象，题面未写明形态时模型默认按下标数组读（`demand[0]` → `KeyError: 0`),m2gen v2 首轮 128 次调用中 50 次 crash 有 49 次是这一种（atom_map off 模式 14/16 crash)。对照组证据：atom_lag 的参数恰好真是 0 起始数组，32/32 全过零 crash。题面补"JSON 形态"段落后重扫（v2)。**受控集题面规范加一条：所有参数写明键/数组形态。**

## F5 翻转对一致率：先验覆盖真实存在且先验强度调制，但"on 更容易覆盖"在扩量后**不成立**(v5,6 实例 × 8 采样）

v4(2 实例 × 4 采样）曾显示 storage_time 上 off 7/8 跟随 vs on 3/8;v5 扩量到 storage_time/hold_time/setup_link 各 6 实例 × 8 采样（每格 48 样本，activation_link 2 实例）后，该对比**反转**。检测全部数值化（solution.json 标志位/目标值与双参照比对；代码正则会在注释上误报——见 F7):

| 翻转对 | 算子 | off 跟随 | on 跟随 | 忽略（off/on) |
|---|---|---|---|---|
| storage_time(inv_cap) | C4 | 29/48(60%) | 32/48(67%) | **17 / 10** |
| hold_time(setup_charge) | C4 | 40/48(83%) | 40/48(83%) | 1 / 0 |
| setup_link(setup_charge) | C3 | 36/48(75%) | **44/48(92%)** | 3 / 0 |
| activation_link(assign_fixed) | C3 | 1/16(14 crash) | 7/16(9 crash) | 1 / 0 |
| hub_conservation(flow_dir) | C2 | —（退化，见 F7) | — | — |

**修订后的结论（两条）**:
1. **先验覆盖真实存在，且由先验强度调制**——此结论在扩量后成立：忽略几乎只发生在 storage_time（忽略率 off 35% / on 21%)，其余连接 ≤6%。"期末库存 ≥ 需求×覆盖期"是教科书强典范；hold_time（目标项时间索引）等非典范位置两模式都照数据做。实例间有异质性：s200 参数组忽略率（off 14/32）高于 s0 组（3/16)，先验覆盖还受实例参数调制。
2. **"thinking 加剧先验覆盖"不成立**——on 模式在全部四个可测翻转上跟随率 ≥ off(setup_link 高 17pp,activation_link 在可运行样本中 7/16 vs 1/16)。v4 的反向信号是小样本噪声。对论文故事的影响：现象（先验覆盖）保住，但"thinking 有害"的归因拿掉；on 模式的收益渠道（更少 crash、更准的连接语义）反而在翻转任务上可见。

## F7 翻转对设计的两个坑（已进生成器自检）

1. **退化翻转**:flow_dir 的"守恒→允许滞留"翻转，翻转参照目标值与 base 完全相同（最小化下松弛永不占优）——该翻转无区分度，测量中剔除。m2gen 已加自动检查：翻转参照目标值必须 ≠ base，否则 labels 里标 `discriminating: false`（当前仅 hub_conservation 被标）。C2 方向的翻转需要重新设计（如改为"流向反向"而非"加松弛")。
2. **检测必须数值化**:代码正则（`>=`、`y[w]==1`）会在模型抄进注释的题面文字上误报。数值通道（solution.json 标志位、目标值 vs 双参照）免疫此问题，但对 hub 这类退化翻转数值通道本身失效——两个通道各有盲区，设计翻转时两者都要可检。

## F6 次要观察

- off 模式跟翻时 1 例 crash 正是经典的 `t+1` 越界（忘了末期 clamp)——连接语义改变引发的连锁代码错误，可归因 C4。
- setup_charge off 有 1 例 W1（库存平衡）违规但目标值恰好 match——目标值比对漏检语义错误的直接证据。
- 内网端点速度：M2 单样本 ~10s,M1 schema 单次 40–180s；全部 pilot 在 CPU+API 下完成，零 GPU。

## 对 motivation v0.2 的修订建议

1. M1 测量标配 schema 模式 + 按族 witness 检查器（替代 LLM 归因）;
2. 翻转对已扩量（F5 v5)：核心保留结论是"先验覆盖存在且先验强度调制",**不再声称 on/off 不对称**;P4 主证据应建立在 storage_time 类强先验连接上，并报告实例参数异质性；
3. 错误四桶细化：誊抄（F1）与题面欠规约（F3）单列为测量装置问题，不进模型的错误分布；
4. assign_fixed 的 crash 构成需在 8B 模型上重测（代码错误率预计更高，需决定 crash 是否计入语义失败分母——建议分开报告）。
