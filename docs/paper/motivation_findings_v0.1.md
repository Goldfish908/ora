# Motivation 验证发现 v0.1（27B 先导，2026-10-30)

数据来源：内网 Qwen3_8-27B 单模型。M1 = RetailOpt-190 先导（4 个 F1 实例 × on/off);M2 = 受控集先导（4 结构 × 2 实例 × on/off × 4 采样，witness 程序归因）。**全部为小样本先导，供机制判断，不作统计结论。**

## F1（发现编号，非数据集族）誊抄错误是大头失败模式 → 测量必须剥离

M1 prompt_full 模式（数据内嵌题面）:on 模式 4/4 全部死于数据誊抄（把内嵌 JSON 抄成 Python 语法，`json.loads` 即炸）。切换到 prompt_schema 模式（数据预加载为变量，物理上不可能誊抄）后 crash 率从 7/8 降到 3/8。
**含义**:M1 主测量必须用 schema 模式，否则测的是抄写不是建模。题面长度本身（13.8k 字符）不是瓶颈，内嵌数据才是。

## F2 假成功普遍且必须程序审计：F1 实例真实正确率 0/8

schema 模式下 5 个能跑通的产出全部 `better_than_reference`（比已证最优解好 1.6%–29%)，即 4/4 有效产出全部是漏约束的假成功。抽查 f1_base(on)：库存平衡/库龄/waste/替代网络都在，但目标值低 17%——必有约束被静默放松。**只比对目标值会把这些全部误判为正确**。M1 需要 witness 式规则检查器（按族实现）替代纯目标值比对，这同时取代 §8.2 的 LLM 归因标注器方案（更便宜、可复现、无自我偏好）。

## F3 题面欠规约是系统性测量伪影

M2 inv_cap 第一轮 16/16 crash，主因不是语义错误：`prod_cost` 对标量/逐期列表双形态，题面未写明，模型默认标量。题面补全数据形态说明后 inv_cap base 变 16/16 全对。**受控集题面必须数据形态完备，否则测到的是"猜数据结构"。**

## F4 受控集 base 语义通过率（cheatsheet v2 后，4 采样 × 2 实例）

| 结构 | off | on |
|---|---|---|
| flow_dir（最简） | 8/8 | 8/8 |
| inv_cap（修题面后） | 8/8 | 8/8 |
| setup_charge | 7/8 | 8/8 |
| assign_fixed（最难） | 1/8(7 crash) | 4/8(4 crash) |

"模块内部足够简单"的设计目标基本达成（三个结构 base ≥ 87.5%);assign_fixed 残留 crash 多为下标/数据结构代码错误，归因五桶中属"代码与数据错误"，与连接错误可区分。

## F5 翻转对一致率：先验覆盖真实存在，但集中在"强教科书先验"的连接上（v4 扩量后精化）

v4 扩到 5 对翻转（C2×1、C3×2、C4×2)，检测全部改为数值化（solution.json 的标志位/目标值与翻转参照比对；代码正则会在注释上误报，已弃用——见 F7)。结果（每格 2 实例 × 4 采样）:

| 翻转对 | 算子 | off 跟随 | on 跟随 | 备注 |
|---|---|---|---|---|
| storage_time(inv_cap) | C4 | **7/8** | **3/8，忽略 4/8** | 先验覆盖信号集中在这里 |
| hold_time(setup_charge) | C4 | 6/8 | 7/8 | 目标项时间索引，无强先验，两模式都跟随 |
| setup_link(setup_charge) | C3 | 6/8 | 7/8 | 恒付启动费，两模式都跟随 |
| activation_link(assign_fixed) | C3 | 0/8(8 crash) | 4/8(4 crash) | off 在该结构连可运行代码都产不出，无法测量 |
| hub_conservation(flow_dir) | C2 | —（退化，见 F7) | — | — |

**精化后的结论**:base 语义两模式全满分，而 storage_time 翻转上 on 有 4/8 把"下一期期末"纠正回教科书形态（comments 里可见模型引用题面后又否决）。先验覆盖**集中在有强典范形态的连接上**（期末库容是教科书标准），不是普遍现象；hold_time 这种非典范位置两模式都照做。这比 v0.1 的"on 普遍更差"更准确，也更能进论文：**thinking 的先验覆盖效应是先验强度调制的**。样本仍小（storage_time 仅 16 样本），需 8 采样 × 更多实例确认。

## F7 翻转对设计的两个坑（已进生成器自检）

1. **退化翻转**:flow_dir 的"守恒→允许滞留"翻转，翻转参照目标值与 base 完全相同（最小化下松弛永不占优）——该翻转无区分度，测量中剔除。m2gen 已加自动检查：翻转参照目标值必须 ≠ base，否则 labels 里标 `discriminating: false`（当前仅 hub_conservation 被标）。C2 方向的翻转需要重新设计（如改为"流向反向"而非"加松弛")。
2. **检测必须数值化**:代码正则（`>=`、`y[w]==1`）会在模型抄进注释的题面文字上误报。数值通道（solution.json 标志位、目标值 vs 双参照）免疫此问题，但对 hub 这类退化翻转数值通道本身失效——两个通道各有盲区，设计翻转时两者都要可检。

## F6 次要观察

- off 模式跟翻时 1 例 crash 正是经典的 `t+1` 越界（忘了末期 clamp)——连接语义改变引发的连锁代码错误，可归因 C4。
- setup_charge off 有 1 例 W1（库存平衡）违规但目标值恰好 match——目标值比对漏检语义错误的直接证据。
- 内网端点速度：M2 单样本 ~10s,M1 schema 单次 40–180s；全部 pilot 在 CPU+API 下完成，零 GPU。

## 对 motivation v0.2 的修订建议

1. M1 测量标配 schema 模式 + 按族 witness 检查器（替代 LLM 归因）;
2. 翻转对扩量：每个连接算子至少 2 个结构 × 2 实例（当前 1×2),F5 是本轮最强信号，值得作为 P4 的主证据之一；
3. 错误四桶细化：誊抄（F1）与题面欠规约（F3）单列为测量装置问题，不进模型的错误分布；
4. assign_fixed 的 crash 构成需在 8B 模型上重测（代码错误率预计更高，需决定 crash 是否计入语义失败分母——建议分开报告）。
