# N3b: 剧本方法跨数据集实验(IndustryOR)— 结果

日期: 2026-11-04
状态: 完成
脚本: scripts/n3b_ior_rescue.py
数据: runs/n3b_ior_rescue/(base_*.json 54 条,card_z*.json 40 条,card_industryor.json)

## 目的

P2 剧本在 RetailOpt 幻影类上 97.5% 营救率,但那是"单一变异类型 × 同分布"。
本实验测试**方法本身**(蒸馏成功修复 → 卡片 → 营救失败)在另一数据集、
自然错误(非注入)上是否成立。

## 设计

- 对象:IndustryOR 判官细胞中 61 个 witness/gold 判错的细胞,其中 54 个有
  D2.1 标定规则(提供审计反馈)
- Phase 1 基线修复:题面 + 错误代码 + D2.1 规则违例(无卡片),≤3 轮;
  验证 = 重执行 + 目标值对 reference + 零规则违例(gold 不进提示词)
- Phase 2:从 Phase 1 成功例蒸馏 IndustryOR 卡片(4 例),营救 Phase 1 失败样本
  (40 个,卡片例子所在的 4 个 key 已排除)

## 结果

| 阶段 | 营救 | 口径 |
|---|---|---|
| Phase 1 基线 | 14/54 = 25.9% | 规则反馈 + 3 轮 |
| Phase 2 卡片营救 | 5/40 = 12.5% | Phase-1 失败样本 |
| 合计 | 19/54 = 35.2% | |

## 诚实结论:弱阳性,远不如 RetailOpt

卡片把"卡死样本"从 0 救到 5,说明方法在 IndustryOR 上有信号;
但 12.5% 与 RetailOpt 的 97% 不在一个量级。

**诊断:失败是异质的,一张卡片盖不住。** IndustryOR 卡片本身列举了 4 种
不同模式(锚界违例/链接约束缺失/变量类型误用/聚合错误)——蒸馏源就是混合的,
卡片自然稀释。而 RetailOpt 幻影类的失败是同质的(同一机制),一张卡片精准命中。
另外 5 个救回样本里 3 个初始零违例(纯"目标值不对"的静默错误),
说明规则反馈覆盖不足时卡片也在裸奔。

## 推论(进入设计)

1. 剧本方法成立的前提是**失败聚类同构** → 需要先做失败分类(router),
   再按类配卡;这正是"错误可数"命题的下一步验证。
2. IndustryOR 上修复前需要先补齐检出覆盖(零违例样本无反馈可用)。
3. 剧本的迁移主张修正为:**机制同构时跨族/跨集有效;异构失败需要
   "分类 → 类级卡片"结构**,而非单卡。
