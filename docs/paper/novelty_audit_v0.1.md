# 创新点审视 v0.1(对我们自己 raise 的各候选贡献逐条做新颖性裁决)

日期:2026-11-03。方法:以 `related_work_scan_v0.1.md`(2026-10-29)为底,
本轮增量检索(11-03)核对新工作,逐条裁决。裁决分四档:
**[空位]** 检索未见占有者,可作为贡献候选;**[拥挤]** 已有直接先例,
只能作工程亮点;**[仅动机]** 现象已被量化,只能引用;**[待精读]**
需读全文确认边界。每条给出防御性表述建议(论文里该怎么写才不被
审稿人一击即溃)。

## 候选 A:幻影(目标值对上但语义违例)的普遍存在

**裁决:[仅动机]**。OptArgus(目标值匹配产物幻觉率最高 31.1%)、
Falsification-Based Verification(NL4OPT 27.6% 目标值正确候选带违规
证书;"execution accuracy is blind in both directions")、SemOPT(语义
错误多于语法错误,自反思只修 21.4% 语义错误)、ReLoop v4 直接命名
"feasible but wrong = silent failure"。现象与量级均被覆盖。

## 候选 B:机制归因——系统性占据欠规约自由度(specification gaming)

**裁决:[待精读,偏弱]**。通用层面 specification gaming 已有系统性
研究(arXiv 2605.02269,推理模型在可利用规约的任务上普遍钻空子);
underspecification 有 D'Amour 等的经典文献。我们的增量 = **OR 建模域的
具体机制案例**(幻影初始库存:全部幻影同机制,目标值虚低 7%–45%)
+ 可执行的归因方法(witness 程序归因而非人工判读)。防御写法:不说
"我们发现 specification gaming",而说"我们给出 OR 建模中该现象的
首个逐实例量化与机制归因,且该机制解释了为何崩溃修复会转化为幻影
(见候选 D)"。需精读 OptArgus 的幻觉分类法,确认"幻影初始库存"这类
"无来源项"是否已被其分类覆盖。

## 候选 C:witness 独立语义审计器

**裁决:[拥挤,但有可站的差异化]**。本轮检索发现**最危险近邻
Opt-Verifier**(arXiv 2605.29556,2026-05):双侧验证——结构侧
回译一致性(模型抽象回结构与题面结构比对)+ 解侧判读(把数值解
翻译回自然语言"故事"再交 LLM 判合理性),NL4Opt 96.5%,跨 5 个
基准均值 64.3%,明确以"执行反馈看不到语义错误"为动机。**语义审计
的概念本身已被占据。** 我们仍然成立的差异:
1. **确定性可执行规则 vs LLM 判官**:Opt-Verifier 的解侧是
   LLM-as-judge,而 judge 校准研究显示 plain LLM 判官对缺陷的
   false-clear 率高达 90%(jev-judge-calibration,2026-09)。我们的
   witness 是零 LLM 的确定性检查,**误报率实测可控**(幻影误报 1.9%、
   成功样本误报 0%),judge 路线给不出这个数字;
2. **外部锚定 vs 自洽闭环**:其结构侧锚是同一管线从题面蒸馏的结构
   (蒸馏错了整个校验就塌);我们锚定参照语义,代价是可迁移性
   (规则需按族定制)——这同时暴露我们的软肋,见"待补充";
3. **数据丰富实例级审计**:Opt-Verifier 对大数据实例用 toy
   instantiation 绕过,恰好漏掉列映射/单位换算类错误(Falsification
   证明的探针盲区);我们的 witness 在真实实例解上检查。
防御写法:定位 = "确定性、零 LLM、误报实测可控的语义审计,与
judge 路线互补且在其不可靠处接管"。
另注:**VeriSimpl**(arXiv 2607.20474,化简式验证)也需列入对照表。

## 候选 D:缺陷洗白的纵向量化(修复把可见失败转化为不可见幻影)

**裁决:[空位,本轮检索未见新占有者]**。最近邻 ORLoopBench 只在
人为破坏的不可行代码上附带观察到"可行但解错问题"的语义漂移;
**在自然 agent 轨迹上逐版本度量"可见→不可见"转化率的工作,两轮
检索均未见**。我们手里的直接证据:P1 臂崩溃 64%→7% 的同时出解题
幻影占比升至 90%;F14 在线臂 witness 不可行残余 75→50、崩溃残余
18→37(瓶颈从语义层转移到代码层,方向相反、量级可比)。**这是目前
最站得住的实证贡献角度。**

## 候选 E:选择/训练压力放大不可见缺陷

**裁决:[空位(域内实证)]**。理论侧已有(LLMs Gaming Verifiers,
RLVR 会激励模型利用"验证器没强制约束的部分");优化建模域内无实证
(EVOM/SIRL/PEARL/StepORLM 均纯结果奖励)。我们进化实验的留出集
落差(第 0 代 +15.0pp → 第 1 代 +21.7pp)是**进化版选择压力放大
不可见缺陷的直接证据**。防御写法:"该理论预测在 prompt 进化场景
的首个域内实证"。

## 候选 F:防"偶然正确"的双层留出协议(变体级 + 族级 + 预注册生死判据)

**裁决:[空位(成套纪律)]**。Opti-Agent-Bench 提出"偶然正确"原则
并主张多实例测试,但量化未见;FunSearch/AlphaEvolve/OpenEvolve/
ShinkaEvolvo 等进化框架均未见留出变体闸门。变体+族双层隔离 +
预先写死判据的**成套**纪律未见占有者。强度中等(方法纪律而非新
机制),但与 D/E 捆绑后成为故事闭环的关键部件。

## 候选 G:多样性优先预算 + 目标值仲裁近 Oracle(80.5% vs 81.6%)

**裁决:[拥挤,工程亮点]**。best-of-n + 验证器选择在通用层面拥挤
(Cobbe 的 best-of-n、PRM、test-time compute 分配);验证预算分配
有 BAVAR/GRACE 直接先例。**OR 域特化点**(witness 判可行候选中按
目标值仲裁、距并集上界 1.1pp)可作系统亮点陈述,不作独立贡献主张。

## 候选 H:连接错误与组合泛化(预注册 RQ1:组合失败超出原子失败率
独立累积的部分归因于连接)

**裁决:[空位,主战场]**。最近邻:VRPCoder/Constraint Injection
(探针针对单模块遗漏/多余约束,不针对模块间连接;单领域;留出仅
3 变体)、CSE(通用指令遵循的乘法累积零假设)。**连接级探针 +
组合留出 + 与零假设的偏离度量,OR 域两轮检索未见**。

## 候选 I:反例/语义监督进入 OR 建模训练(预注册 RQ2)

**裁决:[空位(训练线核心),但留一个待精读]**。代码/数学/策略域
的反例监督已成熟(TCS/RAISE/CoVera);OR 建模 RL 检索所见全部纯
结果奖励。**待精读:SemOPT 的 Bradley-Terry 语义奖励模型训练数据
是否含执行反例——若含,本候选降级为"连接特化";若不含,空位完整。**

## JEV 定位(顺带回答)

JEV = TypeSafe 的 "System One" 判官模型(2026-09 发布,比 LLM 判官
快 200×、便宜 400×)。**它是可替换组件,不是框架级对手**:可在
harness 里充当廉价初筛;但其同类判官的校准数据(false-clear 率高)
反而佐证我们确定性规则审计的必要性。与我们主线无冲突,结合点 =
用它做大规模初筛、witness 做终审。

## 汇总:防御性故事线建议

降格为动机引用:A、B(部分)。
可作为实证贡献:**D(缺陷洗白纵向量化)+ E(选择放大实证)+
F(双层留出纪律)**,三者互相咬合,构成"测量纪律"主线。

研究线主战场:H + I(预注册 RQ1/RQ2,与 D/E 同属"连接与不可见
缺陷"大图景)。
