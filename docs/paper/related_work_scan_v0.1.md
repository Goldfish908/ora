# 相关工作扫描 v0.1（新颖性核查）

日期：2026-10-29。方法：网络检索 + 摘要/正文关键段核对。**尚未逐篇精读全文**，表中"未覆盖"判断只代表本次检索未发现，定稿前需精读确认。

## 1. 核查问题一："结果监督看不到的语义缺陷有多普遍"——已被量化，不可作为贡献

| 工作 | 结论（摘录） |
|---|---|
| OptArgus（arXiv 2605.11738） | 目标值匹配的产物中幻觉率最高 31.1%；基准含 484 干净 / 1266 注入 / 6292 自然 LLM 产物；多 agent 检测器 |
| Falsification-Based Verification（arXiv 2607.16646，Li & Hai） | NL4OPT 上 27.6%（155/562）目标值正确的候选带有违规证书，四族合计 15.7%；"execution accuracy is blind in both directions" |
| ReLoop（arXiv 2602.15983） | 组合型问题上可行性—正确性差距达 90 个百分点；求解器扰动的行为验证（CPT/OPT） |
| SemOPT（EMNLP 2026 Findings） | 语义错误多于语法错误；三轮自反思修正 66.7% 语法错误但仅 21.4% 语义错误；明确指出目标值匹配会给语义错误记分 |
| 基准审计（Zenodo 23375184，2026-10） | 127 题中 34.6% 的官方答案本身错误（主因：未声明的整数性） |
| ORGEval（ICML 2026） | 公式同构判定替代求解器口径评价 |
| 综述 arXiv 2508.10047 | IndustryOR 错误率 ≥ 54%，NL4Opt ≥ 26.4% |

结论：现象、量级、成因（含基准标签本身有错）均已被多篇工作覆盖，且覆盖到 2026-10。本线只能引用为动机，不能作为贡献。

## 2. 核查问题二：反例/证伪式验证与修复——高度拥挤

| 工作 | 机制 | 设定 |
|---|---|---|
| ReLoop | 参数扰动 + 阈值；IIS 诊断；回归安全修复 | 文本题（含 RetailOpt-190） |
| Falsification-Based Verification | 由对偶、比较静态推出的**健全**测试族（零误报）；证明盲区（单槽线性误用即单位错误、轨道上不绑定的约束不可见）；检出—求解调用预算曲线（约 88 次求解达 95% 效力） | 文本题；数值槽从题面抽取；明确把修复策略列为正交未做 |
| 优化模型变异测试（arXiv 2511.16383） | 测试生成 + 辅助模型 + 变异覆盖率 | 文本题 |
| OptArgus | 分类法驱动的专科审查 agent | 文本题产物 |
| OptiLoop（arXiv 2605.27630） | 协同环内验证与修复，跨实例经验复用 | 分布式 ADMM 协同场景 |
| SemOPT | Bradley–Terry 语义奖励模型 + 分层 MCTS 纠错 + 自适应门控 | 文本题 |

结论：round2 的"审查 + witness + 局部修复 + 回归"在方法层面没有新意；扩大受控缺陷集（注入 + 自然）OptArgus 已做。

## 3. 核查问题三：学习分配验证预算——通用层面已有工作

| 工作 | 内容 |
|---|---|
| BAVAR（Preprints 202608.2057） | 把 agent 验证建模为序贯、资源受限决策；异构验证器组合；按不确定性/关键性/信息价值触发；正向信用需可靠证据门控（非对称） |
| Adaptive TTC Allocation（arXiv 2602.03975） | 状态级选择性验证；用验证器反馈训练**同状态组内排序**；按局部不确定性分配验证次数；MATH 上少 44% 验证调用 |
| GRACE（arXiv 2606.19354） | 验证粒度的计算最优理论 |
| Sample, Mix, or Verify?（arXiv 2610.23255） | 不完美验证器下的测试时计算分配 |

结论：v0.1 的 H1/H2（预测检查结果 + 预算分配、组内排序指标）在通用层面已有直接先例，单独作为贡献会被判增量。

## 4. 核查问题四：反例作为训练监督

| 工作 | 领域 | 内容 |
|---|---|---|
| TCS（EMNLP 2026 Findings） | 代码 | 两阶段 RL：先学健全测试，再学针对当前错误的反例测试 |
| RAISE（arXiv 2609.33796） | 访问控制策略 | 失败检查与符号反例转为引导探索，off-context GRPO |
| Verifier-Grounded Agentic RL（arXiv 2610.19298） | 形式验证代码 | 读验证器诊断而非裁决；完整性审计防规格篡改 |
| SCOPE-RL | 数学 | 步级可执行检查，经参考解与受控反例认证 |
| CoVera（EMNLP 2026 Findings） | 代码 | 生成与自验证共进化，执行标签训练验证器 |
| **EVOM（arXiv 2604.00442）** | **优化建模** | **仅用结果（求解执行）奖励**的 GRPO/DAPO |

结论：反例监督训练在代码/数学/策略合成已成熟；**在优化建模中，现有 RL（EVOM、SIRL、PEARL、StepORLM）检索所见均以结果/目标值为奖励**——而第 1 节表明该奖励会给语义错误模型记分。这是本次检索中看到的最清楚的空位（待精读确认 SemOPT 奖励模型训练数据是否含执行反例）。

## 5. 核查问题五：agentic、数据丰富的 OR 设定

ORAgentBench（arXiv 2606.19787）：107 任务，多文件业务数据、配置、提交 schema，隐藏验证器判可行性与质量；最强配置通过率 35.51%；失败分析以"遗漏运营规则、脆弱的公式、可行解构造弱、改进不足"为主。

第 1–3 节的验证工作**全部在文本题设定**（数值来自题面槽位）。数据丰富设定下的缺陷类型（列映射、单位换算、跨文件数据关联、实现未落地的规则）中，单位错误正是 Falsification 论文证明的单槽探针盲区。**本次检索未发现面向 agentic 数据丰富 OR 任务的语义验证工作。**

## 6. 核查问题六："结果看不见的缺陷"还有哪些切面未被解决

已有工作回答的是**静态快照上的普遍性**（某一时刻、某一产物、单实例）。以下三个**动态**切面本次检索未见系统研究：

| 切面 | 问题 | 最近的已有工作 | 差距 |
|---|---|---|---|
| Q1 交互产生 | agent 在结果反馈驱动的调试/修复中，是否把"看得见的失败"转化为"看不见的缺陷"（缺陷洗白：为求可行而放松/删除约束、硬约束改罚项、加无来源项） | ORLoopBench（arXiv 2601.21008）：不可行修复基准；附带观察到整模型重生成会"可行但解错问题"的语义漂移 | 只在人为破坏的不可行代码上、作为附带观察；未在自然 agent 轨迹上逐版本度量可见→不可见的转化率与诱因 |
| Q2 训练放大 | 仅结果奖励的 RLVR（EVOM/SIRL 类）训练过程中，看不见缺陷的占比是否上升；反例奖励能否抑制 | 通用 RLVR 黑客：Verifier Errors in RLVR（arXiv 2609.35677，理论：被接受错误占比在梯度流下的增长条件）；LLMs Gaming Verifiers（arXiv 2604.15149，同构扰动测试 IPT 抑制捷径）；PROF | 优化建模领域未见；OR 的反例天然可执行、可认证，是检验该理论的干净场景 |
| Q3 单实例掩盖 | 在 agentic 数据丰富任务中，通过官方单实例验证器的提交里，有多少在符合规格的数据更新下会失效（"偶然正确"） | 2511.16383 图 1(c)、Opti-Agent-Bench（arXiv 2607.10768）提出"偶然正确"原则并主张多实例测试 | 概念已有；ORAgentBench 类基准上的量化未见 |

另：现有普遍性数字均相对于检测器或抽取的断言（Falsification 论文自述"extraction errors can contribute"），缺少以参考实现行为为真值的认证估计——可作附带改进，单独不足以成为贡献。
