## 1. 一句话问题

> 用交互中**被实际执行确认的反例**作监督，学习预测"在当前状态下执行某项检查，会不会揭示真实语义缺陷"，
> 并用该预测在固定预算下分配验证与修复动作——这能否在同等计算下提高 OR agent 最终决策的正确性？

动机证据（round2）：审查/修复能力在受控集上成立（检出 7/7、修复 6/7），但真实任务中 actor 几乎不调用它
（6 臂合计 2 次 audit、0 次 repair），B2 未胜 B0。**瓶颈是"何时查、查什么"，不是"会不会查"。**

## 2. 形式化

- **状态 s**：题面与公开数据、当前制品版本（代码/模型 hash）、EvidenceStore（Requirement / Finding / CheckResult / RepairResult）、剩余预算。
- **候选检查 c**：一个可执行的检查动作。粒度分两级：
  - c_audit：一次审查调用（focus × requirement 子集）；
  - c_witness：一个具体 witness 程序（微型实例 + 期望接受/拒绝），在容器内真实执行。
- **结果 o(s, c)**：`reveals`（揭示确认缺陷）/ `passes`（未揭示）/ `inconclusive`，以及成本（token、墙钟、执行时间）。
- **预测器 f(s, c)** → P(reveals)、E[cost]，可选输出预期观察（沿用 predict v2 的 validate 分支字段）。
- **策略 π_f**：按 P(reveals) × 缺陷影响 − λ·cost 排序，在检查预算 B 内选择检查；揭示后路由到 repair。

### 2.1 标签定义（本线最关键的口径）

"真实语义缺陷"按**相对参考实现的行为差异**定义，不按 LLM 声明定义：

| 层级 | 来源 | 缺陷真值 | 用途 |
|---|---|---|---|
| T1 受控 | 变异制品（已知变异 + 参考实现） | witness 实例上制品行为 ≠ 参考行为（可行性判定或目标值超容差） | 训练 + 主评估 |
| T2 交互 | agent 轨迹中执行过的 witness | 执行结果 + 独立裁决（有参考解时按 T1 口径；无参考解时双实现一致性 + 人工抽检） | 训练（带噪）+ 分布偏移测试 |

纪律：
1. LLM 审查的 `confirmed` 只是候选标签，进入训练前必须过上表裁决；
2. T2 标签噪声必须实测：在有参考解的 T2 子集上测 `confirmed` 与裁决真值的一致率，作为论文中的显式数字；
3. witness 本身也是对题面的解读——"执行确定"不等于"规格理解正确"，报告中两者分开表述。

## 3. 假设（预注册）

- **H1 预测**：在 held-out 问题族上，学习型 f 优于零样本 LLM 预测器（P0）与启发式基线，
  且在**同状态不同检查**的组内排序上优于 P0（这是"条件于动作"而非"预测平均未来"的核心证据）。
- **H2 分配**：同等检查预算 B 下，π_f 揭示的确认缺陷数、修复后正确率高于固定规则触发（B2）、随机触发、actor 自发触发、零样本预测器驱动的策略。
- **H3 效用**：ORAgentBench 分层子集上，计算对齐条件下 B3 的可行率/质量/通过率优于 B0、B1、B2。

阴性结果同等交付。H1 不成立则不做 H2/H3 的结论实验（见 §8）。

## 4. 数据

### 4.1 D-ctrl（受控缺陷集，扩展自 round2 的 3 题 13 制品）

- **来源题**：IndustryOR、MAMO、NL4Opt 等带参考答案的公开集（需排除与 ORAgentBench 内 IndustryOR 任务重叠的题）；LLM 合成题（用户侧生成）补结构多样性。
- **参考实现**：每题至少两份独立实现且目标值一致（合成题强制此条）；不一致的题剔除。
- **变异算子**：方向、遗漏约束、额外约束、索引范围、量词、单位换算、数据列映射、整数性、目标项增删、硬约束软化。
- **等价过滤**：变异后在随机/边界实例集上与参考行为无差异者标 `equivalent_candidate`，不作缺陷样本；另保留人工构造的合法等价改写作负对照。
- **防泄露**：剥除全部注释与具规格含义的变量名（round2 blind 模式泄露的教训）。
- **划分**：按源问题分组（同源变异不跨 split），另按问题族留 held-out 族。
- **规模目标**：≥ 100 源问题、≥ 500 变异制品（待第 2 周按生成成本校准）。

### 4.2 D-traj（真实轨迹状态）

- ORAgentBench 开发任务轨迹截取中间状态，配合分叉采样获得同状态多检查的真实结果；
- 研究 held-out 任务在任何读取/训练/版本选择前按类型分层抽取并写入本文附录后再运行。

## 5. 预测器候选（效果优先，按 dev 集 H1 指标选型）

| 编号 | 形态 | 说明 |
|---|---|---|
| P0 | 零样本 qwen3.8-27b（predict v2） | 已有，基线 |
| P1 | 结构化特征 + GBDT | 特征：需求覆盖、finding 状态、检查类型、制品变更范围、历史检查结果 |
| P2 | LoRA 微调 LLM（(s, c) → o） | 规模按 dev 效果与延迟定（27B 或更小 Qwen） |
| P3 | P2 + 检索（相似状态的历史 witness 结果） | 视 P2 结果决定是否做 |

## 6. 实验臂

| 臂 | 内容 | 用途 |
|---|---|---|
| B0 | 现有 OR agent，自主执行与修复 | 强基线 |
| B1 | B0 + 通用反思/检查调用，token 与 B3 对齐 | 隔离"多花推理预算"的收益 |
| B2 | 审查/修复 worker，固定规则触发 | round2 核心实现 |
| B2-self | 审查/修复 worker，actor 自发触发 | round2 现状 |
| B3-P0 | 零样本预测器驱动的分配 | 隔离"学习"的贡献 |
| B3 | 学习型预测器驱动的分配 | 本文方法 |

同一 actor 模型、公开信息、工具权限与总预算；worker、预测器、witness 执行的全部开销计入。

## 7. 指标

- H1：AUROC、ECE、Brier；同状态组内 pairwise accuracy（ties 计 0.5）；逐问题族结果，不只报汇总。
- H2：预算 B 下确认缺陷检出数、误报数、修复成功率（witness 复判）、确认回归数；检出—预算曲线。
- H3：官方 verifier 可行率、质量、通过率；全部 LLM token、墙钟、求解时间。
- 统计：按 (task, seed) 配对；H2/H3 用配对 Wilcoxon 或配对 bootstrap，报告置信区间。

## 8. 闸门与止损（阈值为初值，冻结前确认）

| 闸门 | 时间 | 条件 | 不满足时 |
|---|---|---|---|
| G0 | 第 2 周末 | §9 必修项完成；T2 标签噪声可测且已报告 | 不收集训练数据 |
| G1 | 第 5 周末 | 最佳学习型 f 相对 P0：held-out 族 AUROC 提升 ≥ 0.05，且组内 pairwise accuracy 更高 | 转向"受控缺陷基准 + verifier 可靠性"写法 |
| G2 | 第 8 周末 | π_f 相对 B2 规则：同预算确认缺陷检出相对提升 ≥ 10%，配对检验 p < 0.05 | 不跑 H3 结论实验 |
| G3 | 第 11 周末 | H3 结果出齐 | 按实际结果写，不补跑凑数 |

## 9. 动工前必修项（来自 round2 已知缺陷）

1. confirm 流程：对"未发现问题的确认"写 refuted/关闭，不得升级为 confirmed（a_e1 F-002 案例）；
2. 结果分类按语义而非裸 rc（`... | tail` 掩盖崩溃的案例）；
3. 受控制品剥除注释后重跑 full/blind 对照；
4. round2 受控集定位正确性人工复核填表（summary.json 中 localization_correct 为 null）。

## 10. 相关工作区分（待精读核实）

| 工作 | 已知关注点（据任务书） | 本文差异（待核实后定稿） |
|---|---|---|
| SAC-Opt | 语义锚点重建与局部修正 | 本文不提出新的检查方法，学习检查的分配 |
| COVER | 反例、局部修复、回归 | 反例在本文是**训练监督**，而非仅在线修复信号 |
| SemOPT | 语义奖励模型 + 分层纠错搜索 | 本文标签来自执行确认的反例而非 LLM 判断；预测对象是"检查后果"而非"候选质量" |
| 优化模型变异测试（arXiv 2511.16383） | 审查器检错能力与边界 | 本文用变异集作监督数据源，而非只作评测 |
| EquivaMap / SOVER | 形式表示映射与验证 | 可作等价过滤或 witness 工具 |
| LLM-as-WM（Chae et al. 等） | 预测下一观测 | 本文预测"检查会揭示什么"，并用于预算分配 |

必须精读确认的风险点：上述任一工作是否已经**用执行反例训练检查选择/触发策略**。若是，本文贡献需重新定位。
