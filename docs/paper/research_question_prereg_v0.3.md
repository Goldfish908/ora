# 连接错误的可执行反例监督与规则组合泛化：研究问题与预注册稿 v0.3

日期：2026-10-29。目标会议：ICML 2027。状态：**草稿，待确认后冻结**。
前序：v0.2（同目录）。新颖性依据：`related_work_scan_v0.1.md` §6b。

## 0. 命题

> 对于已经学过的业务规则，针对**连接错误**的可执行反例监督，能否比普通样本扩充更有效地迁移到**未见规则组合**？

辨识度来自两点：反例针对什么错误（模块之间的连接，而非模块内部或一般代码错误），以及如何检验组合泛化（严格留出约束交互结构）。表示、验证、修复与训练算法都围绕这两点选择。

术语：本文"交互"指**规则/约束之间的交互（连接）**，不指 agent 与环境的交互。英文统一用 **interaction**：interaction error（连接错误）、interaction counterexample / interaction witness（交互反例）。

v0.2 内容的归位：修复引入的缺陷 → 负样本来源之一与辅助分析；RL 奖励 → 实现监督的方式之一，不预设；单实例掩盖 → 说明为何需要可执行 witness 与多实例检验；论文主结果始终是未见规则组合上的泛化表现。

## 1. 形式化

### 1.1 规则模块与连接

- **规则模块** M = (语义意图, 接口, 内部实现)。接口声明 M 引用的索引集合、决策变量占位符、参数占位符，以及可选的**激活谓词**占位符。表示层复用或参考 CIR（约束原型 + 范式）与 ASTOR（类型化 AST）。
- **连接** κ 把若干模块接到同一个问题上，由以下要素组成：
  - 变量绑定：接口占位符 → 全局变量（例：不重叠模块的 start 绑定到哪个 start 数组）；
  - 索引对应：接口索引 → 全局索引及其映射（例：task → machine 的分配索引）；
  - 量词作用域：模块实例化在哪个 ∀ 之下、求和范围是哪个集合；
  - 激活条件：模块何时生效，以及多个条件如何组合（与/或、指示变量、big-M）。
- **连接算子库 K**：上述要素的有限类型集合，第 2 周定稿（初稿见 §3.2）。

### 1.2 "局部正确、连接错误"的可检查定义

产物 P 是参考 R 的**连接错误变体**，当且仅当同时满足：
1. **模块内部不变**：P 与 R 的每个模块 AST 子树在 α-重命名下相同（可机检）；
2. **差异只在连接**：P 与 R 的 AST 差异只落在 κ 的节点上（绑定、索引映射、量词、激活谓词），且限定为单一连接算子的一次编辑；
3. **可执行**：P 能编译、能求解（不是语法或运行错误）；
4. **行为确实改变**：存在规格实例 θ 使 P 与 R 行为不一致，且该 θ 已被执行认证（**交互 witness**）；找不到这样的 θ 的变体标为等价候选，不作负样本。

示例（来自你给的例子）：分配模块"每项任务选一台机器"、不重叠模块"激活时两任务不能同时执行"均不变；连接把激活条件从"两任务都分到机器 m"改成"任一任务分到机器 m"。交互 witness 是一个两任务分在不同机器、时间重叠的实例：R 接受，P 拒绝或强制串行。

### 1.3 交互 witness 与模块 witness 的区别

- **模块 witness**（VRPCoder 式探针）：只违反一个模块的约束，用来检出该模块被遗漏或多加；
- **交互 witness**：同时激活两个以上模块，且结果取决于它们之间的连接。连接错误在模块 witness 上通常不可见——这是本文监督信号与 VRPCoder 区分的技术核心，第 3 周用数据验证（§5 G1）。

## 2. 与最近邻的区分

| 维度 | VRPCoder（arXiv 2606.04816） | 本文 |
|---|---|---|
| 反例针对 | 单模块的遗漏/多余约束 | 模块之间的连接（绑定、索引、量词、激活） |
| 组合留出 | 3 个变体，模块见过、两两组合未见 | 按连接结构分层留出，粒度预注册（§3.3） |
| 对照 | 有/无注入 | 同预算普通扩充、交互密集正例、普通错误监督、模块级反例监督 |
| 领域 | VRP | 多类业务规则（调度、分配、库存、运输…） |
| 表示 | Gurobi 脚本 | 复用 CIR/ASTOR 式 AST，模块与连接可分开检查 |

"尚未看到有人同时完成：连接级反例 + 结构化组合留出 + 同预算多对照"——目前是**待核实**的定位，VRPCoder 精读后定稿。

## 3. 数据与划分

### 3.1 生成方式

问题从 AST 生成：选规则模块 + 连接 → 确定性编译出参考模型 R（参考正确性由构造保证）→ LLM 生成自然语言题面（用户侧合成）。

**主要风险：题面歧义。** 若题面对连接的表达本身有歧义（如"都分到"与"任一分到"写得含糊），模型错误就无法归因于连接能力。对策：
- 每个题面做回译检查：另一个 LLM 只看题面重建连接，必须与 AST 一致；
- 每个连接算子人工抽检；
- 歧义题剔除，并报告剔除率。

### 3.2 连接算子初稿（第 2 周定稿）

共享索引绑定、条件激活（与/或/指示变量）、量词作用域（∀ 内/外、求和范围）、时间对齐（t / t+1、窗口）、跨模块单位/换算、跨数据表实体映射、聚合层级（按机器/按班次）。

### 3.3 "未见"的粒度（第一阶段）

规则模块与连接算子都在训练中出现过，**测试的是它们未见过的组合结构**。分三层，分开报告：

| 层级 | 训练见过 | 测试未见 |
|---|---|---|
| S1 新配对 | 算子 κ 作用于规则对 (A,B)、(C,D) | κ 作用于 (A,C) |
| S2 更高阶 | 两两连接 | 三个及以上模块的连接链或环 |
| S3 新整体结构 | 局部连接模式 | 这些模式拼成的新问题结构 |

防泄漏纪律：
- **训练反例不得出现测试组合**：任何训练负样本、witness、修复对的 (模块集合, 连接结构) 签名都不得与测试集重合，按签名哈希机检；
- 划分在生成任何训练数据之前固定并写入本文附录；
- "未见"只针对本实验训练数据，不声称基础模型预训练从未见过类似结构。

## 4. 研究问题与假设（预注册）

### RQ1 组合瓶颈
在原子规则能力已测量、已控制的前提下，未见组合是否仍有明显错误？其中多少能定位到连接？

- **H1**：未见组合的失败率显著高于"原子规则失败率独立累积"的预测（零假设参照 CSE 的乘法模型）；超出部分中，可归因于连接错误的比例 ≥ 预注册阈值。
- 测量：每个测试问题同时测其各原子规则单独出现时的正确率；对组合失败做 AST 级归因（模块内部错误 / 连接错误 / 其他）。

### RQ2 监督有效性
相同训练资源下，连接反例监督是否比普通扩充、普通错误监督更能改善未见组合上的表现？

| 臂 | 训练数据 | 排除的解释 |
|---|---|---|
| A0 | 基础训练集（原子规则 + 已见组合的正确例题） | 共同起点 |
| A1 | A0 + 普通完整例题 | 收益只来自更多数据 |
| A2 | A0 + 交互密集的正确例题（连接复杂度与 A4 匹配） | 收益只来自更有针对性的正样本 |
| A3 | A0 + 普通错误监督：模块**内部**变异 + 模块 witness（含 VRPCoder 式探针） | 收益只来自一般错误学习机制 |
| A4 | A0 + 连接错误 + 交互 witness 监督 | 本文方法 |

- **H2**：A4 在 S1–S3 测试上优于 A1–A3，在已见组合与原子规则上非劣。
- **匹配要求**：
  - A1–A4 增量样本数、训练 token 数、优化步数相同；
  - A3 与 A4 使用相同训练算法、相同 AST 编辑规模，难度按"基础模型在该负样本对应正例上的通过率"分层匹配；
  - 训练预算之外，单独报告数据构造成本与求解器调用次数。

### RQ3 机制与边界
收益来自交互样本的选择、负例对比，还是可执行 witness 提供的信息？能迁移到哪些组合深度、问题规模和业务场景？

- 三因子拆解（同算法、同预算）：
  - (i) 选择：A2（只有交互密集正例）；
  - (ii) 对比：A4 去掉 witness（错误程序 + 修复，不给反例实例）；
  - (iii) witness：完整 A4。
- 边界：按 S1/S2/S3、模块数、实例规模、业务领域分别报告；外部迁移用 ORAgentBench 中含相应规则组合的任务做定性/小样本检验。

## 5. 评价口径

- **主指标：认证语义正确率**。在留出的多实例集合与留出的交互 witness 电池上，与参考 R 的行为一致才算对。目标值匹配只作次要指标——它对连接错误天然盲（单实例掩盖）。
- 测试用 witness 电池与训练 witness 不重合。
- 次指标：可执行率、目标值匹配率、原子规则正确率、错误类型分布（AST 归因）。
- 统计：多个训练 seed，按问题配对的 bootstrap 置信区间；逐粒度层、逐算子报告。

## 6. 训练算法（待定，选型标准：A3/A4 必须同算法）

候选：(a) SFT 修复格式（题面 + 错误程序 + witness → 正确程序）；(b) 偏好对比（正确 vs 连接错误）；(c) RL 奖励中加交互 witness 项（VRPCoder 式）。建议先用 (a) 做主实验（成本最低、最容易匹配），(c) 作扩展。基座规模建议 7–8B（与 VRPCoder、EVOM 可比）。

## 8. ORA 工程的位置

ORA 的版本化制品、验证器和分叉设施用于数据构造（负样本、witness 执行）与外部迁移检验。新增模块是否纳入本文的标准：**它是否帮助识别、监督或验证规则连接能力的迁移。**
