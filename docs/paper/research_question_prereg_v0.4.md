## 0. 命题

> 对于已经学过的业务规则，针对**连接错误**的可执行反例监督，能否比普通样本扩充更有效地迁移到**未见规则组合**？

辨识度来自：反例针对什么错误（模块之间的连接，而非模块内部或一般代码错误），以及如何检验组合泛化（严格留出约束交互结构）。表示、验证、修复与训练算法都围绕这两点选择。

**术语**：本文"交互"指规则/约束之间的交互（连接），不指 agent 与环境的交互。英文统一用 interaction：interaction error（连接错误）、interaction counterexample / interaction witness（交互反例）。

v0.2 内容的归位：修复引入的缺陷 → 负样本来源之一与辅助分析；RL 奖励 → 第二组证据（§6.3）；单实例掩盖 → 说明为何需要可执行 witness 与多实例检验；主结果始终是未见规则组合上的泛化表现。

## 1. 形式化

### 1.1 规则模块与连接

- **规则模块** M = (语义意图, 接口, 内部实现)。接口声明 M 引用的索引集合、决策变量占位符、参数占位符，以及可选的激活谓词占位符。
- **连接** κ 把若干模块接到同一个问题上，由四类要素组成：
  - 变量绑定：接口占位符 → 全局变量；
  - 索引对应：接口索引 → 全局索引及其映射；
  - 量词作用域：模块实例化在哪个 ∀ 之下、求和范围是哪个集合；
  - 激活条件：模块何时生效、多个条件如何组合（与/或、指示变量、big-M）。
- **连接算子库 K**：上述要素的有限类型集合（初稿见 §3.2）。

### 1.2 "局部正确、连接错误"的可检查定义

产物 P 是参考 R 的**连接错误变体**，当且仅当：
1. **模块内部不变**：P 与 R 的每个模块 AST 子树在 α-重命名下相同（机检）；
2. **差异只在连接**：AST 差异只落在 κ 的节点上，且为单一连接算子的一次编辑；
3. **可执行**：P 能编译、能求解；
4. **行为确实改变**：存在已执行认证的规格实例 θ（交互 witness）使 P 与 R 行为不一致；找不到的变体标为等价候选，不作负样本。

示例：分配模块"每项任务选一台机器"与不重叠模块"激活时两任务不能同时执行"均不变；连接把激活条件从"两任务都分到机器 m"改成"任一任务分到机器 m"。交互 witness：两任务分在不同机器且时间重叠——R 接受，P 拒绝或强制串行。

### 1.3 交互 witness 与模块 witness

- **模块 witness**（VRPCoder 式探针）：只违反一个模块的约束，检出该模块的遗漏或多余；
- **交互 witness**：同时激活两个以上模块，结果取决于它们的连接。连接错误在模块 witness 上通常不可见——这是本文与 VRPCoder 区分的技术核心，由闸门 G1 用数据验证。

## 2. 与最近邻的区分

| 维度 | VRPCoder（arXiv 2606.04816） | 本文 |
|---|---|---|
| 反例针对 | 单模块的遗漏/多余约束 | 模块之间的连接 |
| 组合留出 | 3 个变体，模块见过、两两组合未见（66 题） | 按连接结构分层留出（S1/S2/S3），粒度预注册 |
| 对照 | 有/无注入 | 同预算普通扩充、交互密集正例、普通错误监督（含 VRPCoder 式探针） |
| 领域 | VRP | 3–4 个业务领域 |
| 表示 | Gurobi 脚本 | 类型化 DSL/AST，模块与连接可分开检查 |

"同时完成连接级反例 + 结构化组合留出 + 同预算多对照"目前是**待核实**定位，VRPCoder 精读后定稿。

## 3. 数据与划分

### 3.1 输出表示（建议）

模型输出**类型化 DSL 的 AST-JSON**（参考 ASTOR 的语法与 CIR 的约束原型），由确定性编译器转为求解代码。理由：
- 第 1.2 节的四条检查只有在 AST 上才能机检；
- 编译确定，排除一般代码错误（API 误用、语法错误），把监督集中到组合机制；
- 参考模型由同一编译器从参考 AST 产生，正确性由构造保证。

代价：外部迁移到 ORAgentBench（自由代码）需要额外的落地层，只作定性检验（§4 RQ3）。

### 3.2 生成方式与题面歧义控制

- 问题从 AST 生成：选规则模块 + 连接 → 编译出参考 R → LLM 生成题面（用户侧合成，走 API，不占训练 GPU）。
- **主要风险是题面歧义**：若题面对连接的表达本身含糊，模型错误无法归因于连接能力。对策：
  - 回译检查：另一 LLM 只看题面重建连接，必须与 AST 一致；
  - 每个连接算子人工抽检；
  - 歧义题剔除，报告剔除率。

连接算子初稿（第 1 周定稿）：共享索引绑定、条件激活（与/或/指示变量）、量词作用域（∀ 内外、求和范围）、时间对齐（t/t+1、窗口）、跨模块单位换算、跨数据表实体映射、聚合层级。初始范围建议 6–8 个算子、15–20 个规则模块、3–4 个业务领域。

### 3.3 "未见"的粒度

规则模块与连接算子都在训练中出现过，测试的是它们**未见过的组合结构**：

| 层级 | 训练见过 | 测试未见 | 本期角色 |
|---|---|---|---|
| S1 新配对 | κ 作用于 (A,B)、(C,D) | κ 作用于 (A,C) | 主结果 |
| S2 更高阶 | 两两连接 | 三个及以上模块的连接链或环 | 边界分析 |
| S3 新整体结构 | 局部连接模式 | 这些模式拼成的新问题结构 | 边界分析 |

防泄漏：
- 训练正例、负例、witness、修复对的 (模块集合, 连接结构) 签名不得与测试集重合，按签名哈希机检；
- 划分在生成任何训练数据前固定并写入附录；
- "未见"只针对本实验训练数据，不声称基础模型预训练未见过类似结构。

### 3.4 规模（暂定，第 4 周按生成成本校准）

| 集合 | 规模 | 格式 |

## 4. 研究问题与假设（预注册）

### RQ1 组合瓶颈
在原子规则能力已测量、已控制的前提下，未见组合是否仍有明显错误？其中多少能定位到连接？

- **H1**：未见组合失败率显著高于"原子规则失败率独立累积"的预测（零假设参照 CSE 的乘法模型）；超出部分中，归因于连接错误的比例达到预注册阈值。
- 测量：基础模型零样本（走推理，不占训练预算）+ A0 checkpoint；对组合失败做 AST 级归因（模块内部 / 连接 / 其他）。

### RQ2 监督有效性
相同训练资源下，连接反例监督是否比普通扩充、普通错误监督更能改善未见组合上的表现？

| 臂 | 增量数据 | 排除的解释 |
|---|---|---|
| A0 | 无（共同起点） | — |
| A1 | 普通完整例题（已见组合） | 收益只来自更多数据 |
| A2 | 交互密集的正确例题（连接复杂度与 A4 匹配） | 收益只来自更有针对性的正样本 |
| A3 | 模块**内部**变异 + 模块 witness（含 VRPCoder 式探针） | 收益只来自一般错误学习机制 |
| A4 | 连接错误 + 交互 witness | 本文方法 |

- **H2**：A4 在 S1 上优于 A1–A3；在已见组合与原子规则上非劣。
- 匹配：增量 token 数与优化步数相同；A3 与 A4 同格式、同 AST 编辑规模，难度按"基础模型在对应正例上的通过率"分层匹配；数据构造成本与求解器调用次数单独报告。

### RQ3 机制与边界
收益来自交互样本的选择、负例对比，还是可执行 witness 提供的信息？能迁移到哪些组合深度、问题规模和业务场景？

- 三因子拆解（同算法、同预算）：
  - 选择：A2；
  - 对比：A4−（错误 AST + 修复，不给 witness）；
  - witness：A4。
- 边界：S2/S3、模块数、实例规模、业务领域分别报告；ORAgentBench 中含相应规则组合的任务做定性检验。

## 5. 评价口径

- **主指标：认证语义正确率**——在留出的多实例集合与留出的交互 witness 电池上与参考 R 行为一致。目标值匹配只作次要指标（它对连接错误天然盲）。
- 测试用 witness 电池与训练 witness 不重合。
- 次指标：可编译率、目标值匹配率、原子规则正确率、AST 级错误类型分布。
- 解码：greedy pass@1 为主，另报 pass@4（temperature 0.7）。thinking 模式训练与测试统一关闭。
- 统计：3 个训练 seed；按问题配对的 bootstrap 置信区间；逐粒度层、逐算子报告。

## 6. 模型与训练

### 6.1 模型选择

- **主实验：Qwen3.5-9B**。理由：
  - 72 小时窗口内能完成 5 个臂 × 3 seeds 的主实验与 RQ3 拆解；
  - RL 第二组证据在 9B 上才放得进预算；
  - 与 VRPCoder（8B）、EVOM 等规模可比。
- **规模验证：Qwen3.8-27B**，只跑 A0/A1/A3/A4 × 1 seed，检验结论在更大模型上方向一致。
- **第 2 周提升空间试点决定最终选择**：两模型零样本跑约 200 道生成题（走 API 或少量推理，不占训练窗口），要求"原子规则正确率高、未见组合有明显缺口"。若 9B 原子规则过弱（RQ1 前提不成立），主模型改为 27B，并按 §7.3 缩减方案执行。

### 6.2 主范式：两阶段 SFT（LoRA）

- **阶段 1**：基础模型在 A0 上 SFT，得到共享起点 A0-ckpt（每个模型规模 1 次）。
- **阶段 2**：各臂从 A0-ckpt 出发，在"增量 2/3 + A0 回放 1/3"上训练，token 数、步数、超参完全相同。
- **样本格式**：
  - A1/A2：生成格式（题面 → AST）；
  - A3/A4：修复格式（题面 + 错误 AST + witness 描述 → 正确 AST）；
  - A4−：修复格式但 witness 描述换成"该模型有误"。
- **witness 描述**由 AST 与执行结果确定性模板生成（"实例 θ：参考接受，当前拒绝；涉及模块 A、B 的激活条件"），**不使用任何 LLM 写的推理文字**，避免把教师蒸馏混进 witness 的效果。
- **已知不对称**：A3/A4 的增量是修复格式，测试是生成格式；修复能力能否迁移到生成本身是混杂因素。两项缓解：回放部分各臂一致保留生成格式；RL 第二组证据在完全相同的生成格式下比较监督信号。
- **超参**：LoRA r=64、α=128、lr 1e-4、2 epochs；只在 A0 开发集上调一次，各臂不单独调参。

### 6.3 第二组证据：GRPO（条件执行）

- 从 A0-ckpt 出发，相同题目池（已见组合训练划分），相同 GRPO 配置（G=8），各臂只差奖励：
  - R1：可编译 + 目标值匹配；
  - R2：R1 + 模块 witness 通过；
  - R3：R1 + 交互 witness 通过。
- 回答"同一算法、同一格式下，换掉监督信号是否仍有效"，与 VRPCoder 的奖励设计直接对标。
- 仅在 SFT 主实验完成且预算剩余时执行，1 seed，结论按探索性证据表述。

## 7. 算力预算与 72 小时窗口

### 7.1 估算假设

A800 80GB，按约 35% MFU 估算；9B LoRA 每 4000 万 token 约 4–6 GPU 时，27B 约为 3 倍。数据生成与题面合成走 API，witness 执行走 CPU，均不占训练 GPU。

### 7.2 预算表（上限 576 GPU 时）

| 项 | 规格 | GPU 时 |
|---|---|---|
| 9B 阶段 1 | A0，1 次 | 约 6 |
| 9B 阶段 2 主实验 | A1–A4 + A4−，5 臂 × 3 seeds = 15 次 | 约 60 |
| 9B 评测 | 16 个 checkpoint × 全部测试集 | 约 25 |
| 27B 规模验证 | 阶段 1 + A1/A3/A4 × 1 seed，每次 2 卡 | 约 60 |
| 27B 评测 | 4 个 checkpoint | 约 12 |
| 9B GRPO（条件） | R1/R2/R3 × 1 seed | 约 150 |
| 预留（重跑、故障、超时） | 约 30% | 约 160 |
| **合计** | | **约 475** |

### 7.3 窗口排程（按优先级，前序未完成不启动后序）

| 窗口时段 | 内容 | 并行方式 |
|---|---|---|
| 0–2 h | 冒烟：9B 小样本训练 + 评测管线全链路 | 1–2 卡 |
| 2–4 h | 9B 阶段 1 | 8 卡数据并行 |
| 4–14 h | 9B 阶段 2 主实验（15 次） | 8 卡各跑 1 个 LoRA，两轮 |
| 14–20 h | 9B 评测；同时 27B 阶段 1 | 评测 4 卡，27B 4 卡 |
| 20–30 h | 27B 阶段 2（3 次）+ 评测 | 每次 2 卡 |
| 30–62 h | 9B GRPO 三臂（条件执行） | 每臂 8 卡顺序或 3 组并行 |
| 62–72 h | 补跑与缓冲 | — |

主实验（RQ1–RQ3 的核心证据）在前 20 小时内完成，后面的内容都可以裁掉而不影响论文主结论。

**缩减方案**（若试点显示必须以 27B 为主模型）：主实验降为 A1–A4 × 2 seeds，取消 A4− 之外的 RQ3 项与 GRPO，27B 主实验约 200 GPU 时。

### 7.4 窗口前必须就绪

- 全部训练/测试数据冻结，签名防泄漏检查通过，本文升级为 v1.0；
- 训练与评测脚本在小模型或少量 GPU 上跑通（若可行，窗口前申请几个 GPU 小时做冒烟，窗口内的 0–2 h 段即可省去）；
- 评测管线（编译、多实例、witness 电池）在 CPU 上对 A0 的零样本输出跑通。
