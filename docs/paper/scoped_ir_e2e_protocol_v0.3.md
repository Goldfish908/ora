# Scoped IR 端到端求解—审计—修复协议 v0.3

日期：2026-11-12 · 状态：真实初始生成前冻结；历史 validation 集成验证，不是 sealed/frozen 终验或 SOTA。

## 1. 目标与完成判据

将 scoped IR 从固定制品审计接入完整主链：

```text
NL 题面 → LLM 生成 PySCIPOpt 代码 → SCIP 求解
→ scoped IR 解级审计 → 违规证据反馈 → 修复并重新求解
→ NLP4LP 专家公式与公开目标值独立评分
```

至少 8 个历史 validation 问题完成真实端到端运行，保存全部制品；至少一个真实语义违规经反馈后重新求解。若没有自然违规，不通过人为注入来伪造完成。

## 2. 问题与信息隔离

预先固定 8 题：`016、021、047、055、058、060、104、229`。选择依据为标量 LP 结构、已有独立参考、覆盖资源约束、比率、目标重算和 makespan，不根据未来模型输出筛选。

- 使用历史 validation，不访问 sealed；
- 不使用这些问题的旧 checker、旧修复结果或公开最优值作为生成/修复输入；
- 公开目标值和专家公式只在最终评分时使用；
- 参考中的语义约定不自动视为无争议金标，冲突时单列。

## 3. 共享初始候选

所有臂共享同一份初始代码与 SCIP 结果，由 `scripts/m3_industryor.py --arm z0` 生成一次：

- 通用 SCIP 输出契约；
- 无工程/业务 memory；
- 必须导出 `solution.json`；
- 变量名使用对应 NLP4LP 参考 schema，保证独立公式可评分；
- 初始生成不运行 zero/text/scoped_ir 的解级检查。

## 4. 三臂

1. `zero`：自由 Python witness authoring + 通用执行反馈；
2. `text`：声明式文本经验 + 自由 Python witness authoring；
3. `scoped_ir`：受限 JSON 不变量 + DVSA 安全解释器 + 数值违规反馈。

每题每臂只生成一次检查资产，后续候选复用，不跨题写回。所有臂使用同一 Qwen3.8-27B、同一温度、最大 token 和最多两次修复调用（最多三个代码版本）。

## 5. 候选管理与反馈

- 初始代码崩溃、无目标值或缺 solution 时，优先使用通用执行反馈；
- `VIOLATED` 时，将规则、坐标、lhs/rhs/delta 和来源反馈给修复器；
- `UNKNOWN` 只表示未验证，不能当作违规，也不能宣称安全；
- 当前候选通过已编码检查才可接受；若后续候选引入违规，不覆盖先前已接受候选；
- 不允许用公开目标值或独立专家公式选择候选；
- 最终评分时另报初始/最终业务正确、改善、`harmed_win`、UNKNOWN、无效修复、调用、token 和延迟。

## 6. 独立评分

`scripts.nlp4lp_reference.audit` 复用 NLP4LP 专家模型与变量级审计，业务正确要求：

1. 返回解满足专家公式及变量域；
2. 目标值与公开答案绝对误差 ≤0.1。

这不等同于模型语义等价证明，参考冲突单独记录。初始与最终使用同一评分器版本。

## 7. 记录与停止规则

- 实现：`scripts/scoped_ir_e2e_data.py`、`scripts/scoped_ir_e2e.py`；
- 保存初始代码、每轮代码、SCIP 输出、检查资产、逐不变量结果、修复提示、响应和最终评分；
- 任一组件失败必须记录，不得把 UNKNOWN 或缺失制品算成功；
- 若 scoped IR 未减少误报/UNKNOWN，或修复主要产生新违规与无效输出，不扩量、不启动第二模型或 SOTA；
- 若至少一个真实违规被修复且未出现系统性 win 退化，才认为完整链路工程可行性成立；泛化结论仍需新开发域验证。
