# 代理信号放大与验证知识进化协议 v0.1

## 1. 核心命题与先行判据

研究对象不是“再做一个修复框架”，而是：非参数自进化在弱代理信号上是否会放大语义错误，以及验证知识的出处授权和层级接受能否抑制这种放大。

**必须先做放大曲线。** 如果 RetailOpt 上 GEPA/AlphaOPT 的代理匹配没有上升，或幻影没有随进化增加，则只能报告“代理指标静态高估正确性”，不能声称复现了进化放大。工程 guard 的小样本成本收益不用于替代该判据。

## 2. 官方方法与冻结版本

- GEPA：`https://github.com/gepa-ai/gepa`，commit `ce5b0d6e3d6af6c6dbec6de2c54536bbb961d309`。
- AlphaOPT：`https://github.com/Minw913/AlphaOPT`，commit `159ea58da557dbfe77f4d33afd78fd3a52d38ce4`。
- 任务与反射模型：Qwen3.8-27B。求解器：现有 PySCIPOpt/SCIP。
- 自写适配只负责数据、模型、执行和审计；不得把自写进化循环冒充官方 GEPA/AlphaOPT。

小规模冒烟只验证官方接口，不进入主曲线。主实验使用官方优化引擎、相同初始任务、模型、代理分数和预算；强 Witness 只用于落盘和事后分析，绝不进入基线臂的反射反馈。

## 3. RetailOpt 数据角色

沿用已有物理切片：

- dev40（F1-F4，v0+v4）：官方方法训练/经验学习；
- gapcheck60（F1-F4，v1/v2/v3）：逐代验证与方法内选择；
- F5-F8 heldout90：最终冻结评估，不参与候选、反射、调参或阈值修订。

已有 43→115 是单次修复环的层迁移证据，不等同于进化曲线。主曲线必须从官方方法的 seed 和后续候选重新计算。

## 4. 指标与分母

逐题逐候选记录：

- `executable`：代码执行成功且有可读取解；
- `proxy_match`：目标值等级为 `match` 或 `better_than_reference`；
- `true_correct`：独立 Witness `feasible` 且目标值合格；
- `phantom`：有可执行解但 Witness `infeasible`；
- `phantom_proxy`：`proxy_match` 且 Witness `infeasible`，是前者的子集；
- `true_success`、`phantom/executable`、`phantom_proxy/proxy_match`、可执行率和成本同时报告。

不将 UNKNOWN 当作安全，不将 objective match 当作业务正确。最终指标以每代全部候选输出重算，不能只汇报 oracle 或最好种子。

## 5. 两条通用规则

### R1：按出处授予否决权

所有新检查从 `hint_only` 开始。获得 `veto_enabled` 必须同时满足：

1. 有题面逐字依据，或有独立验证的惯例资产及注册哈希；
2. 在独立可信审计集上精确重放，至少 3 个干净样本和 3 个独立错误样本；
3. 干净误报为 0、precision≥1.0、错误检出≥0.6、UNKNOWN=0；
4. 检查代码哈希、父代、来源和审计记录全部落盘。

未达到只能作为提示，不能否决、不能接受修复、不能自称业务正确。退休后不得再参与否决。最终评测期注册表冻结，任何写入都报错。

### R2：按层级接受修复

层级固定为：L0 弱代理（目标值/原测试）、L1 执行与输出契约、L2 独立业务/增强测试。以某一层为目标的修复，只有所有已晋升的更高层检查结果逐项不变才可接受；缺失结果按拒绝处理。

这意味着低层修复导致高层 `pass→fail` 或 `fail→pass` 都被拒绝。高层 fail→pass 只能由显式以该高层为目标的修复完成。最终接受还要求所有已晋升检查通过，UNKNOWN 不是通过。规则过强导致无法修复是合法负结果，不临时放宽。

## 6. 对照与消融

- A0：官方 GEPA/AlphaOPT + 弱代理分数；
- A1：A0 + 仅 R1；
- A2：A0 + 仅 R2；
- A3：A0 + R1 + R2。

保持初始候选、训练题、模型和代理预算一致。报告逐代 A0 曲线、最终 A1/A2/A3 差分、paired win/loss、McNemar、可执行率和成本。若可信审计集或检查器覆盖率不足，明确报告，不通过扩大分母或移动阈值挽救。

## 7. 跨域

第二域优先 HumanEval/MBPP + EvalPlus：原始测试为弱代理，EvalPlus 增强测试为强参考，复用同一个授权与层级接受插件，不继承 OR 业务检查。

第三域评估 Text-to-SQL：执行结果匹配为弱代理，test-suite accuracy 为强参考。只有数据、官方评测和预算均可复现时才进入主表；否则明确列为未完成的阻塞项，不以模拟结果替代。

## 8. 结论边界

可信审计集只需要小规模，但其独立性和来源是主结论的一部分。固定 Witness 的既有覆盖不等于 Witness 已进化。所有新检查必须从 hint_only 开始并重新获得否决权。官方方法不同配置仅作参考，不宣称同条件复现其论文榜单或 SOTA。
