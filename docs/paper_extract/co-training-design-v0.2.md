## 3. v1 已被文献验证的设计（无需改动，写论文时引用为动机）

1. **LightGBM v0 + 表格特征**：Hendel et al.（2022）在 B&B 树大小预测上 RF 优于 GBDT/NN；Fischetti et al.（2019）RF/ExT 最优。万级样本 + CPU 分钟级重训的判断正确。
2. **删失纪律**（timeout 的 wall 是下界不是真值）：SATzilla 的 Schmee-Hahn 迭代处理的就是同一问题；你们的「分位数回归/独立超时分类头」是现代等价解。
3. **预算充分性/超时风险维**：CO-Bench 实证超时是 agent 系统的头号失败模式（Valid Solution 率仅 ~55%，主因超时与约束违反）——这个维度是 v1 的原创先见，文献后证。
4. **根节点探针特征（1-2s）**：与 SATzilla 的 DPLL 探测特征、Fischetti 的前 τ 段观测同构；算法选择文献中信息量最大的一组，判断正确。
5. **「快循环追慢循环」**：StepORLM 的 policy/critic 共进化、ACEvo 的逐代交替都是同构节奏；反向振荡的判断有文献支撑。
6. **Goodhart 锚定**（SEM 只作辅助整形、真实求解为锚、低置信回退实测）：与 Gao et al.（2022）reward model overoptimization 的防护建议一致。

## 4. 八项增量（v1.1 修订建议）

### A1. SEM 预测目标加「归一化层」【改 §4.1】

v1 现有目标（P(opt)、E[wall]、E[nodes]、E[gap]）保留，**新增两个相对量**：
- **后端对数成本比** log(cost_X / cost_B0) 与胜负分类——路由决策真正需要的是相对量；Hendel 的教训是绝对 runtime 方差大、SOTA 也只有 factor 2–3，相对量显著更好学；
- **归一化进度 γ(t)**（Hendel 形式，可选 v1）——为 CoBench 的 anytime 预算分配铺路。

### A2. SEM 数据协议显式补「反事实层」【改 §4.3】

v1 的落账只记录**实际决策**的结果 → 路由器训练数据存在 bandit 选择偏差（难实例都给了 B0，则「B2 在难题上的表现」在数据里不存在）。建议补两条：
- **定期重放配对**：W1 A/B 重放设施按周对新实例批次跑双后端配对，产出无偏校准集（这是你们相对全部文献的独有资产，论文里应单列为数据协议贡献）；
- **在线探索流**：约 5% 实例强制走非推荐后端，维持在线反事实数据。

### A3. 弃权信号三通道【改 §4.5 低置信回退】

把「低置信」从定性描述落成三个可计算信号（任一触发即回退 B0）：
1. **特征距离**： Hosny-Reda 式——实例嵌入与训练集 kNN 距离超阈（OOD 检测）；
2. **集成分歧**：SEM 用 K 个 LightGBM（不同 seed/子样本），预测分歧超阈；
3. **校准失效**：滚动窗口上预测胜率与实际胜率偏差超阈。

### A4. PEARL 训练配方四件套 → way2m-grpo 清单【新增 §6 附录】

PEARL（arXiv:2607.18256，GRPO + slime，4B 超 DeepSeek-V3.2-685B）的四个工程件直接入清单：
1. **观测 token loss masking**：工具返回（执行栈/solver 输出）不进 policy gradient——你们的多轮闭环轨迹必须加，否则优化的是「背诵 solver 日志」；
2. **轨迹过滤**：剔除截断与格式违规的负样本——**这正是你们 12/12 reasoning 爆炸在训练侧的镜像**：GRPO 下 response length 天然增长（PEARL 图 10c 实证），截断样本若当负样本训练会污染策略；PEARL 用 adaptive sampling 保证每题至少 K_min 条到达 solver 的有效轨迹；
3. **DAPO decoupled clipping**（按优势符号不对称裁剪）；
4. **batch 内 advantage 归一化**（应对求解结局的高方差）。

### A5. GRPO 门槛可达性更新【改 §6.2 门槛②的评估】

P5 的 12/12 reasoning 爆炸（反馈触发轮 100% finish_reason=length、零产出）曾被记录为「奖励真空区」。PEARL 证明这是**可训练修复的交互行为缺陷**：其核心 claim 正是「学会何时执行、何时修改、何时终止」——4B 模型经 agentic RL 后在同管线下从 22.20 → 69.71 macro 准确率，且 code/runtime 失败占比从 66.2% 降到 14.3%。**门槛②（反复的可验证失败）现已满足，且解法配方存在（A4）**。附带选项：直接以 pearl-4B checkpoint（GitHub: AuroraLHL/PEARL）为起点做成本感知继续训练，替代从 27B 冷启动——【新决策点】。

### A6. 成本感知奖励的空位最终确认【论文 motivation 素材】

逐家核对奖励函数：SIRL = 格式0.5+可执行1+正确2(+技巧1)；StepORLM = solver 硬标签 + GenPRM 过程偏好；**PEARL = 格式(0.1+0.2) + 正确性（目标值容差比对）**；FormuEvo = 成本为适应度但权重不动。**「求解成本进入可训练 LLM 的奖励函数」在 PEARL 之后依然是空位**——你们的差异化声明安全，且 PEARL 的交互训练与你们的成本整形**正交可叠加**（它训「怎么交互」，你们训「建模模得让下游好解」）。

### A7. L3 重设计：吸收 A 层封存理由【替换 v0.1 的 W-D】

v1 封存 A 层的理由（「质量排序先验在 LLM，浅层学习模型只承载 completion risk」）是对纯 learned value head 的有力反驳，v0.1 的 L3 方案与之冲突，**重新设计**：
- **分工**：LLM 保留质量排序（自评/生成式批评，OR-PRM 形态）；**SEM 承载成本与超时风险预测**——CO-Bench 的头号失败（超时）恰是 LLM 排不了的风险，正是 SEM 的本职；
- **形态**：CoBench 探针上的搜索引导 = BoN/MCTS，候选排序键 = LLM 质量分 × SEM 预测（P(预算内完成)、E[wall]），终端锚 = 官方 Evaluator 真实执行；
- **基线纪律**：必须含 LLM-as-judge（无 SEM）与纯 SEM（无 LLM 排序）两臂——若混合臂不赢，L3 回到封存，与 A 层纪律一致；
- 这样 L3 不与 A 层封存冲突：它不复活「浅层 value selector」，而是把 SEM 的系统层价值延伸到 CoBench 探针。

### A8. 对抗课程作为 C 层重进后的协议组件【新增 §5 附条】

PlanB&B 五条门控全满足、进入增量训练后，co-adaptation 的防塌缩协议（文献证据：StepORLM 记录共进化非单调退化 iter2 −4.4%；ACEvo 消融证明撤对抗压力 solver 即退化）：
- 攻击者在**现实性约束内**扰动实例分布（DRO 球，度量与半径待定），PAIRED 式 regret 信号把课程压在联合系统能力前沿；
- 冻结 OOD 探针套件 + 每轮交替后测双端退化，超预算即回滚；
- 攻击者胜场数据同步训练决策层的弃权判据（弃权边界的主动探测）。

## 5. 部署形态口径修正（论文 claim 前置纪律）

系统文档确认：**B2 = policy prior（无搜索），B3 = 一步 lookahead k=8（1 次批量 dynamics + 2 次 value），均非 PlanB&B 论文的完整 Gumbel Search agent（N=50 模拟/决策）**。含义：
- 论文中关于「learned branching 未赢 B0」的所有陈述，口径必须写成「amortized 部署形态下」，并注明完整 agent 的单决策税（50 sims）在你们的预算档下不可行——这反而是 L1 推理税论证的最强证据；
- P5 的 B2/B1 节点 0.63× 是 policy prior 的净搜索信号，这个表述反而更干净（不依赖搜索开销）。

## 6. CoBench 探针绿灯

确认公开工件：**CO-Bench**（arXiv:2504.04310，GitHub 开源，36 题/8 大类，10 秒/实例单核，agent 64 步预算）。文献现状：经典求解器基线 0.797，最佳单体 LLM 0.651，FunSearch 0.842 最高；超时主导失败。与 v1 §7 的探针设计（TaskAdapter + 官方 Evaluator + 求解器白名单）完全兼容，且「{scip, cp_sat, highs, heuristic}×预算档」的工具箱扩张正是 SEM 非平凡价值的兑现场景（§4.6 反方证据的解法）。建议升级状态：待定 → **排队（在 OptMATH 之前）**【决策点】。
