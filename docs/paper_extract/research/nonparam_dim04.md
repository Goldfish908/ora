# 进化出的 Agent 资产的跨数据集/跨域迁移 —— 技术调研报告

- **日期**：2026-08-29
- **委托背景**：自研 agent 系统（冻结 Qwen 27B，CO-Bench/JSSP 组合优化评测），用 (1+λ)+archive 进化 prompt patch。已实证两项关键弱点：(a) 进化资产是 **regime-specific** 的（编码了"30s/实例 + E=16 + tai 规模分布"这一资源包线）；(b) 发生过**假晋升**（PROMO 池 +0.069，locked holdout −0.160）。系统即将迁移到其他数据集（其他组合优化问题族、可能非 JSSP 域）。
- **调研方法**：9 轮共 24 个独立查询（中英混合，术语用英文），来源以 arXiv、OpenReview、ACL Anthology、GitHub、官方文档为主。证据强度分级：**强**（同行评审+直接实验）、**中**（预印本/单系统实验）、**弱**（博客/二手综述/类推）。

---

## TL;DR（给背景系统的直接结论）

1. **"A 基准进化、B 基准失效"已被多方独立复现为结构性现象**，而非个例：MAS 拓扑过拟合（ACL 2026 Findings）[^3^]、prompt 跨模型漂移（PromptBridge）[^2^]、LLM 启发式对设计实例过拟合（URS）[^6^]、代码进化 replay 配方不跨问题族（Cozzuto 学位论文）[^7^]。你们的 PROMO+0.069/holdout−0.160 与文献中的失败模式同型。
2. **成功迁移的共同特征是"迁移的是框架/组合/元技能，而不是单点冠军资产"**：ReVEL 同默认配置跨 TSP/BPP/CVRP[^20^]、EoH-S 迁移"启发式集合"[^18^]、Voyager 迁移整个技能库[^5^]、EvoSkill 迁移带触发条件的 skill 包[^4^]。单点 patch 直接迁移的证据几乎全是负面的。
3. **最贴合你们 (1+λ)+archive 架构的三条方法论**：(i) 把 archive 从"冠军池"改造成 **per-instance 组合 + 选择器**（SATzilla 范式[^22^]，GEPA 的 per-instance Pareto front[^8^]，DSevolve 的 MAP-Elites 调度规则组合[^13^]）；(ii) 给每个资产打**环境/regime 元数据**（Model Cards/Datasheets 范式[^24^] + POET 的 PATA-EC 环境特征化[^10^]），换 regime 自动降级为 challenger，用 **shadow/champion-challenger 协议低成本再晋升**[^25^]；(iii) 迁移时做 **warm-start 而非直接部署**（AutoML 的 prior-decay warm-start[^23^]、POET 的 proposal transfer[^9^]）。
4. **评测治理上**，locked holdout 必须升级为**滚动/时间窗 holdout**（LiveBench/LiveCodeBench 模式[^26^][^27^]），并对 PROMO 池与 holdout 做**防同源污染**处理；假晋升的根因——"用同一分布的验证集做晋升判据"——正是文献反复警告的 "HPO helps val, hurts test"[^29^]。

## 1. 跨任务迁移实证：成功/失败模式

### 1.1 失败模式（与背景系统同型的证据）

**M1. 拓扑/结构过拟合（topological overfitting）—— MAS 层面**
- 来源：So, Jang & Kim, "Superficial Success vs. Internal Breakdown: An Empirical Study of Generalization in Adaptive Multi-Agent Systems", ACL 2026 Findings[^3^]。
- 核心证据：对自适应多智能体系统的系统实证发现两类失败——"(1) topological overfitting—they fail to generalize across different domains; and (2) illusory coordination—they achieve reasonable surface-level accuracy while the underlying agent interactions diverge from ideal MAS behavior"[^3^]。
- 与背景系统的关系：你们的 PROMO 池 +0.069 而 locked holdout −0.160，正是"表面成功 vs. 内部失效"的单 agent 版本——晋升判据只看了优化分布内的表面指标。
- 证据强度：**强**（ACL Findings，跨多个 MAS 系统的对照实验）。

**M2. Prompt/优化资产的 regime 漂移（model drifting / task drifting）**
- 来源：PromptBridge, arXiv:2512.01420（2025-12-01）[^2^]。
- 核心证据："Prompts engineered or optimized for a source model frequently underperform when applied to a target model"——HumanEval 上 GPT-5 最优 prompt 99.39% 迁到 Llama-3.1-70B 只剩 68.70%（其自身最优 79.47%）；同族不同规模间漂移可达 "50–70% relative loss on xCodeEval"[^2^]。
- 重要旁证：AFlow（ICLR 2025）Table 2 声称跨 executor 有强迁移性（HumanEval 上 GPT-4o-mini 进化的 workflow 迁移到 DeepSeek-V2.5 得 94.7 vs 90.8）[^1^]——即**迁移有时成功**，但 PromptBridge 的对角线-非对角线系统实验表明这不可外推为普遍规律。结论应是"迁移性本身是一个需要测量的随机变量，不是默认属性"。
- 对背景系统：模型冻结（Qwen 27B）消除了 model drifting，但**数据集/regime 漂移是同构现象**——prompt patch 编码了评测分布特征。
- 证据强度：**中**（预印本，但实验矩阵系统：7 模型 × 8 基准）。

**M3. LLM 进化启发式对"设计实例集"过拟合**
- 来源：URS（VRP 求解），arXiv:2509.23413[^6^]。
- 原文："the heuristics generated by the LLM are susceptible to overfitting to the specific instances used during the design phase, limiting their generalization capabilities"[^6^]。
- 这是对 FunSearch/EoH/ReEvo 系方法的直接批评：适应度函数只在进化期实例集上计算，资产编码了该实例集的特征——与你们"tai 规模分布 + 30s/实例 + E=16 资源包线被编码进 patch"完全同构。
- 证据强度：**中**（预印本，但与 M1/M4 独立互证）。

**M4. 代码进化资产的 replay 配方不跨问题族**
- 来源：Cozzuto, "Capability-Bounded Code Evolution with Large Language Models"（学位论文，ubishops.ca PDF）[^7^]。
- 核心证据：TSP/ATSP/CVRP 三族上系统测试代码进化循环，结论 "novelty spikes are often unreliable, replay effects are family-dependent, and no single replay recipe dominates TSP, ATSP, and CVRP"；"The replay mechanism does not transfer as a default rule from TSP to CVRP"；"Archive curation is more important than archive size or raw failure accumulation"[^7^]。
- 对背景系统：**最直接的方法论警告**——(1+λ)+archive 的进化动力学参数本身也是 regime-specific 资产，跨问题族时不能假设迁移。
- 证据强度：**中**（学位论文，750 个 task×model×technique 单元格、20 paired offsets，实验纪律严谨）。

### 1.2 成功模式（可迁移的是什么）

**S1. 迁移"框架+默认配置"而非单点资产**：ReVEL（arXiv:2604.04940）在 CVRP 上"uses the same default configuration without problem-specific tuning"，全尺度优于 ReEvo[^20^]；ReEvo 本身跨 5 类算法形态、6 个 COP、白盒/黑盒设定均有效[^19^]。**框架级方法（反思机制、进化算子）比具体启发式更跨域**。

**S2. 迁移"组合/集合"而非冠军**：EoH-S 进化整个启发式集合（heuristic set），训练用 10–200 节点、测试 50–500 节点仍保持最优 gap[^18^]；EoH 原版在训练分布（均匀随机）之外测试 TSPLib 真实实例保持优势，而神经求解器退化[^17^]。

**S3. 迁移"带触发条件的封装技能"**：Voyager 技能库（代码技能+语义索引）不仅跨新世界零样本有效，还能即插即用增强 AutoGPT（0/3 → 1–2/3）[^5^]；EvoSkill（arXiv:2603.02766）报告"skills are structured as self-contained folders with explicit trigger conditions … decoupled from both the training task and the underlying model"，SealQA 上进化的 search-persistence skill 零样本迁到 BrowseComp +5.3pp[^4^]。其原文判断值得引用："skill-level optimization may offer a more natural unit of transfer than prompt-level or code-level optimization"[^4^]——**对你们而言意味着：把 prompt patch 封装成"触发条件 + 适用 regime 声明 + 验证状态"的 skill 包，比裸 patch 更适合迁移**。

**S4. 跨问题族迁移（离散→连续）的罕见正例**：Hierarchical Representations for Cross-task Automated Algorithm Design（OpenReview, 2025-09）"successfully transferred metaheuristics evolved on combinatorial problems (TSP/CVRP/FSSP) to a continuous Black-Box Optimization algorithm"[^21^]——关键在**层次化/抽象表示**（迁移骨架而非具体参数）。

**模式总结**：失败 = 迁移在单一 regime 下优化到头的标量冠军；成功 = 迁移多样性集合、抽象骨架、元技能、或带显式适用条件声明的封装资产。

## 2. 多环境进化的方法论

**M-E1. POET：环境-资产配对共进化 + 定期迁移实验**
- 来源：Wang et al., arXiv:1901.01753（2019-01）+ Uber 官方博客[^9^]。
- 机制：维持环境-智能体一一配对的种群 {(E_i, θ_i)}；大部分时间在本环境内优化；**周期性做 transfer attempts——direct transfer（直接搬到目标环境评估）与 proposal transfer（先在目标环境做一步优化再评估），只有迁移体优于目标环境现任者才替换**[^9^]。
- 对背景系统的映射：把"数据集/问题族"当环境，archive 资产当配对智能体；迁移不靠假设而靠**周期性、低成本的迁移锦标赛**。proposal transfer 就是"warm-start 一步再裁决"——直接回应"低成本再晋升协议"。
- 证据强度：**强**（PMLR/ Uber 系列工作，被引上千）；在 LLM prompt 进化中的直接应用**未查到**，属可复用范式。

**M-E2. Enhanced POET 的 PATA-EC：环境特征化（environment characterization）**
- 来源：Wang et al., Enhanced POET, PMLR v119[^10^]。
- 机制：用"domain-general characterization of key attributes of an environment"计算环境间距离，驱动新颖性排名与迁移决策[^10^]。
- 对背景系统：这就是"给 regime 打元数据"的算法化先例——对 JSSP 实例可计算规模/机器数/加工时间分布等特征向量，资产迁移优先级按 regime 距离排序。
- 证据强度：**强**（方法论层面）。

**M-E3. MAP-Elites / QD 档案：把 archive 从"冠军列表"变成"行为维度索引的组合"**
- 来源：MAP-Elites（Mouret & Clune 2015）在 LLM 进化中的多个实例：LLMatic（arXiv:2306.01102，双档案——网络档案 + prompt 档案）[^13a^]；**DSevolve（arXiv:2603.27628，2026-07）——与你们场景最贴近：动态柔性作业车间（dynamic FJSP）上用 MAP-Elites 进化调度规则组合，行为描述符 = 机器负载不均衡、平均等待比、相对档案的行为新颖度，fitness = 参考实例集上的平均 makespan**[^13^]。
- 机制价值：(i) QD 档案天然保存"不同行为 regime 下的最优资产"，部署时按当前环境的行为坐标选 cell——**这正是 regime-specific 资产的正确组织方式**（不是消灭 regime-specificity，而是索引它）；(ii) 行为描述符可换用"任务族特征"。
- 证据强度：**中-强**（DSevolve 直接面向 scheduling；LLMatic 为 AAAI）。

**M-E4. 多任务/多分布训练方案（domain randomization 的 LLM-AHD 类比）**
- MoH（启发式的元优化，arXiv:2505.20881）：明确批评"单任务训练方案阻碍所生成启发式的泛化能力"，采用**多任务训练方案**让 LLM 进化"元优化器"，跨规模设置 SOTA[^14^]。
- M²GenCO（ICML 2026）：**"Problem Distributions as Tasks"**——把不同问题分布（甚至不同问题类型）作为元学习任务做联合预训练 + support/query 快速适配，建 5 个 COP × 多规模 × 多分布 = 38 个测试集的泛化基准[^15^]。
- NCO 文献中的成熟做法（经 EoH-S/M²GenCO 综述确认）：多分布同时训练、group DRO（Jiang et al. 2022）、多教师蒸馏 AMDKD（Bi et al. 2022）、子策略集成[^15a^]。RL 侧的 domain randomization 实证（VLA Sim2Real 研究）显示空间维度随机化 + RL 组合把真实成功率从 5.6% 提到 42.8%[^16^]；PAIRED（Dennis et al. 2020）的对抗式环境生成课程产生的 agent 泛化优于 Domain Randomization 基线[^12^]。
- **对背景系统的判断**：把 fitness 从"tai 实例集上的均值"改为"多问题族 × 多规模 × 多时间预算的混合分布上的加权/最差组（group-DRO 式）目标"，是消除"30s/E=16/tai 包线编码"的根本手段；低成本版本是每代从分布混合中重采样 minibatch（domain randomization 的进化版）。
- 证据强度：**强**（NCO 侧多篇 ICML/NeurIPS；LLM-AHD 侧 MoH 为预印本）。

**M-E5. OMNI-EPIC：用基础模型自动生成"可学且有趣"的新环境/任务**
- 来源：ICLR 2025[^11^]。机制：FM 生成代码化环境+奖励函数，按 learnability（不太难不太易）+ interestingness 筛选。
- 对背景系统：可用于**自动生成 holdout 的变体分布**（扰动 tai 实例的规模/加工时间分布生成新 regime），支撑第 5 节的滚动评测。
- 证据强度：**中**。

## 3. 资产元数据与再验证协议

**A1. 资产文档化范式：Model Cards / Datasheets**
- 来源：Mitchell et al. 2019（arXiv:1810.03993）、Gebru et al. 2018/2021（arXiv:1803.09010）[^24^]。
- 机制：为模型/数据集强制记录 intended use、评测条件、适用外（out-of-scope）用途、分组性能。后续工作（Human-aligned AI Model Cards, arXiv:2510.06989）已把这些模板参数化为 217 个机器可读字段[^24a^]。
- 对背景系统：**给每个进化 patch 附带 "asset card"**：发现时环境指纹（数据集、规模分布、时间预算、E、适应度定义）、晋升判据与验证历史、已知适用外条件。换 regime 时卡片自动标记失效域。
- 证据强度：**强**（治理范式，FAccT/CACM）；在"进化 prompt 资产"上的直接应用**未查到**——属可复用先例而非现成方案。

**A2. Champion/Challenger + Shadow 部署：换环境自动降级 + 低成本再晋升**
- 来源：MLOps 实践（DataRobot champion/challenger 文档；Atlan shadow deployment 指南；模型风险管理 SR 11-7 系）[^25^]。
- 机制：challenger 与 champion 并行处理相同流量但不服务用户（shadow）；输出对比驱动晋升闸门；晋升分阶段（shadow → canary 10%→25%→50%→100%）；**监控+按风险等级定期再验证（revalidation cadence），漂移检测先于客户发现**[^25^]。
- 对背景系统的映射（最直接可落地）：新 regime 下所有旧资产自动降为 challenger；用小规模 shadow 评测（少量实例、不计入正式成绩）与当前 champion（可以是"无 patch 基线"）对比；达到门槛才再晋升。这精确对应你们"资产自动降级为待验证 + 低成本再晋升"的需求。
- 证据强度：**中**（工业最佳实践，非学术论文，但高度成熟）。

**A3. AutoML warm-start 元学习：先验衰减式迁移**
- 来源：auto-sktime（arXiv:2312.08528）——"automatically extract priors from historic experiments"做全自动 warm-start；Hvarfner et al. 2022 的 πBO——把用户/历史先验 π 以 π(λ)^{β/n} 形式注入采集函数，**随优化进行指数衰减，且证明了不损害 BO 最坏收敛率**[^23^]；XAutoLM（EMNLP 2025）把 warm-start prior 参数化（距离类型、效用方案、衰减因子、拉取上限）[^23a^]。
- 机制价值：**旧 regime 资产不直接部署，而作为新 regime 进化的初始种群/先验，并带衰减**——假晋升风险由"先验可被数据推翻"结构性兜底。对 (1+λ)+archive：旧 archive 整体作为新 run 的初始种群，但晋升判据只认新 regime 数据。
- 证据强度：**强**（AutoML 成熟文献）。

**A4. Per-instance 算法选择：regime-specificity 的制度化利用**
- 来源：SATzilla（arXiv:1111.2249）[^22^]。
- 机制："no single dominant solver; different solvers perform best on different instances"——用实例特征 + 经验硬度模型**在线逐实例选择求解器**，2007 SAT 竞赛 3 金[^22^]。
- 对背景系统：与 M-E3 互补——不要追求一个跨 regime 的通用 patch，而是**保留 regime-specific 资产组合 + 轻量选择器**（实例特征→patch）。迁移到新数据集时，只需重建选择器/特征映射，资产本体作为候选池 warm-start。
- 证据强度：**强**。

**A5. 评测侧的晋升防过拟合机制（可直接并入再验证协议）**
- GEPA 的工程实现把样本分为不相交的 D_pareto（固定验证集，所有候选公平打分）与 D_feedback（变异反馈 minibatch），"This train/validation split is fundamental to avoiding overfitting—prompts are mutated based on feedback goldens but selected based on held-out validation performance"[^8a^]；GEPA 本体用 **per-instance Pareto front** 维持多样性（"stochastically explores the top-performing prompts for each problem instance … enables robust generalization"）[^8^]。
- ProAPO（CVPR 2025）在进化适应度中加**熵约束**以缓解对训练信号的过拟合[^30^]。
- 对背景系统：晋升判据 = 固定 locked 子集（D_pareto 角色）+ 周期性轮换；变异反馈只用 PROMO 池（D_feedback 角色），两池永不混用——你们已有 PROMO/locked 二分，缺的是**locked 池的轮换与规模下限**（见第 5 节）。

## 4. 组合优化领域的跨问题族泛化（JSSP → TSP/CVRP 等）

**C1. 同族内跨规模/跨分布：成功案例多**
- EoH：训练均匀分布、测试 TSPLib 真实实例仍优于神经方法；FSSP 上 Taillard 实例 0.23% gap；仅 ~2000 次 LLM 查询（FunSearch 约 1M）[^17^]。
- EoH-S：训练 10–200 节点、测试 50–500 节点，TSP gap 比次优降 50–60%[^18^]。
- Starjob（JSSP 专用，arXiv:2503.01877）：LLM 调度在 Tai 与 DMU 两个 JSSP 基准上评测，1000 节点大图上有泛化声明[^32^]——**JSSP 域内跨基准（tai→DMU）是可行的最近迁移台阶**，建议作为你们迁移的第一站。

**C2. 跨问题族（TSP→PCTSP/OP，离散→连续）：需要显式适配机制**
- DIFU-Ada（arXiv:2502.12188，AAAI 2026）：TSP 上训练的扩散求解器**零样本**迁到 PCTSP/OP——机制是推理时适配（能量引导采样 + 递归退噪-去噪），PCTSP-20 gap 19.21%→4.20%；并给出理论：当惩罚 ≥ 边际减量时 PCTSP 与 TSP 共享最优 tour（结构相似性定理）[^16a^]。
- 层级表示跨任务 AAD：TSP/CVRP/FSSP 进化的元启发式迁到连续 BBO[^21^]。
- 反面证据：Cozzuto——replay 机制不作为默认规则从 TSP 迁到 CVRP[^7^]；URS——LLM 启发式过拟合设计实例[^6^]。
- **规律**：跨族迁移成功 ≈ (a) 问题间存在可刻画的结构相似性（共享子结构/目标分解），且 (b) 迁移时带轻量适配（推理时引导、一步优化、warm-start）；裸迁移（direct transfer）证据以负面为主。这正好印证 POET 的 direct vs. proposal transfer 区分[^9^]。

**C3. 对"JSSP → 其他问题族"的具体判断**
- JSSP（析取图/调度结构）与 TSP/CVRP（路由结构）的启发式表示接口不同（select_next_node vs. dispatching priority），**裸 patch/heuristic 迁移预期失败**；可迁移的是：(i) 进化方法论与反思/算子模板（ReEvo/ReVEL 的通用性[^19^][^20^]）；(ii) 抽象骨架（层级表示[^21^]）；(iii) 资产组合管理协议（本报告第 3 节）。
- 对"可能非 JSSP 域"：先在 JSSP 域内做 tai→DMU→其他规模分布的**域内迁移阶梯**验证协议有效性，再跨族。DSevolve 的动态 FJSP 是 JSSP 的自然近邻扩展[^13^]。

## 5. 防止"基准过拟合"的评测治理

**G1. 滚动/时间窗 holdout（LiveBench / LiveCodeBench 模式）**
- LiveBench（arXiv:2406.19314，ICLR 2025 Spotlight）：每月更换约 1/6 题目、约 6 个月全量翻新、最新题目延迟公开；同行评审版标题特意用 "contamination-limited" 而非 "contamination-free"[^26^]。
- LiveCodeBench（arXiv:2403.07974）：持续从 LeetCode/AtCoder/CodeForces 竞赛收集新题，**按发布日期开窗——只用模型训练截止之后发布的题目评分**，从设计上关闭污染窗口[^27^]。
- 对背景系统：进化系统对固定 holdout 的"过拟合压力"与预训练污染同构——**locked holdout 若长期不变，archive 进化会通过 PROMO 池与 holdout 的相关性间接适应它**（你们的 −0.160 说明 holdout 目前还有效，应趁有效时建立轮换制度）。建议：locked holdout 按季度从新生成的实例分布（OMNI-EPIC 式扰动生成[^11^]）轮换 1/N，旧 holdout 降级为 PROMO 池；保留"发布日期晚于最近一轮进化"的时间窗子集作为最终裁判。
- 证据强度：**强**（治理范式）。

**G2. 防 Goodhart 的评测纪律**
- 工程界总结（K-Dense AGENTS.md 故障排查手册）："HPO helps val, hurts test → Overfitting the validation set → Nested CV; fresh val; reduce search space"；"Public benchmark SOTA, private eval flat → Pretraining contamination → new held-out set"；"Test-set peeking via 'error analysis'"被列为特征性反模式[^29^]。
- 中文综述（SECA 自进化编程智能体综述解读，2026-08-04）："基准过拟合是个结构性风险。自进化系统的选择压力来自基准，那它进化出的东西天然倾向于讨好基准……评估必须测试能力能否迁移到 held-out 仓库、新基准、不同模型、不同语言"[^28^]。
- 对背景系统：晋升判据除"locked holdout 均值"外，应加**跨 regime 一致性门槛**（至少在 k 个不同 regime 上不退化超过 ε）——把"假晋升"从靠运气发现变成结构性不可能。

**G3. 对进化系统的适用性总评**
- Live 模式直接适用于"晋升裁判"层；对"日常适应度"层成本过高——日常用 PROMO 池 + minibatch 重采样（domain randomization 式[^16^]），晋升用轮换 locked holdout + shadow 协议[^25^]，三层成本递增、防过拟合强度递增。

## 7. 未查到 / 负结果声明

1. **未查到**"进化 prompt 资产在换环境后自动降级为待验证"的现成学术协议——最接近的是 MLOps 的 champion/challenger + 定期再验证[^25^] 与 AutoML warm-start 先验[^23^]，本报告第 3 节的方案是两者的组合迁移。
2. **未查到** domain randomization 在 LLM prompt/agent 进化中的直接命名实践；实质等价物是多分布/multi-task fitness（MoH[^14^]、M²GenCO[^15^]、NCO 多分布训练[^15a^]）与开放式环境共进化（POET/PAIRED[^9^][^12^]）。
3. **未查到** 针对 "(1+λ)+archive 进化 prompt patch 用于组合优化评测" 这一精确设定的迁移研究；最近的邻接证据是 Cozzuto 的代码进化跨族实验[^7^] 与 DSevolve 的调度规则 QD 档案[^13^]。
4. AFlow Table 2 的"强迁移性"声明[^1^] 与 PromptBridge 的 model drifting 证据[^2^] 存在张力；本报告采信后者的方法论（系统对角线实验），前者视为"迁移可能成功的存在性证明"而非普遍规律。
