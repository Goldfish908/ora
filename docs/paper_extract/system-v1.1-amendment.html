2. GRPO 双轨方案

2.1 双轨定义

GRPO 双轨对比
Track 1（先行）Track 2（条件启动）
起点pearl-4B checkpoint（AuroraLHL/PEARL）Qwen3.8-27B + LoRA
前置状态交互行为已修复（code/runtime 失败占比 66.2%→14.3%）P5 记录的 12/12 reasoning 爆炸未修复
成本项可直接叠加交互修复门槛未过前禁止加成本项
解锁条件立即可启动code-output 率 > 90%（连续两个 eval 窗口）

Track 2 的硬性顺序：先用 PEARL 四件套（见 2.3 节）修复交互行为（学会何时执行、何时修改、何时终止），过 >90% code-output 门槛后才允许叠加成本整形。理由：在奖励真空区（截断轨迹）上加成本项，优化的是「尽快截断」而非「建得更好」。

2.2 奖励函数

r = 0.3·r_format + 1.0·r_exec + 2.0·r_correct + λ·1{r_correct}·cost_shaping cost_shaping = clip(log(cost_B0 / cost_this), −2, +2)
  • 成本项仅在 r_correct = 1 时激活：防止「错误但快」的奖励黑客（StepORLM 记录过「错误约束恰好最优」的结局奖励黑客案例）。
  • λ 课程：0 → 0.2，随 KL 监控课程式递增；初值 0.2 为终点而非起点。
  • cost 默认取 wall-clock；nodes 作为辅助报告指标。

2.3 PEARL 四件套配置（两轨共用）

  1. 观测 token loss masking：执行栈 / solver 输出不进 policy gradient；
  2. 轨迹过滤：剔除截断与格式违规的负样本；adaptive sampling 保证每题至少 K_min 条到达 solver 的有效轨迹；
  3. DAPO decoupled clipping：按优势符号不对称裁剪；
  4. batch 内 advantage 归一化：应对求解结局的高方差。

2.4 Goodhart 监控（每 50 步）

监控项：KL 散度、response length 分布、cost_shaping 分布、r_correct 率、code-output 率。任一超阈 → λ 降档或早停。SEM 只作辅助整形，真实求解为锚（v1 §6.2 锚定不变）。

2.5 验收（2×2，预注册）

设计：{track 1, track 2} × {λ = 0, λ = 0.2} 四臂；配对 Wilcoxon 符号秩检验，p < 0.05。接受标准：正确率不降（非劣）且求解成本显著降。阴性结果同等交付。
