## 1. SEM v1.1 规格

### 1.1 特征 schema（五层）

| 层 | 内容 | 采集时机 | 说明 |
|---|---|---|---|
| L1 静态特征 | 变量数、约束数、非零元数、整数/二进制占比、约束类型直方图、系数统计量 | 读 LP 后 | 零成本，全部实例可采 |
| L2 根节点探针特征 | root LP 目标值、root gap、cuts 数量、伪成本统计、早期树信号 | 根节点后 1–2 s | 信息量最大的一层（SATzilla/Fischetti 谱系共识） |
| L3 来源特征 | 实例家族、生成器参数族、seed 族标识 | 落账时 | 支撑 instance-level 划分与 OOD 检测 |
| L4 预算特征 | 预算档位（wall/node 上限） | 路由时 | 与标签的删失标记联动 |
| L5 预算充分性/超时风险维 | 预算 vs 预测难度的相对位置 | 路由时 | v1 原创维，CoBench 后证其价值 |

### 1.2 标签 schema（v1.1 新增字段加粗）

| 字段 | 类型 | 说明 |
|---|---|---|
| solved / wall / nodes / gap | 数值/布尔 | v1 已有；timeout 时 wall 为下界（删失纪律不变） |
| **log_cost_ratio_vs_B0** | 浮点 | log(cost_X / cost_B0)，路由决策真正需要的相对量（A1） |
| **win_vs_B0** | 布尔 | 该后端在该实例上是否胜 B0（A1） |
| **pair_id** | 字符串 | 反事实配对标识；同一实例跨后端的配对行共享 pair_id（A2） |
| **source** | 枚举 | online / replay / explore，三层数据协议（A2） |

### 1.3 三层数据协议

| source | 机制 | 比例/频率 | 用途 |
|---|---|---|---|
| online | 路由器实际决策的结果落账 | ~95% 流量 | 主训练数据 |
| replay | W1 A/B 重放设施对新实例批次跑双后端配对 | 每周一次 | 无偏校准集；消除 bandit 选择偏差；本系统独有数据资产 |
| explore | 强制走非推荐后端 | ~5% 流量 | 在线反事实数据，维持边界探测 |

### 1.4 弃权三通道（任一触发即回退 B0）

| 通道 | 信号 | 阈值（初值） | 文献依据 |
|---|---|---|---|
| ch1 特征距离 | 实例嵌入与训练集 kNN 距离 | > p99 分位 | Hosny & Reda 2024 |
| ch2 集成分歧 | K=5 个 LightGBM（不同 seed/子样本）预测 std | 超阈（按验证集定） | 集成不确定性惯例 |
| ch3 校准失效 | 滚动 200-run 窗口上预测胜率 vs 实际胜率的 ECE | > 0.05 | 校准文献惯例 |

纪律不变：**弃权是正常行为，不是失败**；弃权日志单独落账，进入论文数据协议贡献。

### 1.5 MVP 验收门槛（预注册）

| 指标 | 门槛 |
|---|---|
| router regret（vs 事后最优单后端） | < 5% |
| 预测成本排序 vs 实际排序 Spearman | > 0.8 |
| 校准 ECE | < 0.05 |
| 弃权 recall（该弃权的实例被拦下比例） | > 90% |
| false-release（弃权后实际 B2 更优的比例） | < 2% |

## 2. GRPO 双轨方案

### 2.1 双轨定义

| | Track 1（先行） | Track 2（条件启动） |
|---|---|---|
| 起点 | pearl-4B checkpoint（AuroraLHL/PEARL） | Qwen3.8-27B + LoRA |
| 前置状态 | 交互行为已修复（code/runtime 失败占比 66.2%→14.3%） | P5 记录的 12/12 reasoning 爆炸未修复 |
| 成本项 | 可直接叠加 | **交互修复门槛未过前禁止加成本项** |
| 解锁条件 | 立即可启动 | code-output 率 > 90%（连续两个 eval 窗口） |

Track 2 的硬性顺序：先用 PEARL 四件套（§2.3）修复交互行为（学会何时执行、何时修改、何时终止），过 >90% code-output 门槛后才允许叠加成本整形。理由：在奖励真空区（截断轨迹）上加成本项，优化的是「尽快截断」而非「建得更好」。

### 2.2 奖励函数

```
r = 0.3·r_format + 1.0·r_exec + 2.0·r_correct + λ·1{r_correct}·cost_shaping
cost_shaping = clip(log(cost_B0 / cost_this), −2, +2)
```

- **成本项仅在 r_correct = 1 时激活**：防止「错误但快」的奖励黑客（StepORLM 记录过「错误约束恰好最优」的结局奖励黑客案例）。
- **λ 课程**：0 → 0.2，随 KL 监控课程式递增；初值 0.2 为终点而非起点。
- cost 默认取 wall-clock；nodes 作为辅助报告指标。

### 2.3 PEARL 四件套配置（两轨共用）

1. **观测 token loss masking**：执行栈/solver 输出不进 policy gradient；
2. **轨迹过滤**：剔除截断与格式违规的负样本；adaptive sampling 保证每题至少 K_min 条到达 solver 的有效轨迹；
3. **DAPO decoupled clipping**：按优势符号不对称裁剪；
4. **batch 内 advantage 归一化**：应对求解结局的高方差。

### 2.4 Goodhart 监控（每 50 步）

监控项：KL 散度、response length 分布、cost_shaping 分布、r_correct 率、code-output 率。任一超阈 → λ 降档或早停。SEM 只作辅助整形，真实求解为锚（v1 §6.2 锚定不变）。

### 2.5 验收（2×2，预注册）

设计：{track 1, track 2} × {λ = 0, λ = 0.2} 四臂；配对 Wilcoxon 符号秩检验，p < 0.05。
接受标准：**正确率不降（非劣）且求解成本显著降**。阴性结果同等交付。
