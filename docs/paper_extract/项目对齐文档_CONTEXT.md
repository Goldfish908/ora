# 项目上下文与决策原则（CONTEXT.md）

> 本文件是项目的最高优先级对齐文档。任何任务 prompt 未覆盖的情况，按本文件原则裁决；
> 本文件与任务 prompt 冲突时，以上报裁决为准，不自行取舍。
> 维护：每个阶段闸门更新一次，变更升版本号 + ledger 落账。当前 v1.0（2026-08-18）。

## 1. 最终目标（一句话）

构建**面向供应链与工业制造组合优化的求解过程 World Model**：给定搜索状态与候选动作，
预测真实求解环境的评价后果，并用它改善真实评价预算的使用效率。

**CO-Bench 只是第一个低成本试验场**，不是最终产品，不是竞赛榜单，不得围绕它无限精雕工程。
后续会接入更复杂的数据集与领域问题（FJSP、VRP 变体、库存—运输协同等）。

## 2. 证据主线（所有工作必须能对号入座到其中一环）

```text
A0 最小可信闭环 → 轨迹数据（可训练、有覆盖） → B0 探针（信号存在性）
→ A+B 在线验证（同真实预算下 A+B 优于 A） → D0 领域迁移
```

各阶段回答的问题：
- A0：数据可信吗？
- A1：Agent 能产生有效且有覆盖的候选吗？
- B0：能预测候选修改的后果吗？
- A+B：这种预测能改善规划吗？
- D0：这是供应链/制造方向真正需要的 World Model 吗？

## 3. 核心定位约定

- **B0 是 E 的学习型代理与前置筛选器，不是 E 的替代者**。E（真实求解环境）永远是标签来源与最终裁决者。
- **harness（miniloop + co-bench-env-mcp + 协议）是研究对象和测量仪器**，模型只是填料。
  提升 harness 的机制才是研究贡献；"换更强的模型"不是。
- **轨迹数据的使命是训练 B0**，不是只服务于臂间排名。失败、不可行、超时、近零改进的候选
  与成功候选同等重要——任何人不得以"提高数据质量"为由过滤或删除它们。

## 6. 决策原则（遇到没写过的情况，按此裁决）

1. **单一变量**：臂间对比只允许 harness 结构一个变量。模型配置（含推理强度）必须全臂统一。
   官方先例：CO-Bench 论文用 o3-mini-medium，推理强度本身就是固定配置。
2. **两级实验**：探索实验（少实例少重复，快速淘汰方向）与结论实验（固定数据、足够重复、
   严格统计）分开。只有准备采信进主线的结论才值得结论实验的成本。
3. **双基线**：iterative-v0.2 为永久固定锚点，不可删改；"当前冠军"可动态升级。
   打赢换的是冠军，不是锚点。
4. **瓶颈触发**：memory / skill / 参数化训练（SFT/RL）不排固定阶段，由数据暴露的瓶颈触发。
   不得为"路线完整"提前建设用不到的系统。
5. **评价轴以真实环境预算为准**：真实评价次数、累计评价时间、Best@E-budget、搜索曲线 AUC 为主指标；
   token、LLM 调用次数、墙钟只是辅助成本指标。不同臂的"一步"不可直接比较。
6. **数据划分防泄漏**：transition 级随机切分永远错误；按 run / instance / problem_class 分组。
   测试集永远 natural-only；增强数据（b0_augment）只进训练集并继承源 split。
7. **未来信息隔离**：任何输入特征必须能用 as_of_seq=t 重构；标 derived_from_future 的字段只能作标签。
8. **数据集无关性**：核心六层抽象 ProblemSpec / SearchState / Candidate / Executor / Outcome /
   TransitionRecord。miniloop 与通用 schema 禁止 import CO-Bench 专属模块；
   CO-Bench 的 code/diff 是 adapter 扩展字段，不是通用必选字段。

## 7. 红线（全程有效，无例外）

- 凭证只走环境变量；run_token 只存 hash 不进 trace 明文；
- 不 commit / 不 push（除非明确授权）；vendor/CO-Bench 数据只读不改（题目有问题走剔除机制）；
- raw/ 只追加不重写；已落账 run 的原始数据永不修改；
- 配置变更走 propose → 验证 → 人工批准；指标语义变更升版本落账；
- 测试产物 RUN_MARK 前缀 + purpose 标记，防污染训练集；
- 不动 s142 宿主机任何无关进程。

## 8. 必须上报裁决的情形（不得自行决定）

- 任何影响臂间可比性的口径变更（如某臂单独改推理模式/模型/预算）；
- schema / 协议 / 指标语义变更；
- 删除或"清理"任何历史 run 数据、归档代码、失败记录；
- 冻结清单（§5）中任何项的变动；
- 新增第四个基线或改变双基线制度。

实现细节（库选择、函数拆分、测试写法等）可自行决定，但需在交付说明中注明关键取舍。

## 10. 术语

- **A** = Agentic Policy/Reasoner（LLM 策略）；**B** = 求解过程 World Model；**E** = 真实求解/评价环境；
- **臂（arm）** = 控制搜索策略的 harness 变体；当前四臂：DirectAnswer / BestOfN / GreedyRefinement / iterative-v0.2；
- **Soak Test** = 64 步单臂单题长程稳定性测试（账本一致性/上下文膨胀/资源泄漏/谱系关联/回放一致），
  不产出任何性能或论文对齐结论；
- **TransitionRecord** = 一次 状态→动作→结果 的完整记录，B0 训练的基本单元。
