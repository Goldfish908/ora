## Common Pitfalls to Avoid

1. **Tuple unpacking errors**: When iterating over dictionaries with multi-element tuple keys, always verify the number of elements matches your unpacking pattern. For example, if keys are `(p, dc, pd, m, mode)` (5 elements), do NOT unpack as `(p, dc, pd, mode)` (4 elements).

2. **setObjective signature**: The second positional parameter is `sense`, not a name. If you want to name the objective, there is no name parameter in this API version. Just use `model.setObjective(expr, sense='maximize')`.

3. **Integer vs continuous variables**: Production quantities that must be integer parts/packs use `vtype='I'`. Setup/activation decisions use `vtype='B'`. Continuous quantities (tons, kg) use `vtype='C'` (default).

4. **Rounding solution values**: After solving, round integer variables to nearest integer with `int(round(model.getVal(var)))`. For continuous variables, use `f'{val:.8f}'` format.

5. **Solution file must exist**: The evaluator checks for the solution file. If the solver fails or times out, still attempt to write a best-effort solution file.

6. **Validation before writing**: After extracting the solution, validate all constraints are satisfied within tolerance before writing the file. Print validation results.

7. **Eligibility filtering**: Only create variables for feasible combinations (e.g., only eligible printer-material pairs, only approved lot-order pairs). This dramatically reduces model size.

8. **Binary linking constraints**: For setup/activation variables that gate production, use `x <= bigM * y` where bigM is a tight upper bound on x (e.g., the maximum possible production, not an arbitrary large number).

9. **Weighted average constraints**: When a constraint requires a weighted average to meet a threshold (e.g., average SoH >= minimum), linearize by moving the threshold to the left: `sum(weight_i * value_i * x_i) >= threshold * sum(weight_i * x_i)`.
